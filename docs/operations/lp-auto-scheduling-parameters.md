# LP 自动执行调度参数

状态：#322 任务分支实现。需运行包含该实现的 Prediction 服务；本文不表示已合并或部署。

| CLI 参数 | 字段 | 默认值 | 用途 |
| --- | --- | --- | --- |
| --round-interval-seconds | round_interval_seconds | 60秒 | 本轮完成后，到下一轮开始前的等待 |
| --api-retry-interval-seconds | api_retry_interval_seconds | 60秒 | 必需的规划事实或订单结果读取失败结束后，到再次读取前的等待 |
| --order-check-interval-seconds | order_check_interval_seconds | 10秒 | 订单结果或锁、读取资源尚待恢复时，到再次检查前的等待 |

三项相互独立，单位为秒。取值为正整数：0、负数、小数和非数值均拒绝，失败不改写已有配置。它们不设置单次网络请求超时，也不在每个正常动作之间插入等待。

## 配置示例

设置全部三项：
```sh
open-trader prediction-arb lp-auto config \
  --round-interval-seconds 60 \
  --api-retry-interval-seconds 60 \
  --order-check-interval-seconds 10
```

只修改订单确认间隔，保留另外两项：
```sh
open-trader prediction-arb lp-auto config --order-check-interval-seconds 15
open-trader prediction-arb lp-auto status
```

命令沿用既有本地服务地址、鉴权和写入确认规则。CLI 读取配置版本后仅发送一次写入，校验服务返回的持久状态回执（整数值、版本及未改配置），不承诺写入后增加一次 HTTP GET。服务未确认新值时报告 `UNKNOWN`（退出码 2）；通过同一服务地址的 status 核对实际值，不自动重复写入。

## 生效与保存

允许在运行中单独修改这些调度参数，新值从下一次新开始的等待生效。已经开始的倒计时不重置，本轮目标和动作计划不改变。例如订单确认等待已经按10秒开始，期间改成15秒，本次仍按原10秒到期，下次订单确认等待才使用15秒。

三项持久保存，重启保留。旧配置缺少字段时分别使用60、60、10秒；配置请求省略某项则保留已有值。预算、目标 BUY 数量和买入档位继续遵循原来的交易配置限制。

## 选择哪一个间隔

- 本轮所有动作已有成功或明确拒绝等结果：使用轮次间隔。有空位也等待，不提前选新目标。
- 新计划尚未批准，必需账户事实读取失败或不完整：使用 API 失败重试间隔，恢复后重新取得事实并规划。
- 已批准计划的财务事实过期或财务交易代次变化：不重新验资，不开始 API 等待；按原目标、价格和数量执行。财务 UNKNOWN 与来源时间保持真实，下一轮才吸收新财务事实。
- 撤单 ACK 后有效结果仍显示原 BUY LIVE：保持占资/名额，使用订单确认间隔；较新的有效结果可支持精确 ID 重试，保留各次审计。同一事实不因重复唤醒反复发送。
- 场所明确拒绝撤单，且有效结果确认原单仍 LIVE：本轮结束该动作，保留旧单和保护，不由后台或重启暗中重试；下一轮可再评估。
- 核对订单时发生 API 读取失败：改用 API 失败重试间隔；恢复后继续原订单步骤。
- 有效结果确认精确订单终态：更新真实 BUY 名额及成交库存，继续具备安全依据的原动作，不重新审核规划预算或改量。
- 执行锁、共享读取容量或同市场读取占用：使用订单检查间隔，保留未完成动作，资源恢复后继续原计划。

所有间隔保持固定，不随失败次数递增。结果查询不依赖余额接口，也不发布为完整财务账户快照。UNKNOWN 或 accepted 无 ID 不盲目重发。保护、身份、实际结果时序、当前行情、停止和防重校验继续适用；手动入场与独立增仓仍执行原资金验证。规划预算保证的范围见 [ADR 0003](../contexts/prediction-arbitrage/docs/adr/0003-lp-plan-time-account-validation.md)。

运行中修改仅调度字段时，配置版本仍递增以防并发覆盖，交易配置版本保持不变。预算、档位或目标数量的修改仍要求暂停及完成已有 BUY。非法混合请求在同一写入前完整校验，不部分保存。

本轮固定目标、报价、各动作结果、事实身份和等待原因由自动池持久保存，重启后继续原计划；已有等待保留原到期时间。网络请求超时、资金事实时效及其他保护子系统不使用这三项间隔改写。
