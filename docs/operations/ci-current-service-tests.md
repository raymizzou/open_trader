# Current-service test coverage

`InProcessService` executes the same `child()` assembly as `ServiceChild`: the
current PredictionRuntime/service, offline SDK, real SQLite and native threads.
It replaces the interpreter/signal boundary and restores module, environment,
working-directory, bytecode, tracing and HTTP proxy state after native cleanup.
An assertion-failure case also checks restoration and owner release.

| Family | Current-path coverage | Real process coverage retained |
| --- | --- | --- |
| Dead owner | Copies of real killed-owner databases, current-account exposure, unchanged historical actions and no replay | Signing, before-POST-marker and awaiting-receipt death/lock-release proofs; live-owner negatives |
| Takeover | Known account, incomplete orders/positions, foreign identity, restart and manual idempotency | Each mode has a real-child parity smoke |
| Observed pools | Populated trial/income order membership and exact current financial state | Real-child parity with independent membership expectations |
| Runtime stale/UNKNOWN | Actual current Runtime with stale bookkeeping or incomplete account facts | One real-child parity smoke per mode |
| Background work | Candidate queue, trial maintenance, four preparation outcomes and five blocked optional sources | One real-child comparison per scenario |
| Restart observations | N-leg pause, preserved manual orders and stale daily-report history | One real-child comparison per scenario, including original restart assertions |
| Process/installation boundaries | Original tests and assertions | Actual death, competing-process locks, installed identity, HTTP/native drain and startup cleanup stay real |

`tests/test_lp_service_harness.py` contains 23 parity scenarios. It compares
POST/CANCEL arguments and current financial/account/pool outputs. Only fresh
source/observation IDs are renamed to compare their equality relationships;
account, order, token, monetary and request terms remain exact. Original
financial, UNKNOWN, no-replay, identity, idempotency and cleanup assertions stay
in their shared checks. Temporary actual-source mutations were checked against
the migrated zero-POST, current-reservation and single-manual-POST assertions.

The earlier 34/131/81/50 estimates are not current collection counts. Changes add
real snapshot/parity proofs and preserve original parameter cases. Exact batch
consumer identities, assertion inventories and execution logs are task evidence;
classification alone is not execution or success.

The source template is prepared once per interpreter and made read-only.
Runtime/config/database paths stay private. Identity/tamper scenarios receive a
writable independent source copy. Phase records separate template copy, fixture
preparation and Git from per-child copy, start-to-ready, scenario and exit.
Bytecode stays outside verified release source, as in `BACKEND_PYTEST`:

```sh
PYTHONPATH=src PYTHONDONTWRITEBYTECODE= PYTHONPYCACHEPREFIX=/absolute/task-evidence/bytecode \
  /absolute/selected/python -m pytest -q tests/path.py::test_name
```

Nested sample pytest runs pin their root so durable evidence directories do not
change canonical nodeids. Release preflight still rejects dirty and ignored
source files, including generated bytecode. No fake virtual environment is added
without evidence that traversal causes the rollback cost. Local phase samples
do not establish hosted CI savings; three consecutive exact-main runs and any
deployment/live acceptance remain separate Main-owned evidence.
