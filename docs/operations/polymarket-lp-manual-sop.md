# Polymarket 流动性奖励人工试验 SOP

版本：v3.3
日期：2026-10-08
状态：只读轻筛与小时补全检查已实现；成功历史摘要缓存 24 小时；部分覆盖和逐标的恢复可见；首次真实启动仍需独立授权和当次新鲜预检查

本文区分两个独立流程。Dashboard 的新“推荐标的”是只读外部入场指引：操作者可查看事实并打开普通 Polymarket 市场链接，但页面不会创建预览、启动系统会话或提交订单。原有系统管理会话仍使用固定单市场、单结果和 `$5` 止损触发线；只有操作者按本文重新核对事实并明确确认，才可通过既有 session API 启动。本文不授权入金、真实下单、候选激活、自动做市、部署或连续无人值守运行。

原系统管理会话一次只处理一个市场和一个 outcome。每次会话只有一次开仓和一张固定参数的初始买单；同一初始单的分次成交归入同一开仓。完成、拒绝或需要人工处理后，不重新挂新的 LP 买单。只读推荐本身不创建这种会话。

## 1. 边界与风险

- 每次开仓独立使用 `$5` 止损触发线。它是触发器，不是最终损失上限；跳价、滑点、撤单竞态、流动性消失和接口延迟都可能使最终结果超过触发线。
- 不使用跨开仓累计损失预算，不把资金准备额当作风险上限，也不以奖励抵扣交易损失、费用或剩余库存风险。实际数量和价格必须来自当次预检查、账户可用余额和市场最小订单约束。
- 只有目标持仓已核实为零、会话订单全部为终态且买卖数量对齐时，才把会话标记为完成。交易费用或其他相关交易成本未知时，交易盈亏保持 `UNKNOWN`；仅奖励事实未知时，保留已知交易盈亏，试验净额保持 `UNKNOWN`，不把未知费用当作零。
- 任何关键事实缺失或会话外目标订单／库存无法解释，都停止新写入并保留需要处理状态。不要处理其他会话的订单或持仓。
- 不做双边持续做市、入场追价、循环补买、重复开仓、跨所对冲、merge、redeem 或自动确认开仓。

## 2. 下单前预检查

以下检查适用于启动原有系统管理会话。Dashboard 的只读外部入场指引不是系统预览，也不会替操作者通过这些检查。

使用官方 Rewards 页面、市场页面和当前服务预检查，重新记录：市场标题、官方 URL、结果身份、规则与结算来源、`end_date`、奖励计划时间、最小合格尺寸、最大合格价差、tick、适用费用、目标结果的 bid/ask 和足够深度，以及直接卖出已确认库存的路径。

检查以下条件：

1. 规则、结算来源、提前结束条件和费用适用范围已读懂；任何未知都不启动。
2. 目标结果的价格、盘口深度、订单最小尺寸和价格粒度满足当次计划。奖励页的最大价差不是盘口 spread，YES/NO 显示价差也不是所选结果的 bid/ask。
3. 预检查可展示按奖励最小尺寸过滤后的本地中点估计；它只是报价参考。实际 LP 资格以官方订单 scoring 查询为准，不把中点或奖励估算当成资格、奖励到账或盈利证明。
4. 账户、余额、目标 token 持仓和未完成订单均能按当前身份核对；会话外目标变动保持未知并停止。
5. 预检查给出固定的 outcome、价格、数量、费用事实、复盘绝对时间和订单期限。复盘时间必须是当次明确指定的时间（例如 2026-09-15 08:00 Asia/Shanghai），重启不能自动顺延；过期或无法计算安全期限时拒绝启动。

不设置固定的短时观察期限或 60 分钟上限。下单前可以持续观察市场，但只有最新事实通过上述检查才可提交；价格跳变、深度消失、规则或奖励变化时结束本次评估，不为保留资格追价。

### 2.1 Dashboard LP 首页

- **我的订单与持仓**每 5 秒读取并提供立即刷新，显示账户当前订单和持仓。没有本地 LP 会话的手工订单明确标记为只读；官方 scoring 状态及查询时间、同一 condition 的平台奖励观察仅作为市场事实展示。市场累计不能分摊到某张订单，也不能当作已到账收入。币种、美元换算或读取失败时保留原始资产单位并显示 `UNKNOWN`/过期状态，不显示为零。官方账户级 Rewards 百分比只采用已认证的 `GET /rewards/user/percentages`（由现有 `lp_reward_percentages` 适配器读取），按 condition 显示并核对当前 maker；份额预警全量开启：所有有未完成挂单的标的自动进入监控，无需逐市场选择，无挂单的标的自动停止监控并清除未完成的连续计时。目标区间为 `5%–8%`：低于 5% 显示“还有空间”，`5%` 到 `8%`（含边界）显示“已达目标”，严格大于 `8%` 才显示黄色超额告警。后台每 10 秒刷新一次；样本来源时间不晚于当前时间且年龄 `< 30` 秒，连续超过 8% 满 60 秒后才允许 Xiaoai 语音投递。北京时间 `23:00–08:00` 语音静音；同一 breach episode 只允许一次成功投递，只有确认恢复到 `<= 8%` 后才重新计数。读取失败、缺失、错误 maker、未来时间或过期的份额保持上一份数字并标为 `UNKNOWN`，UNKNOWN 不能当作恢复或零。无订单自动停止该标的的监控、清除未完成的连续计时，新订单出现后自动恢复；服务重启同样会按“有未完成挂单”的监控集合重新推导并清除未完成的连续计时，但不会把仍新鲜的份额数据显示成 UNKNOWN。失败/静音的语音仅在仍有新鲜账户样本、监控有效且连续超额资格未被清除时保持待重试；恢复、无订单、UNKNOWN 或重启后不重播旧事件。该显示和预警不创建、撤销、调整或自动放大订单，不做交易，也不新增飞书发送路径。
- **推荐标的（只读外部入场指引）**生产运行时启动后由独立后台线程每小时检查需要补全的 24 小时价格历史；成功摘要缓存 24 小时，仅缺失或到期方向才下载。候选轻筛线程每 60 秒读取已保存摘要、奖励目录和市场资料。页面和候选刷新不下载历史。轻筛通过后最多保留 50 个市场，按日奖池降序、同额按市场 ID 升序；随后只为入选市场读取新鲜盘口、账户和完整订单/持仓事实。没有摘要、奖励状态、目录或资料的方向保留 `UNKNOWN`；私有账户或选中市场盘口读取失败只令最终风控未知，不清除本轮已取得的目录和轻筛计数。旧的全目录 5 秒 BBO 采样器已停止。页面列出通过轻筛的市场，YES/NO 是同一市场的替代参考方向，不组成双边订单。目录或元数据部分失败时明确报告覆盖不足；部分结果不代表全市场。瞬时失败按 5/10/20/30 分钟退避持续恢复，受影响依赖每 60 秒探测（服从服务器 `Retry-After` 指定的更长等待）；持续故障五分钟后发送合并告警，健康市场继续轻筛。到期的元数据重试在下一空闲历史批次边界实际派发，不能只在队列中领取后丢弃。
- 市场元数据每轮最多覆盖 1,500 个 condition ID；底层 HTTP 每批最多 100 个 ID，按全目录连续分批读取。数字事件按每批最多 100 个 ID 批量查询；公开请求并发不超过 8。成功元数据正缓存 12 小时。事件事实只接受与市场引用 ID 精确匹配的响应，缺失或不匹配仍按未知处理。
- 历史摘要使用官方批量历史接口的 24 小时窗口和 1 分钟粒度；每批最多 20 个 token ID/方向，最多 4 批并发，按批保存后释放原始样本。轻筛最多保留 50 个市场；这是市场上限，不是历史请求的批次大小。窗口首尾允许 1 分钟边界误差，内部缺口不插值也不单独否决；无效时间或价格（历史价格 `0` 有效）令该 token 保持 `UNKNOWN`。摘要有效期为 24 小时，达到边界即过期；服务重启读取已保存摘要，不把 BBO 盘口样本伪造成价格历史。24 小时极差不超过 `$0.01` 才通过轻筛，价格变化仅作带来源的参考。
- 指引使用当前买一，并把订单最小份数与奖励最小份数取较大值、向上按 0.01 份取整。可用资金还扣除当前 active N-leg 中 `(polymarket,catalog-v2,usd-micro)` 预留的 `remaining_units`；不重复扣已成交 holding、原始总成本、其他币种或 venue 总额，也不计算已确认结束的历史执行批次的预留。当前批次的订单状态或资金预留信息不完整时返回 UNKNOWN，不给出可参与指导。风控从压力退出深度中扣除账户自己的剩余订单，并移除建议买价对应的整个买一价位；只有外部 bid 能覆盖全部建议份额、费用和退出压力损失不超过该市场投入资金的 10% 时才通过。输入或退出覆盖不完整时显示 UNKNOWN/不可参与。这个 10% 是入选后的最终风控风险估计，不是前置轻筛估值、止损、损失上限或成交保证；它不替代第 1 节的 `$5` 系统会话触发线。
- 事件检查只使用市场关联事件的明确开始/结束事实或结构化比赛开始时间；普通市场截止日期和标题文本不会推断关键事件。已知事件开始前 30 分钟停止提供指引；事件结束后的 1 小时冷却和筛选通过条件仍由现有风控执行，历史摘要按独立的 24 小时窗口判断，并保留任何更早的显式到期时间。结束状态已确认但没有可信结束时间时，以首次本地确认时间作为起点并保留跨刷新和重启结果。新闻、财报与宏观日历尚未接入，页面必须显示关键事件覆盖不完整；这不等于证明没有其他事件风险。
- 奖励及市场资料读取年龄须不超过 60 秒，盘口与账户读取年龄须不超过 10 秒；单次指引最多有效 60 秒，历史摘要达到 24 小时即过期，或按更早的显式到期时间失效，并在已知事件或奖励的更早截止时间失效。过期指引保留原始价量和检查时间供参考；过期方向不再显示为当前可参与；只要另一方向仍可参与，市场仍显示为当前可参与；全部方向过期后，市场才不再显示为当前可参与。
- 页面“立即刷新”只向既有后台线程排队请求，快速返回 `202 queued` 后读取已保存结果；它不在请求线程同步扫描，也不预览、不确认、不激活候选，不下单或撤单。点击普通 Polymarket 链接仅打开市场页面。方向选择只切换显示的指导价量。
- **系统管理会话**仍是独立路径：第 3 节的既有 preview/start/status/stop API 保留单次开仓、post-only GTD、幂等、绝对复盘时间和 `$5` 止损保护。新只读推荐不会创建或占用系统会话；系统会话的 `$5` 规则也不会被新的 10% 指引门槛替代。

### 2.2 自动补位的启用与暂停

自动补位默认未启用。先保存策略总资金、目标 BUY 数和可选的 `buy_price_level`（1 或 2），再明确点击“启用自动补位”；保存配置本身不下单。旧配置缺少该字段时使用 1，省略字段的后续旧请求保留已选值。档位 2 使用第二高的不同正深度买价，同价行合并、零深度行忽略；缺少第二档或 POST 前档位变化时拒绝该 BUY，不回退买一。首次尚未配置的自动池可在暂停且账户事实已知时，保留纳管手动 BUY 并设置预算/目标；后续改配置仍须满足原有暂停和清空 BUY 规则。启用/恢复立即核对，此后每轮结束约一分钟再检查，不重叠、跨日持续。单笔 GTD 和保护复核时间仍生效。

每轮也检查满额后的收益排名：把该 LP 专用账户纳管的真实 BUY（含手动单）与当前合格候选合并，按预计每小时资金收益率取前 N 个不同市场，N 为目标 BUY 数。新旧单使用相同盘口奖励估算模型和新鲜事实；在场单按实际挂单价量计算，并从竞争量中扣除自身订单。同收益率优先保留已有单，不设相对提升门槛、最短挂单时间或冷却时间。

榜外纳管 BUY 先登记轮换意图再撤单；撤单回执保留为审计，新的完整有效账户快照确认没有该 BUY 后按实际持仓和挂单更新占位，再按最新排名补位。撤单失败或超时后，仅在更新且完整的回执确认原订单仍为 LIVE 时重试原订单；收到撤单确认后等待新的完整有效账户快照。撤单途中成交则中止该轮替换，已成交部分保留库存成本并沿用原退出保护；SELL 不参与 BUY 名额轮换，同 token 的库存仍统一按原退出规则管理。预算或扣除其他挂单占资后的余额无法覆盖目标组合、事实未知、暂停、保护已触发或新单不满足既有 GTD 最短有效期时不轮换，保留具体原因。排名和订单在这些等待期间可能不同，不宣称已追齐。

自动池预算是固定的当前占用上限，本次按 100 USDC 执行；历史盈亏仅作报表，不改变新增额度。可新增额度为预算减当前 API 持仓成本和有效 BUY 未成交占款，且仍需通过当次余额、allowance、盘口与交易授权检查。独立 UNKNOWN SELL 不计入 BUY 名额或未确认回款，不单独阻止其他标的在有效资金下补位；其 UNKNOWN 审计保留。API 的初始成本金额优先，缺失时使用其数量乘平均成本价；不使用当前市值代替普通持仓成本。仅当 API 同时明确可兑付、价格和价值为零时，已结算的零兑付残留不再占用资本。已确认终态订单复用持久化记录，保留完整订单身份及审计，不每轮重查。

目标 BUY 数按未完成的交易所订单 ID 计数：同一 token 两张 BUY 占两个名额；BUY 结束后库存只占预算，不占 BUY 名额。超额订单仍全部登记并计入账户资金和名额，停止新增后沿用收益率轮换收敛，不强卖库存。发送后超时先保留临时占位，在其结束后开始的一轮完整、新鲜且版本有效的账户读取完成后，原临时预留整体由真实订单、成交和库存替换，无需逐请求匹配；原请求仍保留 UNKNOWN 审计。历史无发送时间的记录须有账户归属及非在途证据，否则继续保留。读失败、缺页、旧缓存及版本失效不会释放。当前 API 的持仓数量和成本、有效 BUY 未成交占款决定实际占用；历史成交或费用差异仅影响报表，不产生额外预留。晚到订单可能造成暂时超额，后续同步继续补录并收敛。

完整候选池数量与前 10 个候选预览继续单独展示，轮换目标另记为前 N 个市场。新鲜完整事实证实旧单数量低于奖励最低数量、或价格移出计奖价差时，旧单按零预计收益排名；缺失或过期事实仍记未知，不当作零收益。

### 2.2 LP Auto CLI

终端通过运行中的 Prediction 服务读取和操作同一份 Auto 状态，与 Dashboard 一致。
先保存配置，再明确开启；保存配置本身不会启用 Auto 或提交订单。

```sh
# 保存配置；保持暂停
open-trader prediction-arb lp-auto config --budget 100 --target-buys 5 --bid-level 2

# 使用已保存的预算、BUY 目标和档位开启 Auto
open-trader prediction-arb lp-auto on

# 暂停新增自动 BUY，保留现有订单与退出保护
open-trader prediction-arb lp-auto off

# 只读核对实际状态
open-trader prediction-arb lp-auto status
open-trader prediction-arb lp-auto status --json

# 原 pause 命令保留，与 off 行为相同
open-trader prediction-arb lp-auto pause --url http://127.0.0.1:8769 --timeout 15
```

`config` 的 `--budget` 和 `--target-buys` 必填。预算接受有限、非负 Decimal，
BUY 目标接受非负整数；0 沿用服务原有语义，不表示撤单。`--bid-level` 可省略，
只接受 1 或 2；省略时保留已有档位，服务对旧存储缺字段使用 1。
2 档使用第二个不同且正深度的买价，缺档不回退买一。

预算是当前持仓成本与有效 BUY 未成交占款的总占用额度，不是每单金额，
也不随历史盈亏增加。BUY 目标包含服务纳管的手动 BUY；真正未决和撤单中的 BUY
继续占位，SELL 和单纯持仓不占 BUY 名额。目标不保证立即有 N 张 LIVE 订单，
也不是外部手动单或迟到回执的绝对硬上限。资金、候选不足或事实未知时，保留服务阻塞原因。

配置写入先读取 `config_version`，再发送 `expected_config_version`。
版本冲突、运行中或 BUY 尚未清理而被拒绝时，CLI 显示服务原因，不自动暂停、撤单、开启或重试写入。
失败输出中的 `state` 若存在，是已读取的服务快照；配置拒绝时可能是写入前的快照，
不能把它当作失败后重新核对的当前状态。

`on` 不修改配置。只有严格布尔 `desired_running=true` 的确认回执才返回 `result: ON`。
同时显示实际 `runtime_state`；`ON` 配合 `BLOCKED` 表示已保存开启意愿但仍受阻，不表示已挂满目标。
`off`/`pause` 只有 `desired_running=false` 且 `pause_confirmed=true` 的一致回执才返回
`result: PAUSED`。暂停持久化人工意愿，保留已有 BUY/SELL；退出保护和已发送意图核对继续。
它不会调用 LP 会话 `stop`、全撤订单、清仓、停止进程或改变 N_LEG 状态。

所有命令均支持 `--url`、有限正数 `--timeout` 和 `--json`。
默认 URL 为 `http://127.0.0.1:8769`，默认超时为 15 秒；一次命令共用一个请求时间预算。
仅接受 HTTP loopback IP 的服务根 URL，拒绝凭据、额外路径和重定向，忽略外部代理。
写请求通过现有 `/venues` 获取 session cookie 和 CSRF，认证只保留在内存，不输出认证值。
CLI 不直接打开交易数据库、读取交易所密钥或调用交易所。

确认成功返回 0；`status` 成功读取暂停或受阻状态同样返回 0。
人类输出分别列出 Auto 意愿、运行状态、配置、活动/未决/撤单中/总占位数、资金、阻塞原因与最近检查。
未知字段显示 `UNKNOWN`，不填零；`--json` 输出单个 JSON 文档，未知值保留 null 或缺失字段。
不可达、超时、回执缺失或矛盾时返回 `UNKNOWN` 和退出码 2。
写入可能已被服务接受；CLI 不自动重发 POST，也不宣称已回滚。
随后使用相同 `--url` 运行只读 `status` 核对，再决定下一步。

修改资金/目标前须人工暂停，并等自动 BUY、撤单中 BUY 和未决提交全部终结；页面和 API 使用同一屏障。资金或目标设为 0 不暗中撤单。普通重启保留人工意愿，先核对再恢复新增；无法核清的提交保持受阻，用户期间的人工暂停优先。

## 3. 初始报价与计分

1. 通过服务 API 消费有效预检查和幂等键，固定提交一个 post-only、GTD 限价 BUY。先持久化开仓意图，再提交；重复请求必须返回同一会话。
2. 只提交一张初始 BUY，价格和数量不自动改变。post-only 被拒绝时记录拒绝并结束入场，不改为 taker、不追价、不补发第二张 BUY。
3. GTD 期限按复盘绝对时间和必要缓冲计算，不能把本地复盘时间直接当作交易所 `expiration`。提交后在官方 Open Orders 中核对订单身份、价格、数量和状态。
4. 记录官方 scoring 查询的 `true`、`false`、错误和过期状态及查询时间。`true` 只证明该时刻符合计分条件；奖励资格、分配、到账、成交、退出和净收益是独立事实。

计分持续失效时，按服务的连续失效窗口撤销未成交 BUY 余量并记录原因。单次查询失败不停止库存或止损核对；超过新鲜度阈值显示 `UNKNOWN`。不为凑最小尺寸或恢复 scoring 增加仓位。

### 3.1 平台累计奖励观察（只读）

服务每 60 秒读取一次官方平台 earnings，并把本次会话首次开仓对应的 UTC 计奖日固定在会话中。账户合计使用官方 `sponsored=true` 的日合计；市场合计分别读取原生和 sponsored 结果并按目标 condition、maker 和日期核对。刷新是快照替换，不在本地累加；未四舍五入的 Decimal 账户合计达到 `>= $1` 才显示“已达门槛”。账户合计不能代表本市场或本次开仓已赚到 `$1`。

当前只把官方已核实的 pUSD 和 Polygon USDC.e 地址、且 `asset_rate == 1` 的 earnings 按名义 USD 观察。官方资料没有把 `asset_rate` 定义为通用美元汇率，因此非单位或未知资产／汇率保持 `UNKNOWN`，不推导汇率模型。

奖励读取失败或成功记录超过 180 秒未更新时，状态为 `UNKNOWN`，并保留上一份金额、差额和上次成功时间作为旧记录；这不会清零交易状态、库存、止损或已实现交易盈亏。显示的 earnings 是平台累计，到账未核实，不写入 `paid_rewards` 或净额。会话提前完成后仍观察到原定 `review_at`；在复盘边界允许对原 UTC 日期做一次最后读取，之后保留结果并停止新查询，不滚动到下一天。

运行时停止会先向只读奖励读取传递协作停止信号；当前有界 HTTP 请求返回后不再发起后续总计或分页读取。若读取线程仍未收敛，服务先执行既有后台监控的停止调用，再保留它所依赖的 LP、交易、store 和 owner，不从线程下方关闭资源，后续停止操作再完成清理。运行中的新会话沿用现有 60 秒轮询周期，首次观察可能等待最多一个周期；不保证会话创建时立即读取。此 MVP 仍限于单市场、单次开仓和复盘收尾，不启动重叠会话或重复开仓。

## 4. 成交、退出与止损

任何 BUY 成交都结束入场阶段：

1. 撤销同一 BUY 的未成交余量，并等待官方状态确认；撤单等待期间发生的新增成交也归入本次开仓。
2. 读取完整订单、成交和目标持仓，按实际已成交数量核对可用库存。撤单请求或页面 `open` 状态都不是最终成交证明。
3. 有库存且尚未触发止损时，按当前外部最优卖价挂一张 post-only 限价 SELL。自己的卖单不能当作外部深度；改价前先撤旧单、确认成交和剩余量，再只对剩余库存重挂，不能出现覆盖同一库存的两张卖单。
4. 按本次开仓的已确认买入成本、已确认卖出回款、实际费用和剩余库存按当前可执行 bid 全量退出的预计净回款计算损失。达到 `$5` 时锁定主动退出意图，撤剩余被动 SELL，核对撤单期间成交，再按新鲜买盘用已有保护的主动 SELL 分量退出。
5. 主动退出每次都要等待上一次明确终态并重新核对成交和持仓。明确零成交拒绝可以用新盘口重评；超时、未知状态或无法确认的回执只允许读取和对账，不盲目重发。

到达复盘时间或收到 stop：撤销本会话未成交的 BUY/SELL，核对撤单期间成交，然后进入待复盘。时间和 stop 本身不触发主动卖出、不清除库存、不标记完成；仍有持仓时继续保留同一个 `$5` 止损保护。待复盘期间不重新挂被动卖单、不恢复入场阶段、不重新开仓；止损触发后仍可按上面的主动退出流程处理。

无 bid、可卖数量不足、结算未完成或接口不可用时，保留真实剩余库存和原因，显示 `UNKNOWN` 或 `needs_attention`，不把无法交易等同于零仓位。

## 5. 完成和结果记账

会话只有在以下事实都成立时才完成：

- 本会话所有订单均为终态；
- 已确认买入数量与已确认卖出数量相等；
- 当前账户持仓核实为目标 token 零；
- 成交去重和退出回执已对账。

完成状态确认已无目标敞口，与经济结果记账是两个独立结论。交易费用或其他相关成本无法核验时，仍可在上述持仓和订单事实成立后完成会话，但交易盈亏和试验净额必须保留 `UNKNOWN`；仅奖励无法核验时，保留已知交易盈亏，试验净额保持 `UNKNOWN`。

交易盈亏按实际回执计算：

```text
已实现交易盈亏 = 退出成交回款 - 退出实际费用
                 - 入场成交成本 - 入场实际费用
试验已实现净额 = 已付奖励 + 已实现交易盈亏 - 其他实际相关成本
```

费用在实际发生的地方只扣一次。未付或无法核验的奖励写为预估／未知，不减少 `$5` 止损计算，也不把 scoring `true` 当作收入。剩余库存记录当前真实 bid 深度下的可执行清算价值和风险缺口，不使用中点、last trade 或奖励页估值。

每次试验至少记录：

| 时间（北京时间/UTC） | 市场与结果 | 事件/订单 | 计划/成交数量 | 入场成本/费用 | 退出回款/费用 | 已付奖励 | 预估或未知奖励 | 库存与可执行清算价值 | 状态与备注 |
|---|---|---|---:|---:|---:|---:|---:|---|---|
| 待填 | 待填 | 待填 |  |  |  |  |  |  |  |

### 5.1 每日复盘读取

每日报告按报告日期对应的北京时间 08:00 截止，统计前一 08:00 至当前 08:00 的已核实事件。若服务在边界后才生成报告，`generated_at` 是实际观察时间，不代表边界时的盘口快照；缺少当时的退出估值或成交归属时显示 `UNKNOWN`。跨日未平持仓可以继续列示并关联原会话，但不得在后续日期重复计入先前已经报告的已实现盈亏或平台奖励。08:00 后的新成交计入下一报告区间，同时保留原会话关联。

报告按日期保存为不可覆盖快照，由只读接口 `GET /api/prediction-arbitrage/lp/reports/YYYY-MM-DD` 读取；查询报告不会代替订单/持仓核对，也不会触发交易写入。现有每日飞书自动化在软件部署和相应运行授权完成后读取这份服务端报告；本 SOP 不授权修改或启用自动化、发送通知或部署。已观察的市场/账户累计奖励始终是平台累计，支付未独立核实时保持“到账待核实”，不计入已付奖励或已实现净额。

### 每日报告输出模板

日报正文只包含以下三节，按固定顺序输出；标题与区间行固定为
`Polymarket LP 日报｜{report_date}` 与
`{period_start 日期} 08:00 → {period_end 日期} 08:00（北京时间）｜奖励日 UTC {reward_day}`。

1. **套利情况**：第一行累计奖励（总额 + 同一行逐市场分布，按累计降序）；
   第二行已实现盈亏（附成交情况一句话）。
2. **持仓**：昨日开仓一行（逐笔或“无”）；奖励市场持仓汇总一行
   （仅仍有持仓的市场逐个列出）。
3. **自动撤单（08:00 后）**：逐单一行（市场/方向/价格/数量、撤单时间、
   撤时成交）；日内手工撤单不进报告；无记录时写
   “无撤单记录，当前挂单 {n}”。

写作规则：共性只说一次；只有例外单列；“无”显式写一次；数字、时间戳与
交易哈希保留原值，不四舍五入。非 LP 历史仓位与非 LP 成交、奖励到账状态、
08:00 后入账明细、开仓/平仓/止损章节、待核实清单一律不进日报正文。

## 6. 故障处置与恢复

- **网页、网络或 API 卡住**：停止新写入。恢复后先读取 Open Orders、Recent Trades、持仓和余额；不能把断线或已发出的取消请求当作取消成功。
- **LP 准备部分失败**：保留已完成方向和健康市场的轻筛结果，面板显示历史/资料覆盖计数及等待项。可自动恢复的瞬时失败按 5/10/20/30 分钟退避（之后保持 30 分钟）继续重试，并每 60 秒只探测受影响的资料或历史依赖（服从服务器 `Retry-After` 指定的更长等待）；持续故障满 5 分钟后发送一次合并告警，发送失败按独立退避补发，同一故障 episode 不重复告警。只有受影响范围完成新的外部事实读取并验证完整覆盖后，才发送恢复通知；短故障在告警窗口前恢复不发送通知。`partial` 且存在待补项时继续保留已完成结果并显示覆盖计数；只有认证、证书、配置等操作员阻塞项才暂停并使用既有“恢复暂停项”按钮重新排队。恢复后仍按新的外部事实重新核对，不能把部分覆盖当作全目录完成。
- **仅恢复全局准备**：明确的 SQLite `BUSY/LOCKED` 自动进入上述重试；未知 `OperationalError`、数据库配置或完整性错误仍暂停。
  对只有旧错误类名的全局暂停，先确认当前部署版本和 dashboard preparation 的 `state=paused`、`paused=true` 与 `generation`，
  再经明确授权调用现有受鉴权/CSRF 保护的 `POST /api/prediction-arbitrage/lp/candidates/refresh`：
  `{"manual_recovery":true,"recovery_scope":"global","expected_generation":<当前正整数代次>}`。
  该事务只推进全局准备代次，保留其他市场暂停和旧错误审计；错误代次、非暂停状态或重复旧请求会被拒绝，事务失败不唤醒 worker。
  返回 `ready` 表示重新排队资格，不表示已 prepared；须等待正常 worker 重新读取依赖，核对新的准备成功时间、扫描与资格事实。
  原按钮及 `{"manual_recovery":true}` 保持全量恢复暂停市场的合同，不应用于只恢复全局的场景。
- **订单状态未知**：保留订单和库存为未知，不提交替代 BUY/SELL，不重复退出，直到官方状态或人工支持给出可核对事实。导入持仓的旧 BUY 若缺少原始数量或终态证明，即使成交数量和当前库存已核实，也保留会话指定的当前被动 SELL 身份，不因 `group_fill_collect` 撤单/重挂；其他自有历史 SELL 仍执行原清理及重试校验。独立未知的前置状态仍阻止新的退出。
- **评分失效、规则变化或退出深度消失**：记录原因，撤入场余量，按实际库存进入退出或待复盘；不追价换取资格。
- **进程重启**：用同一会话和官方订单／成交／持仓事实恢复，不重建初始 BUY 或重复 SELL。未结束 LP 会话继续占用执行槽；`needs_attention` 和待复盘状态仍可见，只有 `complete` 或 `entry_rejected` 释放开仓槽位。
- **无法归属的外部订单或目标库存**：停止本会话交易，保留 `UNKNOWN`，由操作者完成身份和账户核对。

服务路由为：`POST /api/prediction-arbitrage/lp/preview`、`POST /api/prediction-arbitrage/lp/sessions`、`GET /api/prediction-arbitrage/lp/sessions/current` 和 `POST /api/prediction-arbitrage/lp/sessions/{id}/stop`。只读或 shadow 模式可展示持久化风险，但不允许 LP 写入；查询不到会话与查询失败要分别记录。

### 6.1 历史 UNKNOWN 请求的显式本地豁免

自动账户同步仍按完整性、时效、账户和版本证据覆盖预留。若旧临时请求缺少归属或发送时间，
操作者可使用 [历史预留 API](polymarket-lp-reservation-api.md) 列出原因，并显式确认释放一笔
intent ID 或本次全部可释放记录。该手动决定只取消本地临时占位，不猜测原订单身份，
不改原 UNKNOWN 审计，也不取消真实订单。实际发送中的请求和已知订单仍排除。
旧空请求容器可因本地豁免退役，这与账户零库存证明不同。
启用池由原调度按真实剩余预算补位；暂停池不被启用。迟到订单仍补录和重算，可能短暂超额。
实现、测试或本 SOP 均不授权执行生产释放；请求/响应及认证方式见上述 API 文档。
