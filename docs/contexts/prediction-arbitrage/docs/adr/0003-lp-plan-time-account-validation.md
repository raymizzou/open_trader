# LP 规划时校验账户，执行时确认动作结果

2026-10-10，#322 修订确定：新计划使用有效完整的账户事实检查预算、余额、allowance、库存、BUY 名额及保护约束，并保存固定目标、价格、数量、精确撤单 ID 和动作身份。已经批准的计划不再因财务事实过期或交易代次变化重新验资。下一轮读取新事实，再调整目标。

2026-10-11，#329 补充：每轮在排名前取得并校验一次真实规划观测，包括账户身份、完整分页的当前挂单、余额、allowance、持仓数量与成本，以及必要的本地订单和在途预留。初始读取失败、身份不符、代次不一致或当前敞口无法确定时不制定买入计划；缺失页面不等于空账户。排名、预算和固定动作使用该观测，保留原来源及 as-of；后台刷新、后续财务代次、时间流逝或后台财务发布故障不触发第二次整份账户审批。固定计划仍与当前运行授权、owner、账户及配置身份、防重控制原子提交；当前行情、精确订单和保护规则独立生效。

历史报告缺失或冲突不否定已证明的当前敞口。仅历史成交传输失败时，内部规划读取仍可独立取得完整当前余额、挂单及持仓，历史状态与收益报告保持 UNKNOWN。此来源不进入完整账户缓存或财务发布，也不凭缺失历史解除原未知请求的预留或推定归属。默认手动入场、SELL、保护、结果证明和完整财务发布保留原完整性、时效及代次规则；恢复历史后需真实新读取才能恢复完整发布。

此决定取代 [ADR 0002](0002-lp-fixed-round-plans.md) 中执行期资金重复准入和明确撤单拒绝后的同轮重试。执行仍检查运行授权、停止、owner、熔断、账户与交易配置身份、动作所有权、防重、当前行情和保护。手动入场、独立增仓、SELL、保护及完整财务发布保留各自原有规则。用户请求不能取得内部计划授权。

局部市场不可用、计划报价变化、场所明确拒绝或实际名额不足，只结束当前业务动作，继续原计划中可执行的其他动作。不临时替补、追价、改量或另撤订单。旧单未撤时保留其真实身份、占用和普通保护。明确撤单拒绝且新鲜结果确认仍 LIVE 时，本轮不再重试；下一轮可重新比较。ACK 后仍 LIVE 或结果未知则保留未完成动作，按新结果恢复精确查询及必要的撤单尝试。

结果确认独立于余额接口。精确订单、完整挂单及必要的成交和持仓证据用于证明原动作和名额，不发布为完整财务快照。UNKNOWN、无 ID 的 accepted 和迟到回执保持原请求与审计；查不到订单不证明拒绝，同 token 订单不证明请求归属。恢复使用原请求的确切会话、审计和订单证据，不重放已发送动作，也不伪造缺失的旧财务来源。财务 UNKNOWN 及原 as-of 如实保留，不单独阻断有效计划的执行。

预算保证限于规划时。例：预算 39.00，五笔固定 BUY 各 20 股、价格 0.39；旧单撤单终态期间成交 8 股，库存成本为 3.12。在名额释放、场所资金及其他保护允许时，原五笔 BUY 仍可尝试，暂时形成 42.12 敞口。下一轮以真实 3.12 库存重新分配预算。仍 LIVE 的部分成交保留原保护门禁；不强卖库存，也不制造全额现金释放。

全部动作处理完且没有未核清计划交易结果后，从完成时刻起等待完整轮次间隔。规划事实或必要结果读取失败，从失败结束起等待 API 间隔；锁、读取容量、同市场读取或订单结果等待使用订单检查间隔。默认仍为 60/60/10 秒，固定且持久；运行中修改仅影响下一次等待，不重置已有 deadline。资源恢复继续原动作，不重新排名或财务审批。

实现沿用自动池文档、现有会话和动作审计，不增加通用流程平台、数据库表或用户绕过参数。分支实现、聚焦验证、独立评审、CI、合并与部署分别确认；本决定不授权生产操作。
