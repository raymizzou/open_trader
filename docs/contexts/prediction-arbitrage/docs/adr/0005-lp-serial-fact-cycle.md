# LP Facts Reader 与连续事实轮次

2026-10-14，#344：自动 LP 依次读取当前事实、发布有效观察及失败状态、制定固定 BUY 计划、同步尝试每个已登记动作，然后进入下一轮。暂停或空计划也发布当前已纳管 BUY 的预计收益。

本决定仅替代 [ADR 0004](0004-lp-buy-plans-and-independent-cancels.md) 中正常轮次完成后等待固定间隔的规定。资金与身份校验、固定请求、防重、独立精确 ID 撤单、600 秒未知收益保护、库存与 SELL 保护继续适用。

## 读取与预算

LP Facts Reader 是逻辑读取入口，负责当前账户及相关市场事实、源时间、完整性和脱敏错误；收益计算与持久发布在下游完成。正常自动规划读取余额／allowance、完整当前挂单和当前持仓，不读取全量成交历史。2026-10-20 预算修订：固定 BUY 预算只扣账户全部活跃 BUY 的未成交占款，包括自动、LP 手动及来源未知的 BUY；已成交持仓成本和 SELL 不扣此上限。余额/allowance 仍独立限制新增，未知持仓成本或不完整订单不能推定为零。此前“预算扣实际持仓成本”的决定仅在预算口径上被本次修订取代，其余财务与调度义务保留。

未读取的历史保持 `not_read`／不完整，不把未知费用或历史盈亏改成零，也不将规划来源冒充完整账户财务发布。默认手动及完整账户读取保持原行为。UNKNOWN 请求、成交归属和报告确实需要的历史证据仍按既有职责按需读取。

## 发布与发送

账户观察保存各分项结果；失败不阻止独立健康观察发布。资金准入需要一致、有效的余额、挂单、持仓成本及预留依据。复用旧事实时保留原时间；过期、身份冲突或交易代次改变的事实不授权发送。

当前收益按账户和精确订单 ID 窄写入现有会话 payload。计算和网络在写事务外完成；提交时复核订单身份和剩余价量，保留更新后的控制、请求和历史。某笔写入失败不伪报其发布成功，也不回滚其他独立提交的收益。

原生事务仍原子登记请求和占用，未登记不得发送。无关执行文件锁不阻止已授权自动 BUY 的结果应用。明确同步回执直接保存原请求，不普遍追加订单查询；UNKNOWN 或投影失败保留原审计，恢复投影不重发。

## 调度与资源

2026-10-21：以下网络串行及共享读取槽位由 [ADR 0006](0006-lp-owned-async-reads.md)
的逐单异步读取取代；金融/计划/发送业务 owner、预算及终态规则继续适用。

健康轮次立即串行推进，现有非重入锁防止重叠。局部失败只按该依赖的期限重试；共享鉴权及接口级 Retry-After 仍保持真实作用范围。无可进行的观察时等待最近依赖期限或现有唤醒事件；唤醒不绕过底层读取期限。

历史 `round_interval_seconds` 仍可读，但不参与连续模式运行。状态显示 `cycle_mode=continuous`、无有效正常间隔和实际依赖等待。HTTP／CLI 新配置写入该字段明确失败；混合请求不部分应用其他设置。API 重试与订单确认配置继续用于其各自用途。

超时返回不代表底层 SDK 已结束。未结束的实际 Future 保留有限读取容量，不重复启动同一来源。公开 LP drain 收集真实账户读取及原发送器；未完成时报告错误，runtime 保留 owner 和账户资源。冷启动忽略旧正常等待和旧计划发送权限，保留真实未决请求、占用、审计及适用的重试围栏。

验证分别记录开发逐案证据、直接消费者 union、独立评审及精确提交 CI；本决定不代表这些门槛已完成，也不授权合并或生产操作。
