# LP 试挂池与实测收益池

2026-10-22，#396：在同一账户、同一 D2 owner、同一原生动作通道中增加两个独立预算的业务循环。该决定扩展 [ADR 0005](0005-lp-serial-fact-cycle.md)，并接入 [ADR 0006](0006-lp-owned-async-reads.md) 的既有异步读取所有权，保留其当前事实、固定轮次、UNKNOWN、保护和真实资源关闭规则。

## 配置与循环

显式保存 `allocation_mode=observed_pools` 后启用双池语义。原 `budget_usd` 成为 `trial_budget_usd` 的兼容别名，原金额不变；`income_budget_usd` 是另外配置的预算，缺省为零。两个值冲突时整个写入失败。试挂与收益各固定三个 BUY 名额，收益权重固定为 50% / 30% / 20%，互不借用预算。保存配置不启用自动交易，不写入生产配置。旧 `minimum` 和 C1 观察配置保留；旧执行器拒绝双池启用和执行，`rank_weights` 的 C2 门槛不变。

两个连续到期的业务循环轮流取得规划机会，测量时间更新不能一直抢占试挂。试挂使用已有的模型收益排序、最小数量与正常轮换。收益使用自己的有效测量及当前市场、账户、风险事实；试挂候选资格依赖失败不取消收益机会。循环共用一个启停意愿、一个账户锁、一个 startup round-zero 清理及现有请求通道，不建立第二个账户引擎。

只有从当前试挂中选入下一收益目标的样本，才保留同一 owner 内有界的转入来源；任意脱离原 BUY 的历史样本不取得候选权限。转入仍需当前市场与账户事实。候选市场与 BUY 共用同一 `LPReadRuntime` 的并发市场通道、64 个真实 scope 上限及既有物理连接、缓存、5 秒期限与起点节奏、清理所有者，按首次等待年龄统一准入；不创建第二个账户引擎或网络线程。未完成、失败或过期的来源不能授权新 BUY；源完成后迟收不刷新时间，当前盘口仍按既有 10 秒可用边界判断。每次已发布事实保留两个循环的到期机会，纯读取等待不能吞掉尚未服务的另一池；全部机会处理后按真实依赖或完成事件等待。

## 可归属测量

收益结果为有效官方小时奖励除以当时实测 BUY 未成交本金，再乘以 100，单位为百分比／小时。首个有效结果即可使用，不增加采样窗口。显式零是已知值；奖励缺失、身份或价量不可靠，以及多单贡献无法分配时保持 UNKNOWN。库存成本不进入这个分母。模型估算、官方测量、累计奖励、到账金额和净利润仍是不同事实。

每市场保留最新有效结果及其账户、精确来源订单、价量、本金和原始测量时间。后续更低的有效结果替代旧高值；取消原单、份额观察更新、读取和重启都不刷新时间。历史结果年龄在 0 至 120 秒（含边界）仅表示样本未过期，不证明当前成员或发送权限。已选中转入的来源可在原始 120 秒边界内继续比较；超过边界等待新测量。过期本身不取消已有收益组。扩大订单后，旧试挂结果仍注明旧来源与旧本金，不冒充大单的当前收益；现有当前敞口展示屏蔽继续生效。

## 收益组与下一轮

收益新候选仅来自当前最多三个受管试挂 BUY 的精确账户、市场、token 和订单身份，样本来源必须匹配当前 episode。仅取得测量不让全部试挂离池；被选中为下一收益目标时，该试挂才立即退出普通试挂业务成员。未分类／手动 BUY 仍保守占用资源，缺少角色不构成受管权限。候选与当前真实收益成员的有效实测值比较。并列优先保留成员，再按稳定市场身份排序；不设最低改善幅度。纯内部收益排名变化不单独重排已有组。新试挂进入前三时，撤销整组旧收益 BUY，包括保留成员，并撤销该候选原 BUY。例如 A=.6、B=1.0、C=.4、D=.8 时，下一组为 B、D、A，额度分别为收益预算的 50%、30%、20%。成员比较、身份或保护不安全／未知时推迟整组替换，独立试挂仍可按原守卫推进。

每轮先复制一个结果快照，封存这一轮固定请求。轮内新结果留到下一轮；旧组合、角色标记和审计都不恢复发送权限。下一收益机会重新读取当前事实并选择，不能强制恢复旧组合或旧请求。

一个成员只使用 50%，两个只使用 50% 和 30%，空权重留现金。最终价格、精度、最小量及其他风险校验在封存前生效；自动 `observed_pools` 的试挂与收益均不以「移除买一后的全量退出亏损≤10%／深度充足」拦截，但仍按实际最终数量计算并展示完整压力退出估算、拒绝原因及 UNKNOWN，不能把不足深度的未知损失写成零。单池和手动入口仍执行原压力退出门禁；不够最小量的市场被排除，再考虑下一候选。不重新分配余款，不增加最终金额的收益排序证明。部分失败保留成功单和现金，不回滚整组。失败槽位消费本次样本；即便曾是收益成员，也不凭该样本重复下单。UNKNOWN 保留原请求身份及真实占用，后续当前覆盖不伪造拒单结果。

## 占用、角色与恢复

转入来源只保留当前所选目标的原始样本、时刻、process epoch 和控制 generation，包括同组需重配的收益成员。该记录是有界过渡来源，不是冻结或可恢复的 BUY 计划；每次机会按当前事实重选，新试挂可改变组合。替换、过期、成功和已尝试的失败／UNKNOWN 消费对应权限，不累积历史队列。已接受的新收益订单可保留原样本与该精确接受身份的 owner 内比较关联；只有该实际订单当前存在时才参与比较，不能重开离场订单或重放请求。当前成员事实缺失／不安全时推迟比较，不因此丢弃仍有效的所选过渡来源。

收益成员离开试挂。原 BUY 的取消 ACK 不释放资金和名额；同市场旧单实际离场前，不创建重复收益 BUY。账户全部实际 BUY 和不确定请求占用只计一次；手动／未分类 BUY 继续按试挂侧保守计数，精确收益订单身份才属于收益侧。余额与 allowance 独立约束新增。库存、SELL 和其保护保留，不新增扣减 BUY 配置额度。

淘汰市场重新参与普通模型试挂；重新晋升需要新的试挂订单及新测量，不增加额外冷却。已放弃的晋升标记在样本过期、原 BUY 确认离场且没有未证明请求占用后，不得永久排除普通新试挂。完整当前账户事实证实精确收益订单已离场、无实际未决 BUY 所有权且无当前转入时，退休其有效成员身份；历史角色／样本不能阻止新组或重开旧 BUY。覆盖不完整仍为 UNKNOWN。重启或控制 generation 变化用当前事实和既有 round-zero 恢复占用，不从持久化角色恢复过渡权限；真实当前试挂可重新取得资格。实际原单释放后，其他试挂可先补位，无须等待收益新单成功。

整组取消使用现有 SDK 与 lease，每个精确订单保留独立请求、回执和 UNKNOWN 结果。真实 group cancel 在线程与 lease 生命周期内保留实际 owner，不占 BUY/SELL 下单的两个槽位；释放 lease 后复用有界完成通知唤醒 owner。空轮次不消费另一池的撤单机会，同一观察中的重叠精确目标仍只分派一次。双池仅对当前账户、市场、token、order 与受管试挂／收益角色精确相合的 BUY，在已成交数量确认>0且仍有剩余时，通过既有逐单取消撤掉剩余 BUY，原因 `buy_partial_fill`。UNKNOWN 成交数量不猜为零，终态或全成不重复撤，手动／未分类单和单池行为不变；持仓继续原成本底线被动 SELL，持仓市场不再新开 BUY。ACK 不推定最终成交量。暂停、stop、库存退出、现有 SELL、600 秒未知收益保护及真实原生 drain 义务不因池变化而放宽。

验证证据分开记录逐案测试、直接消费者、独立评审与精确提交 CI。P214 与 P301 的最初实现存在已披露的 TDD 顺序偏差。P301 原失败混有 ticket／源发布时间和官方测量／D2 时钟不一致；其原 RED 分类已撤回。后续功能 GREEN 和补充调度回归不能补造原始 RED。本决定不授权合并、部署、实盘采样或账户变更。

## 当前成员与四区展示（2026-10-24，#430）

`observed_pools.current_membership` 是既有状态接口的附加只读投影，来自同一当前账户快照及精确订单角色；标记 known／unknown、观察身份和时间，并单列转入来源。GET 不获取或刷新事实，不修改角色与样本。历史 `results.eligible` 仅表示原样本年龄。

移除自动配置下的逐市场历史结果日志，保留预算和启停控件。当天委托固定为试挂区／收益区／卖单区／已结束四个语义行组，各有实际订单数和空态；只在区内按市场合并。相同市场的 BUY 与 SELL 可分区，精确订单仅展示一次。分区使用当前精确身份，不凭数量或市场级旧角色；转入中不冒充已接受的新单，离场来源只作转入说明。双池 BUY 的归属缺失或冲突按下述 #436 数据完整性错误处理；只有显式可靠终态进入已结束，缺失、NaN、过期或 UNKNOWN 不构成终态。市场奖励／占资跨区共享，不重复汇总。会话归因及追加权限保留；SELL／终态行不提供追加。

本修订不改变任何撤单语义、范围、selector、payload、handler、确认或全局撤全部行为。全部既有精确订单动作、授权、资金、UNKNOWN、no-replay 和真实资源保护继续适用。


### 精确订单归属贯通（2026-10-24，#436）

订单的试挂／收益归属与财务 `current_membership.state` 分开。后台快照从实际认证账户响应的顶层 `account_id`／`wallet_address` 投影账户身份，配置钱包单独存在不能补足响应身份。现存 BUY 的账户、condition、token、order 必须与同账户角色的精确 episode、request 及既有已接受 BUY 回执相合，才输出 `pool_affiliation`；该字段同时保留精确四键和 request。数量、purpose、旧市场角色或历史样本都不能替代这些证据。仍然存在的原收益单即使角色已 evicted 或财务完整性 UNKNOWN，也保留收益展示。

同钱包账户键在展示边界统一去除首尾空白并转为小写，与真实 adapter 的账户规范相同；native request／receipt 保留的 mixed-case 拼写不构成另一账户。不同钱包仍拒绝，condition、token、order、request、process epoch 和 session 身份保持逐字精确匹配。前端只对账户键采用相同规范进行匹配与去重。

页面直接使用订单行的明确归属，既有已验证精确转入来源、SELL 和可靠终态优先级保留。标签为“收益单”／“试挂单”，表示已接受订单的明确归属，不宣称它仍具备当前业务成员资格；“转入中”保持原义。双池模式同时随缓存快照传递，独立自动状态尚未加载时也不能退回单池默认值。缺失或冲突的双池归属显示具体数据完整性错误、订单四键、方向及数量，并保留既有逐单撤单控件；错误订单不被猜成试挂／收益，不伪装为空态、不静默丢失，不增加第五个池或“待核对”分区。未启用双池的既有单池载荷保留兼容行为。

此投影只为已有真实行提供展示证据，不由历史记录生成订单。GET 读取后台缓存，展示读取不修改 current_membership、角色、资金状态或实际请求集合；缺失或 UNKNOWN 回执不成为 accepted。财务 UNKNOWN、发送、no-replay、owner 与原生资源守卫及所有撤单授权保持原合同。没有新增持久化字段、schema、历史重建或交易权限。

## 可见性与实测不可用保护（2026-10-27，#482）

收益循环每次跳过保留固定原因及有界相关身份、年龄、数量，通过 `observed_pools.income_gaps` 和只读监控显示；压力退出只作为估算，不再列为阻止进入的缺单原因。最近一次原始实测尝试与 Store 保留的有效样本分开，进程内最多 64 条；完成刷新时间在同一 owner 内保存，超过 120 秒显示「观测刷新停滞 N 秒」。GET 不刷新来源或网络、不改角色和交易集合。缺单持续时间遇到一次 UNKNOWN 不清零；新进程在取得自身连续观察证据前显示 UNKNOWN。

仅受管精确试挂 BUY 连续 600 单调秒没有来源为同一当前订单、年龄≤120秒的可用实测时，走原保护取消路径，原因 `measured_yield_unknown_timeout`。一次有效样本（含已知零收益）清零；重启不继承计时，UTC 跳变不推进它。收益单不因样本过期而取消，原模型 UNKNOWN 600 秒保护独立保留。所有新取消保留真实 native 所有权、发送前身份复核、同事实不重放和 UNKNOWN 最终量保护。本文不授权合并、部署或生产交易。
