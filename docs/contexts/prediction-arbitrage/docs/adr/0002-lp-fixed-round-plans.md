# LP 按固定计划逐轮执行，以 API 事实恢复

2026-10-10 的 #322 设计访谈确定：每轮以有效事实统一选择现有 BUY 和候选，形成固定目标与计划报价；本轮各项动作取得明确结果后，再等待配置的轮次间隔开始下一轮。该决定记录已确认设计。任务分支已实现公开入口行为，完成逐案聚焦检查；独立评审、CI、合并与部署仍由交付流程分别确认。

持续采用最新排名会使行情刷新不断打断执行。为获得清晰、稳定的执行节奏，本轮不因更优候选出现而改选，不自动修改计划报价；提交前发现价格变化则明确拒绝该动作，其他动作继续。接受本轮出现拒绝或临时空位，后续轮次重新选优并使实际组合收敛。

目标包含因保护已经触发且尚未完成而必须保留的订单；正常保护监控不禁止收益替换。允许多笔有独立安全依据的精确退出，不设置最低挂单保留数，接受短暂减少挂单和奖励覆盖。

有效完整的 Polymarket 账户 API 是当前挂单、持仓和占用的事实来源。API 暂时失败使本轮等待，并按固定间隔自动恢复，不将一次调用超时视为轮次完成。API 仍显示原订单 LIVE 时保留占用并自动核对/必要时精确重试；订单已不存在时按当前账户事实推进，不因本地旧审计阻止恢复。未知提交不直接重发，成交库存不提前释放资本，原身份、时效、资金和保护门禁保留。

轮次间隔、API 失败重试间隔、订单确认间隔分别配置，默认60、60、10秒。运行中修改从下一次等待生效，当前倒计时和计划不变，不递增间隔。该决定不改变既有竞争事实按批发布的可见性规则，也不授权合并、部署或生产交易操作。
