# 竞争事实按批提交发布，排序保留旧值

[Issue #306](https://github.com/raymizzou/open_trader/issues/306) 针对整轮竞争持久化的长事务及其对历史写入的干扰，采用有界读取、短事务提交后发布和批间让出；每批原子性替代整轮原子性，未更新市场继续使用最后成功的竞争事实。2026-10-09 用户已批准实施计划及下列三个边界。工作树实现和本机验证已完成，初次 Spec P1 修复后待原 reviewer 独立 staged 复审；本决定不表示已合并或部署。

1. **一次排序保持稳定快照。** 同一批同时更新 A、B 时，一次排序不能因发布交错而读到 A 的旧值、B 的新值。已开始的排序不因新批提交而反复重做；竞争版本变化在现有调度节奏中合并重排，不每批重建全池，也不等待整轮完成。
2. **重启保留已提交事实，重读未完成页。** 竞争行及恢复位置同事务提交，完整页提交后才推进下一页游标。失败批回滚，之前成功的批次保留；重放按市场 identity 幂等覆盖。未提交的读取结果不另建持久化待处理队列，重启可以取得变化后的公开数据，不承诺恢复退出前未提交的原始事实。
3. **本票一次解决长事务干扰。** 在批次正确性、读者隔离及恢复验证通过的前提下，同输入验证若证明事务明显缩短、历史写入不再因此超时，即可达到本票目标；不要求文件缓存或总内存峰值同时下降。仍记录内存、脏页、WAL 和失败证据，相关峰值原因另行处理，不据此声称云端容量或运行健康已通过。

该决定有意取代 [#297](https://github.com/raymizzou/open_trader/issues/297) 的整轮原子发布与整轮回滚要求，保留其缓存所有权、调用者隔离和完整候选覆盖。每批不复制全量竞争表；真实检查时间、来源、陈旧标记、显式零与 UNKNOWN 语义保持，账户、资金、盘口和交易门禁不变。

同规模公开缓存派生回放选择 500 行/10 ms 可中断等待；最终事务观测跨度约 807→43 ms，历史 BEGIN 最大等待约 821→12 ms，整轮刷新约 1.01→7.93 s，RSS 无下降。页恢复、cache+SQLite 批次一致性、旧 reader/旧库兼容及完整候选验证见 [本机验证记录](../competition-batch-verification-2026-10-09.md)。缺少当次云端原样输入，未测 Linux cgroup/dirty pages，不声明云端容量或运行健康；发布、独立评审、CI 和部署保持各自边界。
