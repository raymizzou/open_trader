# 趋势复盘未满 30 笔时展示绩效指标

## 状态

- 日期：2026-08-09
- 状态：已批准
- 范围：A 股、港股、美股趋势复盘的五项绩效指标

## 问题

Dashboard 已正确显示纪律模拟合格闭环进度，例如美股 `7 / 30`，但同时把纪律模拟与同期市场的五项指标全部显示为缺失。现场事实中三个市场的每日模拟账户净值和市场基准均已连续归档；缺失发生在复盘投影阶段，而不是数据采集阶段。

当前实现把 Kelly 样本的策略版本筛选和 30 笔门槛错误地扩展到日终绩效曲线。版本筛选移除了曲线起始日，连续区间校验随后把整条曲线判为缺失。

## 决策

30 笔门槛只控制 Kelly 是否启用，不控制复盘绩效是否展示。它修订 `2026-07-16-trend-strategy-review-design.md` 中“未满 30 笔不计算自己的指标”的规则；其他规则不变。

- Kelly 样本数继续来自独立的完整闭环统计，保持 `n / 30` 进度和现有样本审计。
- 纪律模拟绩效继续直接采用已经冻结的富途模拟账户日终净值，不从闭环收益重新拼接。
- 绩效曲线不再使用 Kelly 开仓版本身份过滤；兼容策略修订期间的连续账户净值属于同一条实际运行曲线。
- 同期市场使用与对应绩效曲线完全相同的日期区间。
- 实际执行仍只使用真实账户日终净值；缺失时不使用模拟值、成交收益或插值替代。
- 每项指标按自己的数学条件输出。期间收益、超额收益和最大回撤在曲线足够时立即显示；最大回撤为零、交易日收益波动为零或观察期不足时，卡玛和夏普继续显示具体不可算原因。

## 数据流

```text
完整闭环成交 -> trend_api_stats.json -> Kelly 样本进度与启用状态

每日模拟净值 + 每日市场基准 -> trend_review projection -> 五项模拟绩效
每日实盘净值 + 每日市场基准 -> trend_review projection -> 五项实盘绩效
```

三条路径互不代算。统计刷新失败不得清空已存在的日终绩效；复盘投影失败也不得改写 Kelly 统计或原始净值事实。

## 最小实现

只调整 `build_trend_review_projection` 的曲线选取边界：策略快照和 Kelly 样本仍按现有身份规则选择，日终绩效则使用已通过事实校验的连续净值与基准。Dashboard 继续消费同一投影结构，不新增 API 字段、服务、调度或前端布局。

## 验证

- 回归测试使用多个兼容策略版本的连续日终净值，并保持 Kelly 样本少于 30；五项中数学上可计算的纪律模拟值和同期市场值必须非空。
- Kelly 样本数、选中闭环和启用状态不得变化。
- 实盘日终净值缺失时，实盘指标仍明确不可用。
- 真实 `data/` 重建三个市场投影后，CN/HK/US 的纪律模拟与同期市场不再全部显示缺失。
- 聚焦测试与直接工作流通过后，更新 `CHANGELOG.md`，合并到 `main`，最后运行一次 `make acceptance`。仅 `PASS` 后精确重部署该 SHA，并验证 PID、工作目录、Git SHA、新日志和 Dashboard HTTP 200。
