# 三市场趋势过热止盈设计

## 状态

- 日期：2026-07-22
- 状态：已批准，grilling 完成
- 范围：东方财富 A 股、老虎美股、辉立港股趋势策略

## 目标

把趋势动物的“沸腾”和“开香槟”信号变成三市场统一、可执行、可恢复的
一次性部分止盈规则：每笔完整趋势交易首次触发任一信号时减仓当前实际持仓的
30%，剩余仓位继续由现有移动保护线和强制清仓规则管理。

本次不自造“波动率放大”指标。实时查询 `getSnapshotColumnBilling` 返回的 45 个
字段中，止盈字段只有：

- `stopwinFlagByBoilingTemperature`
- `stopwinFlagByDangerSignal`
- `stopwinFlagByPopChampagne`

## 已选方案

新增显式 `SELL_PARTIAL` 正式动作，并复用现有卖出订单、重试、人工解决、审计和
完整交易归集链路。禁止用带数量覆盖的 `SELL_ALL` 冒充部分止盈，也不把新规则
降级成只提醒、不执行。

不新增服务、依赖或独立状态机。现有冻结报告、不可变动作账本和保护状态仍是唯一
数据流。

## 退出优先级

每个持仓按以下顺序只产生一个纪律动作：

1. 活动保护线已触发：`SELL_ALL`。
2. 危险信号触发：`SELL_ALL`。
3. 已离开趋势右侧：`SELL_ALL`。
4. A 股由温、热或沸转为平：`SELL_ALL`。
5. 本完整持仓生命周期尚未完成过热止盈，且沸腾或开香槟为真：
   `SELL_PARTIAL`。
6. 否则继续持有。

强制清仓始终胜过部分止盈，但明确为真的信号不被其他未知字段压掉：

- 任一强制清仓条件明确为真时，执行 `SELL_ALL`。
- 没有明确的强制清仓条件、但任一过热信号明确为真时，执行
  `SELL_PARTIAL`；即使危险、右侧、A 股温度或另一个过热字段未知，也只附加
  人工检查警告，不阻止 30% 止盈。
- 没有任何明确退出信号、但所需字段未知时，继续人工复核，不自动交易。

## 一次性语义

“沸腾”和“开香槟”合并为一次机会，而不是各减仓一次：

- 任一信号首次出现时触发 30% 止盈。
- 连续多日为真不重复触发。
- 另一个信号以后首次出现也不再次触发。
- 当前尚未平仓的旧仓适用新规则；其状态中没有既有止盈完成事实时，部署后当前
  已为真的过热信号视为首次可执行信号。
- 仓位归零后删除该持仓状态；未来重新入场形成新的完整交易，可以再次止盈一次。

每个冻结动作携带 `position_started_for`，使成交事实和保护状态都能绑定同一持仓
生命周期，避免旧仓退出后的历史止盈事实污染未来再入场。

新仓不设置最短持有期。首次买入成交后的下一份报告只要出现明确过热信号，就可
执行部分止盈；同一份报告不会对尚未成交的新买入同时生成部分止盈。

## 数量与最小交易单位

冻结报告保存：

- `action = SELL_PARTIAL`
- `reason = overheat_take_profit`
- `target_fraction = 0.30`
- 市场最小交易单位
- 基于报告账户快照的预计卖出数量
- `position_started_for`

首次提交前，执行器重新读取模拟账户实际持仓，并冻结不可变目标数量：

```text
目标数量 = floor(实时持仓数量 × 30% / 最小交易单位) × 最小交易单位
```

最小交易单位为：

- A 股：100 股。
- 美股：1 股。
- 港股：Futu 返回的标的整手股数。

实时数量用于防止报告生成后发生人工调整而超卖；同一持仓生命周期的第一笔
intent 写入后，后续恢复和重新触发都只使用该不可变目标，并扣除该生命周期已经
确认的部分卖出成交，不随持仓、价格或报告日期重新计算第二个 30%。

目标不足一个交易单位时不下单，写入一次终态 `below_lot` 并将该持仓生命周期的
过热止盈记为不可执行完成，避免每天重复提醒。缺少或无效的港股整手数据时不写
`below_lot`，而是人工复核，因为系统无法证明目标确实不足一手。

## 移动保护线

沸腾或开香槟出现时，无论部分止盈最终是否成交，都立即启用现有跟踪保护：

```text
新活动保护线 = max(旧活动保护线, 此前 5 个完整交易日最低价)
```

保护线只升不降。部分止盈后的剩余仓位继续受活动保护线、危险信号、右侧退出和
A 股温度转平约束。

## 订单与恢复

### 正常执行

- 过热信号来自日级快照。报告在数据日冻结，模拟盘在下一交易日开市后执行；不把
  日级信号冒充盘中即时信号。
- `SELL_PARTIAL` 使用市价卖单，并排在所有买入动作之前。
- 预计止盈回款不计入当天买入预算。
- 首次 intent 冻结目标数量；累计确认成交达到目标数量后才完成部分止盈。
- 部分成交后，只有原订单明确终止，才按未完成目标提交下一 attempt。
- 活动或状态不明确的订单禁止重叠提交，并沿用现有 `uncertain` 人工解决流程。
- 未完成动作跨进程重启和交易日恢复，不因生成新报告而丢失。
- 动作触发后，即使下一份快照的过热信号消失，也继续完成已冻结目标；明确人工
  `abandon` 是唯一例外。
- `abandon` 只终止当次动作，不把本持仓生命周期记为已止盈。下一份报告仍有过热
  信号时重新执行；信号消失时不执行，以后再次出现时再触发。重新触发只补足最初
  30% 目标的未成交数量。

### 与强制清仓合并

卖出身份继续使用市场、执行日期、标的和 `sell` 方向，避免同日创建两个可重叠的
卖出动作。账本事件增加明确的卖出目标：`partial_30` 或 `position_zero`。

部分止盈期间出现强制清仓时：

1. 立即追加不可变的 `position_zero` 升级原因，并阻止冲突买入。
2. 若已有卖单仍活动，不提交重叠卖单。
3. 原订单明确终止后，重新读取实际剩余持仓。
4. 为全部剩余数量创建下一 attempt，直到权威账户快照证明仓位为零。

`partial_30` 的 `filled` 事件不能满足 `position_zero` 的完成条件。这样即使 30%
已经成交，同日保护线触发仍会卖出剩余仓位。

如果原部分止盈订单状态不明确，强制清仓原因仍立即记录并发出紧急人工处理提示，
但控制器不得猜测成交数量或叠加卖单；人工解决原订单状态后，再卖出权威账户快照
中的全部剩余仓位。

### 崩溃恢复

不可变订单和成交事件是“是否已经止盈”的权威事实，保护状态只是可重建投影。
如果进程在确认成交后、写保护状态前崩溃，重启后必须先从账本恢复同一
`position_started_for` 的止盈状态，再生成或执行动作；不得重复减仓。

只有累计确认成交达到冻结目标，或已权威确认 `below_lot`，才把保护状态中的
`overheat_trim_status` 写为终态。提交、部分成交、失败或不明确状态都不能提前
消耗这次机会。

## 样本与策略身份

本次按用户要求保持三市场现有：

- `strategy_id`
- `strategy_version`
- Kelly 样本键与既有样本计数
- 累计回撤高水位和人工解锁状态

策略快照新增机器可读参数和对应中文参数行：

- `overheat_trim_fraction = 0.30`
- `overheat_trim_once_per_position = true`
- `overheat_trim_signals = [boiling, champagne]`
- `overheat_trim_rounding = floor_to_market_lot`
- `overheat_trim_below_lot = no_order_terminal`
- 强制清仓优先于部分止盈

历史冻结产物不重写。报告日期、完整参数快照和 Git SHA 区分规则生效前后；旧规则
和新规则闭环按用户要求进入同一个 Kelly 样本池。

部分止盈不关闭完整交易。样本只在持仓最终归零时生成，并聚合同一生命周期内的
全部买入、部分卖出、最终卖出和费用。

本次不在复盘页增加“样本混合新旧规则”的提示、拆分指标或新图表；复盘展示保持
原样，冻结产物继续保留足够的参数和 Git SHA 供审计。

部分止盈后不按原目标权重补仓，也不因 Kelly 或目标权重变化重新加回。同一完整
交易只有在最终归零、以后重新入场时，才重新获得新的仓位和止盈机会。

## 纪律账户与真实执行

三套 Futu 模拟账户继续是趋势动作的唯一事实源，真实账户不另跑第二套退出状态：

- 模拟盘由控制器自动执行 `SELL_PARTIAL`。
- 东方财富、老虎和辉立真实账户仍由用户手工下单，不新增实盘自动交易权限。
- 真实操作以“下单时真实持仓的 30%，向下取整到市场交易单位”为准。
- Dashboard 把自动订单数量明确标为“模拟数量”，不得冒充真实账户建议股数。
- 不新增真实成交确认步骤。模拟盘完成后不重复提醒；真实账户是否跟单由后续结单
  和执行偏差统计反映。
- 真实账户和模拟账户持仓不一致时，仍以模拟纪律账户产生动作，不为真实账户创建
  第二套冲突信号。

## 报告、Dashboard 与通知

冻结 JSON、Markdown、飞书和 Dashboard 必须把 `SELL_PARTIAL` 显示为
`止盈减仓 30%`，不得显示成全部卖出。展示以下事实：

- 触发信号：沸腾、开香槟或二者同时出现。
- 目标比例和预计数量。
- 最小交易单位。
- 已成交数量、剩余目标和订单状态。
- 当前活动保护线。
- `below_lot` 或人工复核原因。

颜色不能作为区分部分止盈和全部卖出的唯一方式。桌面和 375px 移动布局都必须
显示动作文字与数量。

不为日级 30% 止盈新增语音提醒。它沿用 Dashboard 和飞书日报；语音继续留给盘中
保护线等紧急风险事件。

## 错误处理

- 没有明确退出信号且退出字段未知：人工复核，保留原活动保护线。
- 任一过热字段明确为真：即使其他退出字段未知，仍执行 30% 止盈并显示人工检查
  警告。
- 港股整手未知或非法：人工复核，不猜数量。
- 模拟账户持仓缺失或非法：阻止该动作，不写 intent。
- intent 已写但经纪商事实不明确：`uncertain`，禁止自动重试。
- 动作账本、持仓生命周期或冻结报告不一致：失败关闭，不修补历史事实。
- 状态投影缺失但不可变成交事实完整：从账本恢复投影，不再次下单。
- 保护线或强制清仓触发：即使部分止盈异常，也保持完整退出优先。
- 已冻结或锁定的历史及当天报告不改写。新规则只从部署后生成的第一份新报告
  生效；当前旧仓在该报告中首次按新规则检查。

## 验证与验收

自动化测试至少覆盖：

1. 三市场共同动作优先级，以及 A 股独有温度转平规则。
2. 沸腾、开香槟、同时出现、连续出现和先后出现只止盈一次；任一明确过热信号
   穿透其他未知字段，而纯未知仍人工复核。
3. 当前旧仓、仓位归零后再入场和 `position_started_for` 隔离。
4. A 股、美股、港股向下取整及 `below_lot`；港股整手缺失转人工复核。
5. intent 之前按实时仓位冻结目标，之后不重新计算。
6. 部分成交、拒单、活动订单、不明确订单、跨重启和跨日恢复。
7. 部分止盈进行中或完成后，同日强制清仓升级且不重叠下单。
8. 成交事件写入后、保护状态写入前崩溃的无重复恢复。
9. 部分卖出不关闭样本，最终归零只形成一个完整交易并聚合全部费用。
10. `abandon` 后按后续信号重新触发，并只补足同一生命周期原 30% 目标。
11. 策略版本、Kelly 样本计数和累计回撤状态不重置，复盘页面保持原样。
12. 冻结 JSON、Markdown、飞书、Dashboard 桌面与移动展示，且无新增语音。
13. 真实账户保持手工执行，模拟数量不会冒充真实建议数量，部分止盈后不补仓。
14. 旧报告不改写，新规则只在部署后的第一份新报告生效。
15. `纪律.md`、`CONTEXT.md` 和策略快照参数一致。

开发中运行聚焦测试和三市场直接工作流，不提前运行 `make acceptance`。最终必须：

1. 运行相关和全量自动测试并记录精确输出。
2. 使用真实三市场模拟账户直接运行报告与控制器流程。
3. 检查并重启仍加载旧代码的 controller、screen 或 launchd 进程。
4. 核对新 PID、工作目录、Git SHA、时间戳和新日志。
5. 将 `make acceptance` 作为唯一最终 Dashboard 验收门；只有 `PASS` 才能请求
   用户验收。
6. 重新部署完全相同的已验收 Git SHA，并验证 Review URL 返回 HTTP 200。

- 不把部分止盈成交当成完整交易结束。
- 不重置 Kelly 样本、策略版本或回撤基准。
- 不在复盘页显示样本混合提示或拆分新旧规则指标。
- 不为真实账户自动下单、创建第二套信号或新增成交确认流程。
- 不在部分止盈后补回目标仓位。
- 不新增部分止盈语音提醒。
- 不改写已冻结或锁定的报告。
