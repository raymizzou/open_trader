# 富途模拟股票账户固定配置修复

## 目标

富途模拟盘的港股、美股和 A 股股票读写都严格使用各市场已配置的模拟正股账户：

- `OPEN_TRADER_TREND_REVIEW_CN_SIMULATE_ACC_ID`
- `OPEN_TRADER_TREND_REVIEW_US_SIMULATE_ACC_ID`
- `OPEN_TRADER_TREND_REVIEW_HK_SIMULATE_ACC_ID`

配置 ID 是唯一权威来源，不做自动发现、账户类型推断或回退。账户不存在时沿用现有明确失败行为。Dashboard 模拟持仓、趋势控制器、趋势报告账户读取、Kelly 模拟执行和验收检查继续复用现有 `FutuSimulateOrderExecutionClient`。

本次不新增期权配置或执行路径；实际接入期权交易时再按相同方式增加对应的固定账户配置。

## 根因与修复

现有代码已经把三个市场的配置 ID 传入持仓查询和下单客户端。故障来自：

1. 港股配置误写为期权模拟账户。
2. Dashboard 和控制器仍运行旧进程，未重新载入修正后的配置。
3. 港股冻结报告及执行账本绑定旧账户，直接切换配置会触发审计保护。

修复仅包括：

- 把港、美、A 三个配置 ID 固定为对应正股模拟账户。
- 只读归档旧港股冻结报告、执行账本和控制器状态，不修改历史文件。
- 新建绑定港股正股账户的活动状态；今天已执行的信号不再重放，从下一交易日正常自动运行。
- 部署时统一重启 Dashboard 和三个趋势控制器，使启动配置立即生效。

不增加配置热加载。账户配置变更由部署重启生效，启动状态和日志记录实际账户 ID。

## 测试

先运行现有聚焦测试，确认 Dashboard、趋势控制器和执行客户端继续严格传递配置 ID；只有测试暴露代码缺陷才修改生产代码。

真实富途模拟盘测试对 CN、HK、US 各提交一笔远离市价的限价股票单，使用唯一 smoke-test 备注；确认实际订单账户与固定配置一致后立即撤单，并核对 `dealt_qty == 0`。若任一订单成交，立即停止后续测试并报告实际持仓。

Dashboard 使用港股正股账户的现有真实模拟持仓验证 `/api/trend-simulate-positions/phillips` 不再为空。

最终按项目规则运行一次 `make acceptance`。仅当结果为 `PASS` 时，部署该验收 Git SHA，重启 Dashboard 和三个趋势控制器，并验证 PID、工作目录、Git SHA、新日志、HTTP 200 与港股模拟持仓页面。

## 非目标

- 不触碰真实账户或实盘下单。
- 不改变趋势策略、仓位计算、报告哈希或防重账本。
- 不新增生产路由代码、配置项、依赖、账户缓存、配置热加载或后台任务。
