# 轮换强度口径、可解释展示与刷新位置修复设计

## 状态

- 设计日期：2026-08-03
- 基线：本地 `main` `31be3be45d56afa0943207fc8341e261c225e977`
- 市场：A 股、港股、美股，各自包含股票与 ETF 大类
- 用户已确认：同大类用大类内强度轮换，跨大类用全局强度轮换；
  股票和 ETF 允许互相轮换；今天的三市场报告全部重新生成。
- 实盘仍只生成手动建议，不增加自动下单权限。

## 背景与根因

当前美股报告显示 SHEL 大类内强度 `98.6`，模拟盘最弱持仓 PM
大类内强度 `76`，两者差 `22.6`，但报告没有轮换。现有轮换程序
统一比较 `trendStrengthGlobalCurr`：SHEL `95.36` 减 PM `86.18` 只有
`9.18`，未达全局差 20 的门槛。

现有规则可以比较股票和 ETF，但对同大类内的强弱更换不够敏感。
同时 Dashboard 仅显示名为“强度”的大类内强度，隐藏了实际轮换口径，
空轮换区只显示“无”，导致正确但不可解释的结果。

Dashboard 自动刷新时会重建账户内容。旧修复已保留当前账户页签和
`details` 展开状态，但重建后的 `focus()` 会让浏览器自动滚回顶部页签。
实测可稳定复现从 `scrollY=1000` 跳到 `scrollY=275`。

## 目标

1. 同大类轮换使用大类内强度，跨大类轮换使用全局强度。
2. 保持 20 点轮换门槛、每市场每账户每交易日最多两组、模拟盘
   自动与实盘手动的已确认边界。
3. Dashboard 同时展示大类内强度和全局强度，并展示实际比较口径、
   差值、门槛及未轮换原因。
4. 自动刷新不改变用户的纵向滚动位置，且不丢失键盘焦点、当前页签
   或展开状态。
5. 部署后重新生成并选中 2026-08-03 运行日的 A/HK/US 三份报告；
   美股模拟轮换可按其今晚的目标交易日执行。

## 非目标

- 不改变三市场资源排名；资源排名仍统一使用全局强度。
- 不改变普通入场、强制退出、Kelly、风险、现金、手数和保护线规则。
- 不追求与趋势动物小程序收藏夹整数逐点相等。
- 不增加轮换冷却期、新的持仓上限或第三组轮换。
- 不使用 `localStorage` 记录滚动位置，不增加前端状态库。
- 不覆盖或删除旧报告、旧执行批次或旧订单事实。

## 强度口径

### 大类身份

配对时使用趋势动物 snapshot 中的 `asset` 作为大类身份：

| 市场 | 股票大类 | ETF 大类 |
| --- | --- | --- |
| CN | `A股` | `ETF基金` |
| HK | `港股` | `香港ETF` |
| US | `美股` | `美国ETF` |

候选与持仓必须冻结这个大类身份。缺少或不属于当前市场两个允许大类
时，只排除该标的轮换比较，不影响其他标的。

### 每对的比较规则

```text
if candidate.asset == holding.asset:
    basis = local
    gap = candidate.local_strength - holding.local_strength
else:
    basis = global
    gap = candidate.global_strength - holding.global_strength

rotate when gap >= 20
```

- `local` 对应 `trendStrengthLocalCurr`，报告与 UI 命名为“大类内强度”。
- `global` 对应 `trendStrengthGlobalCurr`，报告与 UI 命名为“全局强度”。
- 同大类比较缺少任一大类内强度时不回退到全局强度。
- 跨大类比较缺少任一全局强度时不回退到大类内强度。
- 任何缺失只使当前比较不可用，不冻结整个市场报告。

### 配对选择

1. 保留现有入场门槛、持仓 `HOLD` 结论、强制退出和空席优先级。
2. 对所有合格的“未持有候选 × 可轮换持仓”生成可比较组合。
3. 每组按上述规则决定比较口径和差值。
4. 先按差值降序，再按同大类优先、候选代码和持仓代码做稳定打破平局。
5. 按排序贪心选取候选与持仓均未被占用的组合，最多两组。
6. 只有差值大于或等于 20 且后续现金、手数与风险规则生成非零买单时，
   该组才成为正式轮换。

两种口径都是 0–100 的排名分位尺度，因此差值可共用 20 点门槛。
差值相同时优先同大类是为了让直接同类替换比跨类替换更易解释，
不改变数值门槛。

## 冻结报告合同

新策略版本必须冻结：

- 候选和持仓的 `asset`、大类内强度和全局强度；
- 每个正式轮换对的 `strength_basis`（`local` 或 `global`）；
- 买卖两端的大类、大类内强度和全局强度；
- 实际用于比较的买方强度、卖方强度、差值和门槛；
- 模拟盘与实盘各自最多两条冻结比较结果。

每条比较结果包含：

```text
pair_index
sell/buy identity and asset
sell/buy local_strength and global_strength
strength_basis
sell_compared_strength
buy_compared_strength
strength_gap
threshold = 20
outcome = planned | gap_below_threshold | sizing_blocked | data_unavailable
reason
```

新字段增加在现有 `simulate_rotation_pairs` / `real_rotation_pairs` 之外；正式轮换对
仍是执行唯一输入。比较结果只用于解释与审计，不能被 Controller
当成订单。正式对必须与同一个 `planned` 比较结果的身份、口径和差值一致。

旧版报告继续按旧合同只读显示，不回算。新版报告使用新策略版本，
并继承已审计的 Kelly 样本与回撤状态，不重新积累。

## Dashboard 设计

### 候选和持仓表

- 原“强度”列改名为“大类内强度”。
- 紧邻其后增加“全局强度”列，数值加粗但不使用新的色彩语义。
- 桌面继续使用现有表格横向滚动；手机继续由现有 `data-label` 卡片化，
  不新建移动版组件。
- 强度缺失时明确显示“数据未提供”。

### 相对强度轮换区

保留现有“模拟盘自动”与“实盘手动”两组。每组显示最多两张冻结
比较卡：

- 正式轮换：显示“已进入轮换”、比较口径、买卖标的、差值、门槛、
  目标仓位、金额、数量与执行状态。
- 差值不足：显示“未触发”、比较口径、实际差值、门槛 20 以及
  “还差 X”。
- 仓位、现金、手数或风险阻止：显示已冻结的精确原因，不用笼统的
  “无”。
- 实盘账户输入不可用：显示数据源阻止原因，不暗示已做轮换判断。

同大类卡片主数值标注“大类内强度”；跨大类卡片主数值标注“全局强度”。
Dashboard 不根据候选表与持仓表自行重组或重算轮换。

## 自动刷新不跳位

修复当前根因，不引入通用滚动状态系统：

1. 重建账户 DOM 后仍恢复原键盘焦点。
2. 焦点恢复使用浏览器原生 `focus({preventScroll: true})`。
3. 保留现有当前账户、当前视图、`details` 展开状态和历史报告显式
   滚动恢复。
4. 用户主动切换账户、页签或历史报告时，仍允许现有导航行为改变视图。

该修复针对定时行情刷新和就地 Dashboard 重绘，不承诺跨浏览器进程保留
手动 F5 前的位置。

## 今日三市场重新生成

实现、验证、合并并将候选 SHA 部署到生产运行时后，在最终 Dashboard
`make acceptance` 之前，使用该精确 SHA 重新生成今天运行的三市场报告：

- CN：使用当前 A 股数据日，交易日仍由市场日历确定。
- HK：使用当前港股数据日，交易日仍由市场日历确定。
- US：使用最新美股收盘数据日，目标交易日为今晚对应的美股交易日。

“重新生成”表示写入新的不可变 `-rN` 修订并将它提升为当前报告，
不覆盖旧 JSON/Markdown。执行前必须重新确认：

- 目标交易日没有已锁定且不同 SHA 的执行批次；
- 没有已提交、部分成交、状态未知或冲突的模拟单；
- 新报告冻结相同的资源排名快照参考和新策略版本；
- Controller 在市场开盘时只锁定新报告 SHA。

任一市场已有不可安全替换的批次或订单事实时，该市场停止自动切换并
报告具体阻止项，不删除或改写事实。

重新生成复用正式报告通知幂等契约；已发送的同一消息不强制重发，
不为验收额外发送测试通知。

## 验证与验收

### 策略单元测试

- 同大类 `local gap = 20` 触发，`19.9` 不触发。
- 跨大类 `global gap = 20` 触发，`19.9` 不触发。
- 同大类缺 local、跨大类缺 global、缺 asset 时不使用其他字段回退。
- 股票与 ETF 可形成跨大类轮换。
- 差值排序、同大类平局优先、候选/持仓唯一使用与两组上限稳定。
- 模拟盘与实盘的配对、资金和阻止原因仍相互独立。
- 新策略版本继承 Kelly 和回撤状态。

### 报告和 Dashboard

- JSON、Markdown、Dashboard 投影对大类、两种强度、比较口径、差值与原因一致。
- 无正式轮换时不再只显示“无”。
- 旧报告仍能显示，且不被新规则回算。
- 键盘焦点保留时，将页面滚到报告下方后调用就地刷新，`scrollY` 保持不变。
- 展开状态、账户页签、历史报告与手机卡片展示不回归。

### 最终运行验证

1. 运行相关精准测试和完整测试集。
2. 在 `CHANGELOG.md` 已提交后合并到 `main`，将该精确候选 SHA 部署到生产
   运行时，但此时不声称任务完成。
3. 运行无下单预检，然后直接生成并提升三份当日新修订，核对冻结
   JSON、当前报告选择和旧进程不会重写。
4. 最后运行一次 `make acceptance`，使验收同时覆盖新代码、真实 API/报告数据、
   实时刷新和桌面/手机流程；只有 `PASS` 可继续。
5. 不再改变源码或报告数据，重新部署精确验收 SHA，核对 PID、工作目录、
   Git SHA、新日志与审查 URL HTTP 200。
6. 重新检查三个 Controller 的批次 SHA、阻止状态、订单账本和新日志。

## 验收示例

若生成时的冻结数据仍为 SHEL 大类内强度 `98.6`、PM 大类内强度
`76`，且两者均属于 `美股`、全部其他门槛仍通过，美股模拟盘应冻结：

```text
卖出 PM → 买入 SHEL
比较口径：大类内强度
差值：98.6 - 76 = 22.6
门槛：20
结果：进入模拟盘自动轮换
```

该示例不硬编码标的或数值；当日实际报告仍以重新获取并冻结的
趋势动物、账户、价格和风险事实为准。
