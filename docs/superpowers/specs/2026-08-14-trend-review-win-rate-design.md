# 趋势复盘完整交易胜率设计

日期：2026-08-14
状态：设计已确认，待实施计划

## 目标

在现有“策略与市场基准”区域分别展示纪律模拟与实际执行的完整交易胜率，让用户能看到一笔持仓从首次开仓到最终清仓后是否取得成本后正收益。

## 已确认口径

- 纪律模拟和实际执行必须分开统计，不合并样本。
- 一个样本沿用现有完整趋势交易定义：同一标的从首次可归因买入开始，聚合期间的加仓、部分卖出和费用，直到关联持仓数量归零。
- 只有归因明确、成本完整、净收益可得且符合当前策略身份边界的完整闭环进入分母。
- 成本后净收益 `net_pnl > 0` 才计为胜。
- 成本后净收益 `net_pnl == 0` 计入闭环分母，但不计为胜。
- 胜率为 `胜出闭环数 / 合格完整闭环数`。
- 少于 30 个合格闭环时仍展示观察到的胜率；30 笔门槛继续只控制 Kelly 启用和现有“数据不足”提示。

## 数据所有权

`trend_api_stats` 已经把成交构建成完整闭环，并为每个闭环保存 `win`、`loss`、`flat` 或 `unavailable`。本功能必须复用这套结果及现有 `_partition_round_dispositions` 身份、归因、成本和净收益筛选，不在趋势复盘投影或 Dashboard JavaScript 中重建持仓周期。

`trend_statistics_disposition` 为纪律模拟和实际执行分别补充：

- `winning_sample_count`：合格闭环中 `result == "win"` 的数量；
- `win_rate`：0 到 1 的十进制字符串；没有合格闭环或统计来源不可用时为 `null`。

现有 `eligible_sample_count` 继续作为分母。投影验证必须保证：

- `0 <= winning_sample_count <= eligible_sample_count`；
- 有合格闭环时，`win_rate == winning_sample_count / eligible_sample_count`；
- 没有合格闭环时，`winning_sample_count == 0` 且 `win_rate is null`；
- 来源不可用时不得合成 `0%`。

## 投影契约

趋势复盘投影从 `open_trader.trend_review.projection.v4` 升级为 `open_trader.trend_review.projection.v5`，因为 `sample_details.discipline` 和 `sample_details.actual` 的严格字段集合发生变化。不得在保留 v4 版本号的同时静默增加字段。

生成器、Dashboard 验证器和三市场 Controller 同步要求 v5。Controller 沿用现有版本恢复机制，把旧 v4 投影视为需要重建；部署验收必须确认 CN、HK、US 的最新投影均已更新为 v5。

## 页面设计

采用用户选择的 Mock A，不新增指标轴、卡片或市场基准占位。

在现有两列统计摘要中分别增加一行：

- 有合格闭环：`完整交易胜率 16.67% · 1 胜 / 6 闭环`
- 来源可用但无合格闭环：`完整交易胜率 数据不足 · 0 闭环`
- 来源不可用：保留现有 `统计来源不可用`，不显示虚假的胜率数值。

该行位于各自的“发现 / 排除 / 未闭环”信息之后。百分比最多保留两位小数，复用现有趋势统计百分比格式，不由前端重新计算胜率。

同期市场、市场 1 年和市场 5 年没有“完整交易”语义，因此不显示胜率或“不适用”。现有五个市场比较指标、共享标尺、桌面与移动布局保持不变。

## 数据流

1. 成交事实继续由 `trend_api_stats` 构建完整闭环并判定 `result`。
2. `trend_statistics_disposition` 按来源和当前策略身份筛出合格闭环，返回合格数、胜出数和胜率。
3. `build_trend_review_projection` 把两条独立统计写入 v5 投影。
4. Dashboard 加载投影后，继续用最新统计快照覆盖样本明细；覆盖结果包含相同的胜率字段。
5. `renderTrendReviewStatisticsMeta` 只负责格式化并放入已选定的位置。

## 缺失和失败语义

- 统计来源缺失或无匹配审计：显示 `统计来源不可用`。
- 来源可用但合格闭环为 0：显示 `完整交易胜率 数据不足 · 0 闭环`。
- 有闭环但投影中的胜出数、分母或胜率不一致：投影无效，Dashboard fail-closed，不猜测或修正数值。
- 排除样本和未闭环样本不进入分母，继续由现有统计摘要解释。
- 日终净值缺失只影响收益、回撤、Calmar 和 Sharpe 等曲线指标；只要闭环统计有效，胜率仍可独立展示。

## 范围外

- 不改变买卖规则、策略版本继承、Kelly 计算、仓位或执行逻辑。
- 不新增交易历史系统、数据库表、前端闭环算法或第三方依赖。
- 不把纪律模拟和实际执行合并成一个总胜率。
- 不为市场基准定义或推导胜率。
- 不增加盈亏比、平均盈利、平均亏损或单笔明细入口。

## 验证

实施使用测试先行，最小覆盖如下：

1. `trend_api_stats`：纪律模拟与实际执行分别覆盖赢、亏、持平、排除和未闭环样本，验证胜出数、分母和胜率。
2. `trend_review`：验证 v5 投影、零样本、来源不可用、少于 30 笔仍有胜率，以及纪律模拟与实际执行互不混合。
3. `dashboard`：严格校验字段和比率一致性，验证最新统计覆盖不会写文件。
4. `dashboard.js`：验证方案 A 的两条独立文案、零样本不显示 `0%`，并确认仍只有五个市场比较指标和 25 个基准序列项。
5. Controller：验证 v4 被识别为需重建，v5 被识别为当前版本。
6. 直接工作流：使用当前真实 `trend_api_stats` 重建三市场投影，核对 HK 纪律模拟示例为 `1 胜 / 6 闭环 = 16.67%`，实际执行无闭环时显示数据不足。
7. 最终 Dashboard gate：仅在所有修改完成后运行 `make acceptance`。只有 `PASS` 才进入交付；随后部署完全相同的已接受 SHA，并核验新 PID、工作目录、Git SHA、新日志和 review URL HTTP 200。

合并前按项目要求更新并提交当日 `CHANGELOG.md` 条目。

## 验收标准

- CN、HK、US 的纪律模拟和实际执行各自显示自己的完整交易胜率状态。
- 正收益、持平、排除、未闭环和零样本口径符合本设计。
- 当前 HK 数据能显示 `16.67% · 1 胜 / 6 闭环`，而不是由页面硬编码。
- 实际执行 0 个合格闭环时显示数据不足，不显示 `0%`。
- 市场基准区没有胜率或“不适用”噪声，现有五项指标与布局不变。
- 聚焦测试、直接真实数据工作流和最终 `make acceptance` 均通过。
