# 趋势复盘纪律去重与 ETF 候选池展示设计

## 目标

1. 港股、美股和 A 股复盘页不再重复展示“当前策略参数”；当前纪律只在趋势报告页的折叠“纪律”区域展示。
2. 趋势报告页的当前纪律使用 Dashboard 启动配置中的当前候选池，而不是所选历史报告冻结的候选池。
3. 历史报告、历史审计参数和历史候选结果保持只读，不重写、不补算。

本次是 Dashboard 展示与配置投影修复，不改变策略、候选过滤、ETF 池解析、纪律版本或 Kelly 样本身份。

## 已确认的根因

Dashboard 当前从报告的 `strategy_snapshot.parameters.candidate_pool_ids` 生成
`current_strategy_parameter_rows`。现有 US/HK 报告生成于 ETF 池接入之前，冻结值分别只有
`622460` 和 `622494`；因此即使当前配置已经包含 US ETF 池 `705013` 和 HK ETF 根池
`707617`，页面仍显示旧的正股池。

复盘页的“当前策略参数”和趋势报告页的“纪律”来自两个独立渲染入口，但表达同一组规则，
因此形成重复。

## 方案选择

采用配置单一来源方案：

- 删除复盘页“当前策略参数”区块及其专用样式。
- Dashboard 配置接收 CN、US、HK 当前候选池 ID。
- CLI 继续使用现有环境配置键解析固定池，不在 Dashboard 代码中复制 ID 常量。
- 投影当前纪律时使用对应市场的当前配置；冻结纪律仍从报告原文读取。

不采用以下方案：

- 在 Dashboard 中再次硬编码池 ID：会形成第二份易漂移配置。
- 重新生成报告来覆盖症状：不能保证历史报告打开时仍显示正确的当前纪律。
- 把重复参数表改成另一个折叠区：仍保留两个相同的纪律入口。

## 数据流

```text
daily_premarket.env
  -> dashboard CLI 现有配置解析
  -> DashboardConfig 的 CN/US/HK 当前候选池
  -> load_dashboard_state
  -> 当前市场 live_trend_strategy_snapshot
  -> current_strategy_parameter_rows
  -> 趋势报告页折叠“纪律”

历史报告 strategy_snapshot
  -> strategy_parameter_rows
  -> 历史审计与当前配置不可用时的只读回退
```

CN 当前池由 A 股池和 ETF 池组合；US/HK 使用各自的池列表。HK 的 `707617` 仍只作为稳定根
池，实际温转热子池继续由现有报告生成流程动态解析。

## 缺失与错误处理

- 当前市场候选池配置完整时，当前纪律必须使用该配置，即使所选报告较旧。
- 当前候选池配置缺失时，不得把历史池冒充当前池；页面回退为报告冻结纪律，并保留
  “当前纪律不可用”的现有说明。
- 配置解析继续复用现有正整数和去重校验。
- 当前配置不修改历史报告 JSON、历史策略参数或历史审计数据。

## 界面

复盘页保留标题、策略身份、样本数、共同截止日和两组绩效比较，删除整块
“当前策略参数”。趋势报告页现有折叠“纪律”保持位置、结构和可访问性不变。

## 验证

最小回归覆盖：

1. 复盘渲染不包含“当前策略参数”或参数表。
2. 旧 US/HK 报告只冻结正股池时，显式传入当前配置后，当前纪律分别显示
   `622460,705013` 和 `622494,707617`。
3. CN 当前纪律继续显示已接入 ETF。
4. 未提供当前池配置时，纪律回退为报告冻结值，不声称是当前版本。
5. 聚焦 Python/Node 测试、真实 Dashboard API 与浏览器桌面/移动流程通过。
6. 最后运行 `make acceptance`；仅 `PASS` 后重部署同一已验收 Git SHA，并验证 PID、
   工作目录、Git SHA、新日志和 review URL 的 HTTP 200。
