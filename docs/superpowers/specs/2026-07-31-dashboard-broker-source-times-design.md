# Dashboard 券商数据时间设计

**日期：** 2026-07-31  
**状态：** 已确认  
**范围：** Dashboard 顶部账户数据来源面板

## 目标

删除账户数据来源面板中重复且无法帮助判断单一券商数据新鲜度的全局信息，
改为按来源类型分组，并在每个券商行直接显示该券商自己的数据时间。

## 已确认布局

采用方案 C，保留现有暖色面板、状态行、语义色、圆角、边框和字号：

```text
实时账户
  富途账户          同步正常 · 13:48
  老虎账户          同步正常 · 13:48

券商结单
  辉立账户          数据截至 · 07-29
  东方财富账户      数据截至 · 07-30
```

删除以下内容：

- 行情提示，例如`部分标的当前时段无报价`
- 顶部`同步正常 / 同步异常`
- 顶部`控制器心跳`
- 来源列表中的`控制器`行
- 底部全局`刷新于`

## 数据与展示规则

Dashboard 继续只读取既有文件投影，不新增 API 字段，也不改变同步、发布或行情
刷新流程。

券商分组沿用现有固定来源边界：

- `富途`、`老虎`属于`实时账户`
- `辉立`、`东方财富`属于`券商结单`

每行继续读取 `account_sync.brokers[broker]` 的 `status`、`data_as_of`、
`last_success_at` 和 `display`：

- 实时账户正常时把 `data_as_of` 格式化为`同步正常 · HH:MM`
- 券商结单正常时把 `data_as_of` 格式化为`数据截至 · MM-DD`
- 实时账户失败时把 `data_as_of` 格式化为`同步失败 · 上次 HH:MM`
- 过期时把 `data_as_of` 格式化为`数据已过期 · 截至 <时间>`
- 实时账户缺少 `data_as_of` 时才用 `last_success_at` 作为时间回退
- 券商结单不使用导入时间代替结单数据日期
- 没有可信时间时只显示状态，不伪造时间
- 未知时显示`同步状态未知 · 数据未验证`

时间格式只负责展示；原始时间、时区和状态判定保持不变。

## 组件边界

改动限于现有 Dashboard 静态页面：

- HTML 移除三个全局状态占位
- JavaScript 删除对应全局渲染，给券商行补上时间并插入两个分组标题
- CSS 复用现有 token，只补充分组标题与窄屏排列
- 测试更新现有渲染和浏览器断言

不改账户同步控制器、账户状态投影、行情轮询、持仓数据、交易动作或后台服务。
行情仍正常刷新并用于持仓价格，只是不再在此面板展示全局行情文案。

## 响应式与可访问性

- 桌面和手机使用同一份 DOM，不复制组件
- 375px 宽度下券商名和状态时间保持同一行；状态文字必要时可换行
- 页面不得产生横向滚动
- 正常、失败、过期和未知均保留文字说明，不能只依赖红绿颜色
- 面板为只读状态，不增加按钮、悬停交互或动画

## 异常处理

异常只影响对应券商行，不再生成全局横幅。单一券商失败时，其他券商的时间和
状态保持可见；缺失或无法解析的时间退化为已有状态文字。

## 验证

实现阶段应完成：

1. 聚焦前端测试，覆盖实时时间、结单日期、失败、过期、未知和缺失时间。
2. Dashboard 浏览器检查，确认被删除文案不再出现，两个分组及四个券商时间正确。
3. 375px 手机与桌面画幅检查，无横向滚动且状态不依赖颜色。
4. 最终执行 `make acceptance`；只有 `PASS` 才进入部署。
5. 部署接受通过的精确 Git SHA，验证 PID、工作目录、SHA、新日志和 HTTP 200。
6. 从实时评审 URL 截取受影响区域的桌面和手机截图后交付。

## 未采用方案

- 不采用无分组的`状态 + 时间`，因为用户选择按来源区分实时账户和券商结单。
- 不采用只显示时间的方案，因为异常状态会变成隐含信息。
- 不新增设计系统、时间组件、依赖或后端字段。
