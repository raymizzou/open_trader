# A 股、美股、港股趋势纪律统一设计

## 目标

让 A 股、美股和港股共用同一套趋势入场与退出纪律，只保留交易市场本身要求的差异。A 股继续使用现行 v7；美股和港股升级为 v5。

统一后，三个市场的新开仓候选必须同时满足：

- 个股趋势温度从“温”转为“热”或“沸”；
- 趋势强度不低于 95；
- 行业温度为“温”“热”或“沸”；
- 趋势节气为“谷雨”“立夏”或“夏至”；
- 总市值不低于人民币 100 亿元；
- 单日成交额不低于人民币 2 亿元；
- 明确位于趋势右侧、可交易、无危险信号；
- 数据日期与纪律批次一致、不是当前持仓；
- 右侧天数存在、ATR14 可计算。

不设置静态股价上限。候选继续按趋势强度降序、右侧天数升序、成交额降序、股票代码升序排序，展示前 10，并按剩余持仓席位产生买入动作。

## 方案

在现有趋势报告流程中提取并复用最小的共同候选判定，原始行情事实仍保留市场本币口径。只有市值和成交额门槛比较时，使用策略快照中冻结的汇率换算为人民币。

不把原始数据整体改写为人民币，以免污染来源证据和历史报告；也不复制三套相同过滤逻辑，以免规则再次漂移。市场特有逻辑仍留在现有市场分支，包括候选池、证券范围、交易时段、交易单位、账户和报价来源。

## 统一纪律

### 入场

三个市场共用以下参数：

```text
temperature_transition = 温 -> 热或沸
min_strength = 95
allowed_industry_temperatures = 温、热、沸
allowed_phases = 谷雨、立夏、夏至
min_market_cap_cny_100m = 100
min_amount_cny_100m = 2
requires_right_side = true
requires_tradable = true
requires_no_danger = true
requires_matching_data_date = true
requires_not_held = true
requires_right_side_days = true
requires_atr14 = true
```

静态筛选价不参与判断；`priceIndex` 可以作为来源事实保留，但缺失或高于 200 都不构成排除原因。

ATR14 继续用于初始保护线、单笔计划止损风险和买入数量计算，因此仍是新开仓的必要数据。

### 退出

三个市场共用现行 A 股退出条件：

- 危险信号；
- 离开趋势右侧；
- 个股温度转为“平”；
- 触发保护线。

任一条件成立均产生 `SELL_ALL`。现有过热止盈、移动保护线和强制清仓优先级保持不变。

### 市场特有规则

仅保留以下差异：

- A 股：现有 A 股及 ETF 个股候选池，沪深证券范围与 ST、`*ST`、退市标记排除，100 股整手，现有 A 股买入窗口；
- 美股：现有美股候选池，美元账户和报价，1 股交易单位，美股常规交易时段；
- 港股：现有港股候选池，港币账户和报价，Futu 返回的逐标的整手，现有港股买入窗口。

现有持仓上限、Kelly 仓位、单笔与组合风险预算、异常损失缓冲、保护线及实际账户只提示不自动交易等系统约束不变。

## 本币数据与冻结汇率

趋势动物的 `marketCap` 和 `amount1d` 继续按标的市场本币的“一亿元”单位保存和展示：

- A 股：人民币；
- 美股：美元；
- 港股：港币。

策略比较值按以下冻结汇率换算：

```text
CN: 1 CNY = 1 CNY
US: 1 USD = 7.85 / 1.08 = 7.268518518518... CNY
HK: 1 HKD = 1 / 1.08 = 0.925925925925... CNY
```

汇率以精确十进制字符串随策略 v5 快照冻结，不读取每日汇率，不随市场变化，也不增加偏离监控或提醒。候选审计同时记录：

- 原始本币值与币种；
- 冻结汇率；
- 换算后人民币值；
- 与人民币门槛的比较结果。

历史报告继续使用各自冻结的策略快照解释，不重算、不改写。

## 行业温度数据

美股和港股复用 A 股现有的两阶段趋势动物请求：

1. 获取候选及持仓的个股快照和 `industryTmId`；
2. 对唯一行业 ID 请求行业快照，并按 `industryTmId` 回填行业温度。

行业请求使用与个股批次相同的预期数据日期，并把查询、响应、缓存和费用证据冻结到报告证据中。

单个行业行缺失时，只排除引用该行业的候选，原因为行业温度不可用。若行业快照请求整体失败：

- 当前持仓的持有、减仓和清仓判断继续生成；
- 所有新开仓统一暂停；
- 报告明确记录行业数据不可用及暂停原因；
- 不用空行业数据伪装成正常的零候选，也不因入场数据失败阻断退出。

## 策略版本与生效边界

策略版本和生效日期为：

| 市场 | 版本 | 生效日期 |
| --- | --- | --- |
| A 股 | v7 | 2026-07-24，保持不变 |
| 美股 | v5 | 2026-07-24 |
| 港股 | v5 | 2026-07-27 |

报告按执行日期选择策略。早于对应生效日期的历史重跑仍使用 v4，避免把新纪律套到旧执行窗口。冻结历史报告保持不可变。

## Kelly、回撤与已有持仓

三个市场的样本始终隔离。

- A 股 v7 保持已经批准的一次性规则：只接受 A 股 v4 和 v7 开仓的合格闭环样本；A 股 v1、v5、v6 及其他市场均不计入。
- 美股 v5 和港股 v5 只接受同市场、由 v5 开仓的闭环样本；不继承 v4，初始样本数为 0，并建立各自新的回撤基准。
- 样本归属由开仓策略身份决定，不复制、不改名。

美股现有由 v4 开仓的持仓在 v5 生效后立即按 v5 退出纪律管理，包括新增的“温度转平”清仓；将来平仓后仍归入美股 v4 样本，不计入 v5。港股采用相同归属原则。

部署后，模拟账户继续走现有自动执行机制，因此新报告中的 v5 买卖动作可以在正常执行窗口直接执行；真实账户仍维持现有人工执行约束。

## 当前策略复盘展示

Dashboard 当前复盘页展示该市场当前生效的策略快照和兼容样本，而不是固定筛选 v1/v3：

- A 股显示 v7，并按批准关系汇总 v4 + v7；
- 美股显示 v5，只显示美股 v5 样本；
- 港股显示 v5，只显示港股 v5 样本。

美股和港股 v5 初始显示 `0 / 30` 是正常冷启动。旧事实继续保留并可用于历史审计，但本次不增加历史版本切换界面。

## 实施范围

最小实现包括：

1. 让实时策略快照支持 US/HK v5，并按执行日期选取 v4 或 v5。
2. 让三个市场复用统一候选门槛和温度转平退出判断。
3. 给 US/HK 报告增加行业快照获取、证据冻结和故障降级。
4. 在 US/HK v5 比较市值和成交额时使用快照冻结汇率，并完善审计字段与参数表。
5. 让 Kelly、回撤和复盘投影按上述版本身份工作，保留 A 股 v4 + v7 特例。

不新增配置入口、每日汇率服务、汇率监控、影子报告、历史版本 UI 或新的通用框架。

## 验证

自动化测试覆盖：

- 三个市场全部共同门槛的通过、边界、缺失和排除原因；
- 无静态股价上限，ATR14 和右侧天数仍为必要条件；
- 美元、港币冻结汇率换算及门槛边界；
- 行业请求去重、日期、缓存、证据冻结、单行缺失和整体失败降级；
- 温度转平在三个市场均清仓；
- 生效日期前使用 v4、生效日起使用 v5/v7；
- A 股 v4 + v7 特例不变，US/HK v5 冷启动且不接收 v4 样本；
- v4 开仓持仓按 v5 退出但平仓样本仍归 v4；
- 当前复盘页显示当前版本和正确样本数，旧冻结报告仍可加载。

开发期间运行聚焦测试和可用市场的真实报告流程，并检查报告、证据、动作、后台进程和新日志。Dashboard 最终只运行一次 `make acceptance`；只有结果为 `PASS`，才提交变更日志、部署被接受的同一 Git SHA，重启相关控制器，并核对新 PID、工作目录、Git SHA、新日志和复核 URL 的 HTTP 200。

## 已知基线

独立 worktree 的实施前全量测试结果为 `3366 passed, 6 failed`。6 个失败均因测试直接读取主工作目录中未被 Git 跟踪的 `data/trend_review/daily/{CN,HK,US}/2026-07-16.json`，而该数据不会自动出现在新 worktree；它不是本设计引入的行为回归。实施验证必须解决或显式提供这些既有测试数据后再执行最终验收。
