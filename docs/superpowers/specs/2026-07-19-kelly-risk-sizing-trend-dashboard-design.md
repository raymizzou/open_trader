# 趋势策略 Kelly 仓位风控与实盘纪律对比

## Problem Statement

当前趋势报告已经能够给出确定性的买入、卖出和持有建议，但仓位仍主要由固定名义比例决定，
没有把保护线距离、组合同时止损风险、样本质量和交易单位统一成一套可审计的仓位算法。
用户希望用纪律模拟盘替代情绪判断：每天的策略建议只由模拟盘、市场数据和策略版本决定，
真实账户中的少买、多买、漏卖或其他人为干预不能改变后续建议。

系统还缺少模拟盘与真实账户的胜率、盈亏比和样本数对比。模拟盘已有可关联订单，老虎实盘
可以通过 API 获取成交；东方财富与辉立则需要在上传结单后解析成交。目前只看持仓快照无法
可靠还原完整闭环交易，因此不能用推测值冒充实盘盈亏比。

用户需要的不是新仪表盘，而是在当前持仓 UI 的现有趋势报告中加入少量、决策优先的信息：
今天建议买多少、计划风险是多少、Kelly 是否压低仓位、实盘偏离了什么，以及模拟与实盘的
盈亏比差异。

## Solution

为 A 股、港股、美股分别建立以富途纪律模拟盘为唯一策略基准的仓位风控流程。报告在开市前
根据模拟盘事实生成并冻结；系统开市后按冻结动作和数量执行模拟盘，不盘中重算报告。真实账户
沿用相同的方向、目标仓位比例和保护纪律，只提供按真实净值换算的参考数量，用户自行调整。
真实账户的持仓、现金、成交和人为偏差只进入独立的审计与对比统计，不影响报告、模拟盘或
Kelly 参数。

固定风险底盘为：热档名义仓位上限 4%、沸档 2%，港美股现有名义上限 4%；单笔计划止损风险
上限为账户净值 0.40%，组合正常计划风险上限为 4%，另保留 1% 异常损失缓冲。5% 是风险预算
目标，不是最大损失保证；价格跳空、滑点、停牌和未按纪律退出仍可能使实际损失更大。

Kelly 只使用同市场、同策略版本的模拟盘完整闭环交易。少于 30 笔时禁用；30–199 笔使用
当前版本的全部合格样本；达到 200 笔后使用最近 200 笔。采用四分之一 Kelly 作为未来新仓的
名义仓位上限。Kelly 可以随样本改善向上恢复，但永远不能突破固定仓位和风险底盘；Kelly 为
0 时暂停新开仓，等待人工复盘。

在现有趋势报告风险摘要中展示模拟策略风险、Kelly 阶段、策略回撤、模拟/实盘胜率、盈亏比
和样本数。真实账户状态作为实时覆盖层展示，不回写冻结报告。东财或辉立结单上传成功后，
系统从已导入成交明细重建实盘统计；重复上传不得重复累计，更正版结单必须替换旧期间并重新
计算。

## User Stories

1. As a 趋势策略用户, I want 每日建议只以纪律模拟盘为准, so that 实盘人为操作不会造成策略版本分叉。
2. As a 趋势策略用户, I want 开市前报告生成后保持不可变, so that 我能够审计系统当天究竟建议了什么。
3. As a 趋势策略用户, I want 模拟盘按冻结报告自动执行, so that 下单过程不会被盘中情绪干扰。
4. As a 趋势策略用户, I want 实盘仍看到同一方向和目标仓位比例, so that 我能自行决定实际执行数量。
5. As a 趋势策略用户, I want 实盘参考数量只作为净值换算, so that 它不会被误解为策略重新计算。
6. As a 风险管理者, I want 每笔新仓的计划止损风险不超过净值 0.40%, so that 单笔失败不会占用过多风险预算。
7. As a 风险管理者, I want 模拟组合的正常计划风险不超过净值 4%, so that 多个持仓同时触发保护线时仍有明确预算。
8. As a 风险管理者, I want 额外保留 1% 异常损失缓冲且禁止用于开仓, so that 正常仓位不会主动吃掉跳空和滑点余量。
9. As a 趋势策略用户, I want 页面明确说明 5% 不是最大损失保证, so that 我不会把风险预算误认为成交承诺。
10. As a 趋势策略用户, I want 热档继续以 4%、沸档以 2%作为名义仓位上限, so that 新算法不改变已有温度纪律。
11. As a 趋势策略用户, I want A 股按 100 股、港股按实际每手、美股按 1 股向下取整, so that 建议可以实际下单。
12. As a 趋势策略用户, I want 最小交易单位超出风险上限时跳过, so that 系统不会借用异常缓冲或硬凑最低数量。
13. As a 趋势策略用户, I want 报告中的卖出计划在生成仓位时被视为会执行, so that 开市前能够形成完整、冻结的执行建议。
14. As a 趋势策略用户, I want 卖出订单提交失败时停止当天后续模拟买入, so that 系统不会在明显执行故障时继续扩大风险。
15. As a 趋势策略用户, I want 卖出提交成功后继续执行冻结买入而不等待盘中重算, so that 执行逻辑保持简单、确定。
16. As a 趋势策略用户, I want 新仓成交后以成交均价减 2ATR 建立活动保护线, so that 实际止损监控使用成交事实而不修改原报告。
17. As a 趋势策略用户, I want 模拟盘关键风险数据不完整时暂停新开仓, so that 未知风险不会被当成零。
18. As a 趋势策略用户, I want Kelly 少于 30 个合格样本时不参与仓位, so that 小样本不会产生伪精确调整。
19. As a 趋势策略用户, I want Kelly 在 30–199 笔使用全部当前版本样本, so that 前期估计尽可能利用已有数据。
20. As a 趋势策略用户, I want Kelly 达到 200 笔后滚动使用最近 200 笔, so that 久远环境不会长期压住当前结果。
21. As a 趋势策略用户, I want Kelly 每完成一笔模拟闭环交易才更新, so that 未实现盈亏不会造成仓位抖动。
22. As a 趋势策略用户, I want Kelly 只能压低固定仓位但允许恢复, so that 仓位不会永久单调缩小也不会突破纪律底盘。
23. As a 趋势策略用户, I want Kelly 为 0 时暂停新开仓, so that 没有正净收益证据时系统不继续冒险采样。
24. As a 趋势策略用户, I want A 股、港股和美股分别维护样本池, so that 不同市场结构和成本不会互相污染。
25. As a 趋势策略用户, I want 影响交易结果的规则变化开启新策略版本, so that 新旧规则的样本不会混用。
26. As a 趋势策略用户, I want UI 文案和纯展示修复不重置样本, so that 无关改动不会触发冷启动。
27. As a 风险管理者, I want 模拟策略净值从高点回撤 5%时暂停该市场新开仓, so that 连续亏损受到独立于 Kelly 的控制。
28. As a 风险管理者, I want 回撤暂停只能人工解锁, so that 风险纪律不会自动失效。
29. As a 风险管理者, I want 同版本解锁保留 Kelly 样本并重置回撤基准, so that 系统能够恢复且留下审计记录。
30. As a 趋势策略用户, I want 同时看到模拟与实盘的胜率、盈亏比和闭环样本数, so that 我能比较纪律执行与人为执行的结果。
31. As a 趋势策略用户, I want 盈亏比定义为平均净盈利率除以平均净亏损率绝对值, so that 指标与 Kelly 使用的赔率一致。
32. As a 趋势策略用户, I want 实盘统计不进入 Kelly, so that 实盘执行偏差不会改变策略优势估计。
33. As a 趋势策略用户, I want 富途模拟成交与老虎实盘成交通过 API 自动累计, so that 可用数据无需手工录入。
34. As a 趋势策略用户, I want 东财和辉立在上传结单后更新实盘统计, so that 无 API 账户也能进行长期对比。
35. As a 趋势策略用户, I want 结单重复上传不会重复累计, so that 实盘指标保持可信。
36. As a 趋势策略用户, I want 更正版结单替换原期间并触发重算, so that 历史修正能够正确反映在统计中。
37. As a 趋势策略用户, I want 结单解析失败时保留上次有效统计和截止日, so that 页面不会因为一次失败显示错误的零值。
38. As a 趋势策略用户, I want 实盘分批买卖按从首次策略买入到持仓归零的回合统计, so that 部分成交不会被拆成虚假的多笔胜负。
39. As a 趋势策略用户, I want 跨版本持仓归入开仓版本, so that 旧规则结果不会污染新版本样本。
40. As a 趋势策略用户, I want 归因不明确或混入策略外交易的实盘回合排除并标明原因, so that 对比指标不伪造精度。
41. As a 趋势策略用户, I want 实盘纪律风险按策略保护线与真实数量估算, so that 我能看到若按纪律退出时的预计损失。
42. As a 趋势策略用户, I want 策略外实盘持仓显示为风险未纳入估算, so that 它们不会影响模拟建议也不会被错误套用止损。
43. As a Dashboard 用户, I want 所有新增内容沿用当前趋势报告布局, so that 页面仍然像现有持仓 UI 而不是新系统。
44. As a 移动端用户, I want 375px 下风险说明放在候选卡第二行且无新增横向滚动, so that 手机上仍能快速做决定。

## Implementation Decisions

### Canonical strategy state

- A 股、港股、美股各自使用对应的富途模拟账户作为唯一纪律持仓状态。
- 每日方向、排序、目标仓位、冻结数量、Kelly 和策略回撤只读取模拟盘、市场数据和当前策略版本。
- 东方财富、老虎和辉立的持仓、现金、成交及人为操作不进入报告生成或 Kelly。
- 真实账户页面复用模拟策略建议；目标仓位比例完全一致。实盘参考数量只按真实账户净值和冻结参考价换算，并明确标为执行辅助。
- 实盘少买、跳过、追买、超买、漏卖或策略外持仓只形成执行偏差，不改变后续报告。

### Frozen report and execution

- 报告在开市前一次性生成，生成后不可局部改写或盘中重算。
- 仓位规划使用模拟盘的计划后状态：报告内所有 `SELL_ALL` 被视为将释放对应现金、席位和计划风险，然后按确定性候选顺序分配新仓。
- 模拟执行器先提交卖出，再提交报告中冻结的买入数量。
- 任一应执行卖出在订单提交阶段失败时，停止当天尚未提交的模拟买入；若卖出提交成功，不等待成交回执重算买入。
- 开盘价格偏离不导致撤单、缩量或重算。系统按冻结数量执行，触发保护纪律时退出。
- 冻结报告保留预计保护线；模拟成交后独立记录活动保护线 `成交均价 - 2ATR`。活动保护线是成交事实，不回写报告。

### Fixed risk floor

- 无杠杆，每个市场模拟账户最多 10 个持仓席位。
- A 股热档名义仓位上限为净值 4%，沸档为 2%；港股和美股沿用当前 4%名义上限。
- 单笔正常计划止损风险上限固定为净值 0.40%，空余席位不提高其他单笔额度。
- 组合正常计划风险上限为净值 4%。
- 额外 1% 是异常损失缓冲，只用于解释跳空、滑点和额外费用；不得用于开仓、不得计入组合剩余风险。
- “5%”只能描述风险预算目标，不能描述为保证、最大损失或券商端止损承诺。
- 新仓数量取名义上限、单笔风险承载、组合剩余风险承载、Kelly 上限、现金和剩余席位共同约束后的最小值，再按市场单位向下取整。
- A 股交易单位为 100 股，港股为标的实际每手，美股为 1 股。
- 最小交易单位超限时跳过；不借用异常缓冲、不跨日保留额度、不把空余席位风险转给其他单笔。
- 模拟持仓缺少数量、净值、价格、汇率或可信活动保护线时，当天不生成新买入数量；沿用现有人工复核状态，不新增恢复页面。

### Kelly samples and stages

- 样本池键为市场、策略 ID 和开仓策略版本。A 股、港股、美股完全隔离。
- 只有模拟盘从首次买入到最终归零的完整纪律回合进入 Kelly。未成交、跳过、仍持仓、成本不完整或归因不明的记录只审计，不增加样本数。
- 每笔样本收益率为扣除模拟成本后的净损益除以入场名义金额。
- 少于 30 笔时显示 `冷启动 n / 30`，Kelly 不参与仓位计算。
- 30–199 笔使用当前版本全部合格样本；至少 200 笔后只使用最近 200 笔。
- 每完成一个合格回合更新一次。持仓中的未实现收益不触发更新。
- 在 `0 ≤ f ≤ 1` 上最大化样本平均 `log(1 + fR)` 得到全 Kelly，再乘 0.25 得到保守名义仓位上限。
- Kelly 是固定底盘之下的上限：可以降低、否决或随着样本改善恢复，但永远不能提高热/沸名义上限、0.40%单笔风险或 4%组合风险。
- 如果所有正仓位的经验对数增长都不为正，则 Kelly 为 0并暂停该市场新开仓。恢复需要人工复盘；规则改变时开启新版本冷启动，规则未变时可明确解锁同版本。
- 入场、退出、止损、仓位上限或模拟成本模型变化都开启新策略版本。UI 文案、布局或纯展示修复不改变版本。
- 实盘手续费、滑点和盈亏不自动更新模拟成本模型。只有用户明确批准的成本模型变化才能进入新版本。

### Strategy drawdown gate

- 每个市场、每个策略版本维护独立的模拟策略净值高点。
- 从高点回撤达到 5%时，暂停该市场的新开仓；已有保护和卖出纪律继续执行。
- 回撤暂停不自动解除。用户确认继续同一版本时保留 Kelly 样本，把当前模拟策略净值设为新的回撤基准，并记录审计事件。
- 如果复盘后改变影响交易结果的规则，则建立新版本、重置回撤基准并进入 Kelly 冷启动。
- 同时在险 4%+异常缓冲 1%与累计回撤 5%是两个不同概念，UI 必须分别命名。

### Performance comparison

- 盈亏比统一定义为盈利回合平均净收益率除以亏损回合平均净收益率绝对值；同时展示胜率和闭环样本数。
- 模拟统计只使用纪律模拟闭环回合，并作为 Kelly 输入。
- 实盘统计只用于对比，不进入 Kelly、报告、仓位或模拟成本模型。
- 实盘一个样本是同一市场、标的、策略和开仓版本下，从首次可归因买入到关联持仓归零的完整回合。期间分批买入、部分卖出及费用聚合成一笔。
- 跨版本持仓归入开仓版本。新版本没有实盘闭环样本时显示暂无样本，不沿用旧版本数字。
- 策略外交易或无法把实际成交可靠关联到报告的回合标为归因不明确并排除。
- 富途模拟成交和老虎实盘成交通过 API 获取。东方财富和辉立通过现有结单上传入口获取实际成交。
- 结单导入按来源期间和来源身份幂等保存成交事实。重复上传不重复累计；更正版替换原期间并从全部有效明细重建统计，而不是在旧汇总数字上追加。
- 上传成功后立即刷新实盘胜率、盈亏比、样本数和统计截止日。解析失败保留上次有效统计并显示失败原因。

### Dashboard interaction

- 不新增页面、全局导航、顶部风险卡、图表或前端依赖。
- 只修改现有趋势报告：四个动作计数之后、卖出区域之前增加一条紧凑风险摘要，并复用现有买入表与候选明细子行。
- 风险摘要优先展示模拟纪律状态：组合正常风险、组合剩余风险、单笔风险上限、异常损失缓冲、Kelly 阶段、策略回撤状态。
- Kelly 区块增加两行对比：`模拟：胜率｜盈亏比｜样本数`与`实盘：胜率｜盈亏比｜样本数｜统计截至`。不新增独立统计卡。
- 真实账户持仓、纪律风险和执行偏差作为独立实时覆盖层更新，不回写冻结报告。
- 实盘纪律风险文案为“若按策略保护线退出，预计损失 X%”；不能声称真实最大风险或已挂券商止损。
- 策略外或归因不明确的实盘持仓显示数量和市值，并标注“风险未纳入估算”。
- 买入表的`目标仓位`改为`目标仓位（占净值）`，不增加新的横向列。风险允许、跳过原因、Kelly 限制和实盘偏差使用现有详情子行。
- 禁止使用`本次可用风险`；统一使用`组合剩余风险`，并解释其供所有后续新仓共享，不等于单标的仓位。
- 375px 移动端复用现有候选卡，把风险说明放在动作后的第二行；不得新增横向滚动，状态不能只依赖颜色。

### Data boundaries

- 仓位计算、Kelly 校准、模拟/实盘回合汇总均由后端产生不可变事实；Dashboard 只校验和投影，不在浏览器计算资金或统计。
- 报告事实必须保存生成时的模拟账户净值、现金、持仓、卖出假设、成本模型、汇率、候选排序、风险预算、Kelly 身份、最终数量和决定性约束。
- 模拟执行事实保存报告身份、策略版本、冻结动作和数量、订单提交结果、实际成交及活动保护线。
- 实盘审计事实与报告身份关联但单独存储，任何实际状态变化都不能更新报告摘要或 Kelly 校准。
- 干净 checkout 必须包含运行 Kelly 统计所需的受控策略模板，不能依赖仅存在于开发者本地且被忽略的数据文件。

## Testing Decisions

- 测试只断言外部行为和冻结产物，不绑定内部 helper 数量或前端实现细节。
- 复用现有趋势报告构建、模拟执行、Kelly 统计、结单导入、Dashboard 投影和移动端渲染测试入口；只在没有现有入口覆盖新事实时增加一个最高层的新测试缝。
- 先写失败测试，再写最小实现；每个独立行为变更都必须留下可运行检查。
- 仓位测试覆盖热 4%、沸 2%、港美 4%、单笔 0.40%、组合 4%、异常缓冲 1%、10 个席位和三个市场取整。
- 覆盖最小交易单位超限跳过、模拟关键数据缺失暂停、卖出释放假设、卖出提交失败停止后续买入，以及价格变化不重算冻结数量。
- 覆盖成交后活动保护线使用成交均价减 2ATR且原报告字节保持不变。
- Kelly 测试覆盖 29/30/199/200 边界、最近 200笔滚动、四分之一 Kelly、可降可恢复、零 Kelly暂停、市场/版本隔离和实盘数据不进入校准。
- 回撤测试覆盖到达 5%暂停、卖出纪律继续、同版本人工解锁保留样本并重置基准，以及规则改变时新版本冷启动。
- 统计测试覆盖平均盈亏比定义、分批成交聚合、部分卖出不提前闭环、跨版本归属、归因不明排除、API 重复订单和结单重复/更正版幂等重建。
- 结单上传测试必须确认上传成功后统计立即更新，解析失败保留旧值、错误和截止日。
- Dashboard 测试覆盖现有布局不变、禁止文案、风险定义、模拟/实盘对比、实时实盘覆盖层不改变冻结建议、颜色非唯一状态，以及 375px 无新增横向溢出。
- 直接工作流分别运行 A 股、港股和美股报告与模拟执行，核对冻结 SHA、最终数量、风险、Kelly 阶段、订单提交、活动保护线和统计更新。
- 本任务属于 Dashboard 行为变更。最终一次运行 `make acceptance`；只有 `PASS` 才能报告完成。随后重新部署完全相同的验收 Git SHA，并验证新 PID、工作目录、Git SHA、新日志和 Review URL HTTP 200。

## Out of Scope

- 不自动交易东方财富、老虎或辉立真实账户。
- 不让实盘持仓、盈亏、手续费或滑点影响模拟建议、Kelly 或策略版本。
- 不根据实盘现金、未卖持仓或风险状态把模拟建议数量改成零；只显示警告和执行偏差。
- 不因 Kelly 变化补仓、减仓或再平衡已有持仓。
- 不提高热 4%、沸 2%、港美 4%、单笔 0.40%或组合 4%的固定底盘。
- 不使用杠杆、保证金或强平模型。
- 不实现多市场联合 Kelly、相关性折扣或因子 Kelly。
- 不新增手工成交记账页面；实盘成交只来自可审计 API 或结单。
- 不从持仓快照猜测已实现盈亏，不对归因不明确的交易给出伪精确统计。
- 不增加新的 Dashboard 页面、全局风险仪表盘、图表或前端框架。

## Further Notes

- 当前报告执行窗口在开市后，报告本身在开市前生成。本设计有意选择“冻结建议 + 简单执行”，不引入卖出成交后重算工作流。
- 5%组合风险预算与 5%策略累计回撤暂停线数值相同但语义不同，代码、API 和 UI 必须使用不同字段和中文名称。
- Kelly 为 0是样本平均净收益不再为正的结果，不要求连续亏损。它可能在累计损失很小时发生，也不能替代独立回撤暂停线。
- 实盘盈亏比可能晚于模拟盘更新。东方财富和辉立未上传新结单时保留上次有效值并显示明确截止日期。
- 设计以最少新增 UI 和一个共享仓位计算边界为原则；不为将来可能的联合优化预建抽象。
