# 趋势策略 Kelly 仓位风控设计

## 状态

- 日期：2026-07-19
- 状态：已批准
- 范围：东方财富 A 股、老虎美股、辉立港股的趋势策略真实账户与富途纪律模拟账户
- 前置修复：干净 checkout 缺失的 `kelly_strategy_templates.json` 已作为受控夹具签入

## 目标

在不改变现有选股和退出纪律的前提下，为每个趋势账户增加可审计的仓位风控：

1. 普通情况下，全部持仓同时触发保护线的计划损失不超过账户净值 4%。
2. 额外保留账户净值 1% 作为跳空、异常滑点和额外费用缓冲，不用于开仓。
3. 每笔新仓的计划止损风险不超过账户净值 0.40%。
4. Kelly 在样本不足时不参与计算；样本达到门槛后只约束未来新仓，不调整已有持仓。
5. 真实账户与纪律模拟账户使用同一套算法，但分别使用各自的净值、持仓、现金和交易单位。
6. Dashboard 直接回答“可以买多少、为什么、为什么跳过”，不增加一套新仪表盘。

这里的 5% 是风险设计目标，不是成交结果保证。保护线无法消除跳空、流动性枯竭、
停牌或市价单滑点；系统保证的是普通计划风险不超过 4%，并预留 1% 异常损失缓冲，
不能宣称实际最大损失一定不超过 5%。

## 已选方案

采用“固定风险底盘 + Kelly 向下约束”的决策优先方案：

- A 股继续保留热 4%、沸 2%的名义仓位上限。
- 港股和美股继续保留当前策略快照中的 4% 名义仓位上限。
- 10 个持仓席位对应固定的单笔正常风险上限 0.40%；空余席位不提高其他交易额度。
- Kelly 不预测方向，也不放大固定底盘；只允许把未来新仓缩小或否决。
- 真实执行偏差不进入 Kelly 样本，避免把用户临时少买、跳过、追买或超买混入策略优势。
- 页面沿用现有账户、趋势报告和复盘标签，不增加全局入口、新页面或顶部风险仪表盘。

不采用以下方案：

- Kelly 直接替代热 4%/沸 2%并自动放大仓位：当前没有合格样本，参数误差会被放大。
- 每完成一笔真实交易就把真实收益直接并入 Kelly：会把执行纪律问题误当成策略表现。
- 按币种或策略列表简单相加 Kelly：当前没有可靠的联合分布，不能伪装成组合 Kelly。

## 风险术语

以下用词是 API、报告和 UI 的统一语义：

| 名称 | 含义 |
|---|---|
| 目标仓位 | 订单名义金额占该账户净值的比例。 |
| 计划止损风险 | 按执行参考价、活动保护线、数量、汇率及普通成本估计，触发保护线时损失的账户净值比例。 |
| 组合正常风险 | 当前全部持仓的计划止损风险之和。 |
| 组合正常风险上限 | 账户净值的 4.00%。 |
| 组合剩余风险 | `max(4.00% - 组合正常风险 - 当批已分配风险, 0)`，供所有后续新仓共享。 |
| 单笔风险上限 | 账户净值的 0.40%，不是名义仓位比例。 |
| 异常损失缓冲 | 账户净值的 1.00%，只覆盖异常损失，不计入组合剩余风险，不参与开仓。 |
| Kelly 仓位上限 | 使用纪律模拟样本得到、只作用于未来新仓的保守名义仓位上限。 |

禁止在 UI 或数据字段中使用“本次可用风险”描述组合剩余额度，因为它容易被误解为
单标的目标仓位。

## 账户与样本隔离

三个市场独立计算，不能混样本或共享风险预算：

| 市场 | 真实账户 | 纪律模拟账户 | Kelly 样本池 |
|---|---|---|---|
| A 股 | 东方财富 | 富途 A 股模拟账户 | A 股策略 ID + 策略版本 |
| 美股 | 老虎 | 富途美股模拟账户 | 美股策略 ID + 策略版本 |
| 港股 | 辉立 | 富途港股模拟账户 | 港股策略 ID + 策略版本 |

富途期权增强账户不进入本设计。各账户不使用杠杆。

同一市场的真实账户和模拟账户共享已批准的策略参数与 Kelly 校准结果，但风险计算
分别使用自己的账户事实。真实账户已有持仓必须进入真实账户的组合正常风险；模拟持仓
只进入模拟账户的组合正常风险。

策略 ID 或影响入场、退出、仓位的版本发生变化时，新版本建立新样本池并进入冷启动。
旧版本样本保留审计，但不能与新版本合并估参。

## 合格 Kelly 样本

Kelly 的主样本只来自纪律模拟的完整交易周期：

- 开仓发生在该策略版本生效后；
- 从首次买入到最终持仓归零；
- 属于正式纪律动作；
- 市场、策略 ID 和开仓版本明确；
- 实际成交额和普通交易成本可审计；
- 部分成交已按成交明细加权合并；
- 退出前没有无法解释的外部转入、补仓或手工改写。

漏单、仍未平仓、纪律外交易、无法归属策略的交易和成本不完整的交易不增加样本数，
但必须保存排除原因。

真实账户只用于两件事：

1. 校准按市场版本化的佣金、税费和普通滑点假设；只使用成本事实，不使用真实交易胜负
   改写策略优势。
2. 衡量执行纪律。少买或跳过是保守执行偏差；追买、超买、报告外加仓或突破风险上限是
   风险违规。

真实执行偏差和真实收益都不得进入纪律模拟 Kelly 样本。

## Kelly 阶段

### 冷启动：少于 30 笔

- Kelly 状态显示 `冷启动 n / 30`。
- Kelly 不参与订单金额计算，不显示伪精确的 0% 建议。
- 新仓继续使用固定名义仓位、0.40% 单笔风险和 4% 组合风险规则。
- 当前三个市场从各自合格样本数开始，不用历史实际持仓倒灌。

### 校准：30–199 笔

每完成一笔合格纪律交易，使用最新同市场、同版本样本重新计算。每笔样本保存扣除普通
成本后的名义收益率：

```text
R_i = 净损益 / 入场名义金额
```

在无杠杆可行域 `0 ≤ f ≤ 1` 上求经验增长最优名义仓位：

```text
f_full = argmax mean(log(1 + f × R_i))
f_conservative = 0.25 × f_full
```

订单使用 `f_conservative` 作为 Kelly 名义仓位上限。它只能使最终仓位低于固定规则或把
交易变为跳过，不能让仓位超过固定名义上限、0.40% 单笔风险或 4% 组合风险。

重新计算只影响此后的新仓，不补仓、不减仓，也不重平衡已有持仓。最新 Kelly 上限可以
随新增样本变化，但最终单笔风险始终不超过 0.40%。

### 评审：至少 200 笔

- 继续显示当前保守 Kelly 对未来新仓的向下约束。
- 系统可以生成下一策略版本的仓位建议和样本外验证报告。
- 不自动提高 0.40% 单笔风险、4% 组合风险或热/沸名义上限。
- 任何底盘上调都必须创建新策略版本并由用户批准。

### 失效处理

- 冷启动阶段数据无效：Kelly 保持未启用，继续固定风险规则并显示原因。
- Kelly 曾经启用后，校准产物缺失、过期或无效：不得自动回退到更大的固定仓位；冻结
  最后一个有效的较低上限，无法证明其版本身份时暂停新开仓。
- 经验增长在所有正仓位上不为正：Kelly 上限为 0，新仓跳过。

## 新仓计算

对每个账户按报告的确定性候选排序依次计算。后一个候选只能使用前面候选分配后剩余的
现金、席位和组合风险。

### 基础量

对多头候选：

```text
保护线距离 = (执行参考价 - 预计保护线) / 执行参考价
单笔风险名义上限 = 0.40% / 保护线距离
组合剩余风险名义上限 = 组合剩余风险 / 保护线距离
```

上式先给出不含成本的名义上限，最终数量必须按下式复核：

```text
新仓计划止损金额 = 数量 × (执行参考价 - 预计保护线) × 冻结汇率
                 + 预计入场普通成本 + 预计止损退出普通成本
新仓计划止损风险 = 新仓计划止损金额 / 账户净值
```

普通成本来自冻结的市场成本模型。汇率使用报告生成时冻结的账户基准货币换算率。保护线
距离小于或等于 0、价格/保护线/汇率不可用时不得开仓。

### 最终约束

候选名义仓位先取以下最小值：

```text
min(
  热/沸或市场名义仓位上限,
  单笔风险名义上限,
  Kelly 名义仓位上限（已启用时）,
  组合剩余风险可承载的名义仓位,
  可用现金可承载的名义仓位
)
```

再按市场交易单位向下取整：

- A 股：100 股；
- 港股：标的实际每手股数；
- 美股：1 股。

取整后重新计算目标仓位和计划止损风险。结果必须同时满足：

- 单笔计划止损风险不超过 0.40%；
- 当批分配后组合正常风险不超过 4.00%；
- 名义仓位不超过市场/温度上限和 Kelly 上限；
- 不超过现金和 10 个持仓席位。

若最小交易单位已经超过任一上限，数量为 0 并跳过。系统不得借用 1% 异常损失缓冲、
不得把未使用风险转给其他单笔、不得跨日保留名额；下一次正式信号重新完整判定。

### 已有持仓风险

已有多头持仓只计算从当前时点开始尚未发生的风险：

```text
已有持仓计划止损金额 = max(当前执行参考价 - 活动保护线, 0) × 数量 × 冻结汇率
                     + 预计止损退出普通成本
```

入场成本已经反映在当前账户净值中，不重复计入。保护线已经触发时仍由原卖出纪律生成卖出，
不能因为上式价格差按 0 处理而继续开新仓。

任何已有持仓缺少可信活动保护线、价格、数量或汇率时，账户组合风险状态为未知，暂停该
账户所有新开仓；不能把未知风险当作 0。已有持仓达到或超过 4% 组合正常风险时，新开仓
数量全部为 0，现有卖出纪律继续运行。

风险汇总覆盖该趋势账户中的全部正持仓，不只覆盖能归属当前报告的持仓。报告已经给出
`SELL_ALL`但尚未确认持仓归零的标的仍占用风险、现金和席位；系统不能提前假设卖出成功。

## 真实账户与纪律模拟执行

真实账户和模拟账户都调用同一个纯仓位计算入口：

- 输入：账户净值、现金、当前持仓及活动保护线、候选、市场交易单位、成本模型、Kelly
  校准和当批已分配风险；
- 输出：动作、最终数量、目标仓位、计划止损风险、决定性约束和跳过原因。

真实报告使用真实账户快照生成建议。纪律 watcher 在执行时使用模拟账户最新事实重新计算
数量，不能复制真实账户绝对股数。两次计算共享算法和策略参数，但结果可以因净值、持仓、
现金和交易单位不同而不同。

用户仍可手工少买或跳过真实建议；系统不自动替用户下真实订单。实际成交回写后记录：

- 建议数量与实际数量；
- 建议目标仓位与实际目标仓位；
- 建议计划风险与实际计划风险；
- 保守偏差或风险违规分类；
- 普通成本和滑点校准事实。

## 数据流与最小代码边界

不增加服务、数据库或前端框架。复用现有趋势报告、复盘、模拟执行和 Dashboard 投影：

1. `trend_review.py` 从不可变纪律事实生成同市场、同版本合格样本和 Kelly 校准状态。
2. 一个共享的纯仓位计算模块完成账户风险汇总、候选数量计算和取整后复核；A 股、港股、
   美股报告以及模拟 watcher 都调用它，不能各自复制公式。
3. 趋势报告产物冻结真实账户风险摘要和每个候选的仓位决定；模拟执行事实冻结模拟账户的
   同类决定。
4. `dashboard.py` 只校验和投影已有字段，不在请求时重新计算仓位或 Kelly。
5. `dashboard.js` 只渲染风险摘要、候选解释和复盘参数，不在浏览器计算金额。

仓位决定至少保存：

- 账户净值、基准货币和冻结汇率时间；
- 组合正常风险、组合剩余风险和异常损失缓冲；
- 固定名义上限、保护线距离、单笔风险上限和 Kelly 上限；
- 取整前名义仓位、最终数量、最终目标仓位和最终计划止损风险；
- 决定性约束；
- 最小交易单位风险；
- `allow` 或 `skip`及机器可读原因；
- 策略 ID、策略版本、Kelly 样本数、阶段和校准产物身份。

## Dashboard 设计

### 位置

只修改现有账户内两个位置：

1. `趋势报告`：四个动作计数之后、`优先处理 · 卖出触发`之前。
2. `A股/美股/港股复盘`：现有`当前策略参数`表中的仓位执行行。

不修改顶部总资产、账户卡、真实/模拟持仓表、全局导航或富途期权关注页面。

### 趋势报告风险摘要

摘要使用现有米白页面、边框、字号和间距，正式页面不显示“新增”或“修订”标签。固定文案：

- `仓位风控`：`以下百分比均指账户净值损失风险，目标仓位会单独标明`；
- `组合正常风险`：`已占用 / 上限`；
- `组合剩余风险`：`供所有后续新仓共享`；
- `单笔风险上限`：`按保护线估算；不是仓位比例`；
- `Kelly`：阶段、样本进度和是否启用；
- 单独一行：`异常损失缓冲 1.00%：仅覆盖跳空、滑点和费用，不计入组合剩余风险，也不参与开仓。`

禁止出现`本次可用风险`。

### 买入候选

沿用现有正式买入表，不新增横向列：

- `目标仓位`表头改为`目标仓位（占净值）`；
- 动作下显示文字状态`风险允许`、`超过风险上限`或具体跳过原因；
- 每个候选使用现有明细子行展示决定性计算。

允许示例文案：

```text
若触发保护线，预计账户损失 0.38% ≤ 单笔风险上限 0.40% ·
计算仓位 0.40% ÷ 14.2% = 2.82%，按 100 股取整后目标仓位 2.70% · Kelly 未启用
```

跳过示例文案：

```text
最小 100 股时，预计账户损失 0.63% > 单笔风险上限 0.40%，因此跳过 ·
不借用异常损失缓冲 · 下次信号重新判定
```

卖出表不增加 Kelly 字段，因为 Kelly 只约束新开仓。

### 复盘参数

在现有参数表中增加或修订以下行，不增加独立卡片：

- 组合正常风险上限；
- 组合剩余风险；
- 单笔风险上限；
- 异常损失缓冲；
- 最终目标仓位算法；
- Kelly 阶段和样本口径；
- 纪律模拟与实际执行的职责区别。

原有五项复盘指标保持不变。Kelly 状态可以作为参数状态文字显示，不能变成第六项绩效指标。

### 移动端

复用现有移动候选卡结构，把风险说明放在动作后的第二行。375px 视口不得新增横向滚动；
状态必须同时使用文字，不能只靠绿色或红色。常驻短说明必须可见，不把关键定义藏在 hover
tooltip 中。

## 错误处理

- 账户净值、现金或持仓快照缺失/无效：不生成新买入数量，显示明确原因。
- 已有持仓风险无法完整计算：组合风险未知，暂停该账户新开仓。
- 执行价、保护线、ATR、汇率或交易单位缺失：只跳过对应候选；系统性缺失使报告失败。
- 组合正常风险已达 4%：所有新候选跳过，不借用异常损失缓冲。
- 最小交易单位超过任一约束：跳过并保存最小单位的计划风险。
- Kelly 冷启动：使用固定风险规则，不显示 0% Kelly。
- Kelly 已启用后校准无效：冻结最后有效的较低上限；身份无法验证时暂停新开仓。
- 数值出现非有限值或 `1 + f × R_i ≤ 0`：校准无效，不输出 `NaN`、无穷大或负数量。
- 同一批候选顺序或账户事实改变：重新生成整份计划并冻结新报告修订，不局部改写旧决定。

## 非目标

- 不自动交易真实账户。
- 不因 Kelly 变化调整、补仓或再平衡已有持仓。
- 不提高热 4%、沸 2%、市场 4%、单笔 0.40%或组合 4%的固定底盘。
- 不使用杠杆、保证金或强平模型。
- 不实现多市场联合 Kelly、相关性打折或因子 Kelly。
- 不增加新的 Dashboard 页面、全局风险卡、图表或前端依赖。
- 不修改现有五项复盘绩效指标。

## 验证与验收

### 自动化验证

至少覆盖：

### Dashboard 最终门禁

本任务属于 Dashboard 行为变更。完成实现后：

1. 运行相关自动化测试并记录精确结果；
2. 运行真实报告、账户/行情刷新和一个模拟账户仓位计算工作流；
3. 检查并重启仍加载旧代码的 Dashboard、watcher、`screen` 或 `launchd`进程；
4. 核对新 PID、工作目录、Git SHA、时间戳和新日志；
5. 最后运行一次 `make acceptance`，只有 `PASS` 才能请求用户验收；
6. 重新部署完全相同的已验收 Git SHA，验证新 PID、工作目录、Git SHA、新日志和 Review
   URL HTTP 200，再向用户提供该 URL。
