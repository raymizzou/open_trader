# 结单上传来源权威设计

**日期：** 2026-07-30

## 目标

东方财富与辉立 PDF 结单以上传文件为来源事实。上传准入只验证文件可解析、账户数据有效，以及结单期间不早于该券商当前已接受期间；同期间重传允许覆盖。

下游实盘闭环统计是结单的派生产物。统计生成或写入失败不得否决、回滚已经通过准入的结单。

## 已确认规则

- 更旧结单：拒绝，不改动当前来源。
- 同期间结单：以上传文件替换当前来源。
- 更新期间结单：以上传文件替换当前来源。
- 不用服务器当前时间、`generated_at` 或 `statistics_cutoff_at` 判断结单是否可上传。
- PDF 无法打开、券商不匹配、没有持仓和现金等输入错误仍然拒绝。

## 数据流

`StatementImportService.import_pdf` 保持唯一上传接口：

1. 解析 PDF，取得券商、结单期间、持仓、现金与成交事实。
2. 与该券商当前已接受结单期间比较，只拒绝更旧期间。
3. 原子归档 PDF 并生成该期间的导入 run；这一步成功后，结单即为已接受来源。
4. 基于已接受来源重建 `trend_api_stats.json`。
5. 统计成功时返回 `statistics_status="updated"`；失败时恢复旧统计文件并返回 `statistics_status="failed"`，但保留新结单及导入 run。

Dashboard 对统计失败显示简短的“统计待重建”，不把结单上传显示为失败。

## 辉立非成交流水

辉立 `Transaction Details` 同时包含股票买卖和 Payment、Deposit、余额结转等非成交流水。只有包含 `Bought` 或 `Sold` 的候选行解析失败时，才生成 `invalid_execution_row` warning 并降低成交完整性。

没有 `Bought`/`Sold` 的非成交流水不生成成交 warning。真实但未知格式的股票买卖仍然 fail-closed，不会被静默忽略。

## 错误与回滚

- 解析、期间比较、归档或导入 run 失败：回滚本次来源变更并返回上传失败。
- 统计重建失败：保留新来源，恢复旧统计文件，返回上传成功及 `statistics_status="failed"`。
- 不新增队列、后台任务、数据库或依赖。

## 测试

- `StatementImportService`：同日东方财富结单即使统计时间校验失败，来源仍被接受；统计文件保持旧版本，结果标记失败。
- `StatementImportService`：统计写入失败不回滚辉立归档和导入 run。
- 辉立解析器：只有 Payment/Deposit 的结单不产生假成交 warning，成交完整性为 true。
- 辉立解析器：未知 `Bought`/`Sold` 行继续产生 warning 并标记不完整。
- Dashboard：统计失败仍显示导入成功，并附加“统计待重建”。
- 两份真实 PDF 均在隔离数据目录走完整上传链路。

## 不做

- 不修改全局趋势统计时间不变量。
- 不新增精确成交时间推断。
- 不新增统计重试调度；现有后续同步或再次上传可重建统计。
