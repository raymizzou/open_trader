# 三市场趋势退出纪律 v9/v6 设计

## 状态

已于 2026-07-25 由用户确认。

## 目标

统一东方财富 A 股、老虎美股和辉立港股的持仓退出纪律：

- A 股“温转热”和“温转沸”新仓统一使用账户净值的 4%，不再使用“沸状态 2%”；
- 新策略不再因“沸腾”或“开香槟”生成 30% 部分卖出；
- 三市场持仓继续在危险信号、离开趋势右侧、温度转平或 `2 × ATR14` 保护线触发时全部卖出；
- 退出规则变更后继续继承现有 Kelly 样本和回撤基准。

## 非目标

- 不改候选池、入场过滤、排序、持仓数量上限、买入窗口或风险预算。
- 不删除旧版本 `SELL_PARTIAL` 的读取、展示、回放、执行和对账兼容代码。
- 不重写历史报告、历史订单、成交事实或既有策略样本。
- 不新增自动实盘交易；现有人工执行边界不变。

## 策略版本与继承

发布以下新机器策略版本，部署后的新正式报告默认使用新版本：

| 市场 | 旧版本 | 新版本 | 明确继承的 Kelly 开仓版本 |
| --- | --- | --- | --- |
| CN | v8 | v9 | v4、v7、v8、v9 |
| US | v5 | v6 | v4、v5、v6 |
| HK | v5 | v6 | v4、v5、v6 |

每个新快照继续使用该市场既有策略族，只通过显式
`kelly_sample_inherits` 列出以上全部允许身份，不依赖递归继承。
三市场的策略回撤高水位从各自旧版本接续，不因本次升版归零。
完整交易仍归开仓版本，退出事实同时记录实际触发退出的新版本。

## 仓位规则

`CN_TARGET_WEIGHTS` 对“热”和“沸”都返回 `0.04`。A 股冻结策略参数和
Dashboard 纪律区只显示一条“单票目标仓位：账户净值的 4%”，移除
“沸状态仓位：账户净值的 2%”。美股和港股原有 4% 目标不变。

已有持仓不补仓、不因新版本重新平衡，也不追溯修改其首次开仓金额。

## 新版本退出决策

新版本对三个市场使用相同的全部清仓条件：

1. 已记录实时价格触及活动保护线；
2. `stopwinFlagByDangerSignal` 明确为 `true`；
3. `isTrendRightSide` 明确为 `false`；
4. `trendTemperatureCurr` 从“温”“热”或“沸”明确转为“平”。

任一条件先被系统观察到即生成 `SELL_ALL`。同一批次同时存在多个条件时，
保持现有确定性优先级：保护线、危险信号、离开右侧、温度转平。

“沸腾”和“开香槟”在新版本中仅作为市场事实，不生成 `SELL_PARTIAL`，
不启用五日最低价跟踪，也不改变活动保护线。

### ATR 保护线

新持仓首次成交后仍建立：

```text
初始保护线 = 合并买入成交均价 - 2 × ATR14
```

新版本不再因过热信号上移该保护线。版本生效前已经上移的活动保护线不得
向下放宽，继续作为该既有持仓的保护线；版本生效后不再继续上移。

### 缺失数据

明确的保护线、危险或离开右侧退出优先于其他字段缺失。没有退出条件且
温度、趋势信号或保护线所需行情不完整时，继续生成 `MANUAL_REVIEW`，
不得把未知解释为安全，也不得补猜信号或 ATR。

## 旧版本兼容

旧版本快照继续保留原参数和 30% 过热减仓语义。使用旧快照进行历史回放
时，仍可重建 `SELL_PARTIAL`；已冻结的旧报告以及已经产生的部分卖出
动作仍可展示、执行、恢复和对账。

新版本路径不得生成新的 `SELL_PARTIAL`。旧兼容分支只由旧策略快照或
既有冻结动作进入，不成为新版本的隐藏退出条件。

## 输出与界面

新版本冻结参数、Markdown、飞书和 Dashboard：

- 移除“沸状态仓位 2%”；
- 移除过热止盈比例、信号、次数、取整、不足一手、清仓优先级和过热跟踪；
- 不显示“止盈减仓 30%”计数或动作；
- 新持仓的保护线触发明确显示为“2×ATR14 硬止损”；旧持仓若沿用已上移的
  保护线，则显示“既有活动保护线触发”；
- 分别保留“危险信号清仓”“离开右侧清仓”和“温度转平清仓”原因。

Dashboard 仍按冻结快照渲染历史报告，因此旧报告继续显示其原始 30%
部分卖出纪律和动作，不被新版本文案覆盖。

`纪律.md`、`CONTEXT.md` 和相关 README 同步描述新版本规则、旧版本兼容
以及本次明确批准的 Kelly 样本和回撤继承关系。

## 测试

最小自动化覆盖：

1. CN v9 的热、沸目标仓位均为 4%，冻结纪律中没有沸状态 2%；
2. CN v9、US v6、HK v6 的危险、离开右侧、温度转平和保护线触发均产生
   `SELL_ALL`；
3. 新版本仅出现沸腾或开香槟时保持持有，不生成部分卖出或上移保护线；
4. 明确退出信号不会被其他缺失字段降级为人工复核；
5. 新快照不含过热减仓参数和纪律行，并含精确的样本继承身份；
6. 旧版本快照仍能生成、展示并对账 `SELL_PARTIAL`；
7. 新版 Markdown、飞书和 Dashboard 不含“止盈减仓 30%”或“沸状态
   仓位 2%”，历史冻结报告仍保持原文。

## 直接验证与上线

实现期间运行相关单测和直接报告流程。完成源码改动后：

1. 更新并提交 `CHANGELOG.md` 的 2026-07-25 操作日志；
2. 检查 `screen`、`launchctl` 和相关 watcher，停止仍加载旧 SHA 的进程；
3. 以新 SHA 启动服务并核对 PID、工作目录、Git SHA、时间戳和新日志；
4. 运行 `make acceptance` 作为最后一个 Dashboard 验收步骤；
5. 只有结果为 `PASS` 才部署完全相同的已验收 SHA；
6. 再次核对 PID、工作目录、SHA、新日志和 review URL 的 HTTP 200，然后
   将 URL 提供给用户。

`FAIL` 必须继续修复并重跑；`BLOCKED` 必须如实报告，不能用 curl、fixture、
mock、截图或单测替代浏览器和真实环境验收。
