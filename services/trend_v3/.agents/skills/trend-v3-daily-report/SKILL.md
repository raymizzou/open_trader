# Trend V3 日报

在当前交互式会话完成私有日报。当前范围包括股票、1 倍 ETF 和期权的新仓观察，以及入选大类本身作为交易品种时的当期特殊信号观察。期货与持仓、凯利数据均后置。实盘、模拟盘和凯利各保留一节，统一显示「未接入」。正式阅读文件先在本地核对，再按「读取、修订与同步」交付。禁止交易、发布、发消息、微信或登录自动化、委派其他 agent，以及改动调度。

先辨明入口。指定固定证据离线成稿或复验时，直接走「离线证据入口」。定时会话按「定时会话」运行。普通交互请求按「读取、修订与同步」处理。每次日报交付以适用于请求报告日及其截至时间的可用证据成稿，交付一份保留 V1 阅读版式的现行 HTML。禁止核验整份日报的数据完整性，或用市场、标的、信号等覆盖情况决定是否成稿或交付。任何查询均受原有授权与费用保护约束。

## 开始与费用控制

1. 用启动消息给出的 Asia/Taipei 运行日，交互请求按指定日期或当日。除离线演练外，定时、手工及修订都在同一主机使用同一个私有目录 `~/.local/share/trend-animals/reports/`。读写报告及同日证据须持该日运行锁。普通手工修订仅在用户明确要求时进行，先说明变更范围和预计新增费用。启动消息指定的定时会话按下文接管当天检查、同日修订和私有状态更新。任何入口发可能计费的请求前，都须按「运行锁与共享账本」核对跨日报日证据。
2. 从本技能入口的绝对路径定位所在 OpenTrader 检出目录，或使用启动消息明确给出的检出目录。用 `git -C` 核实根目录及指定的提交，未指定时用该检出目录的 `HEAD`。从同一个完整提交 SHA 核对本技能的 `SKILL.md`、`render_report.py`、`assets/report.html` 及仓库根目录的 `纪律.md`。使用与该 SHA 字节一致的文件，记录完整 SHA 和四份文件的摘要。渲染器和模板须保留相对目录，独立发布包也须同时包含两者。不依赖启动工作目录，不混用分支或其他检出目录的文件。缺文件、版本不符或无法确认时回报缺口，停止正常成稿。
3. 按本机私有配置确认 API 权限、允许范围与速率。`TREND_ANIMALS_API_KEY` 从环境或明确配置的私有来源在内存读取，配置文件只解析。只向通过证书校验的 `https://www.trendtrader.cn/apiData/data/` 发送 `X-API-Key`，不随重定向转发。输出、调用参数和证据中不得留存密钥、认证请求头或账户标识。
4. 用 `getSnapshotColumnBilling` 和当前官方价目，按调用、字段集、预计行数、折扣和缓存估算已有授权且确有必要的查询费用，按当前获准频率串行执行。费用上限仅在用户明确指定时适用。遇认证失败、限流、权限、费率、费用或额度不明时停止受影响的付费请求，保留已核实证据，缺项标 `UNKNOWN`，继续用可用证据成稿。

### 离线证据入口

- 用户指定固定证据目录离线成稿或复验时，只使用固定输入、版本核对、日期核对、筛选与成稿步骤。跳过定时和实时取数路径，不访问供应商、行情、价目、账户或调度，不为任何缺项购买数据。只在指定离线输出目录写文件，保持输入只读，跳过正式日报目录和跨日账本。按原报告日和截至时间核对事实，私下保存证据摘要、来源和费用；新增付费调用为零，缺失的旧费用仍标 `UNKNOWN`。重复成稿核对阅读文件的候选与事实，并在私有证据核对来源、名次和费用。
- 复验未提交候选时，可显式指定同一检出的候选技能、渲染器与模板，并记录基准完整 SHA、三份候选文件摘要、纪律的实际提交及摘要、固定证据版本。候选和证据身份只记在私有验证记录。定时与手工运行仍用前述固定版本规则。

## 定时会话

每个日历日（含周末及股市假日）在 Asia/Taipei 08:30 启动一个交互式标签，负责启动日的报告。当日只做一轮定时取数和成稿，晚启动时补做该轮。未到时点不取行情。取数后按「生成阅读 HTML」用该日可用证据成稿，结束自动处理，保留标签供 Ray 追问。

- 在 `_evidence/YYYY-MM-DD/` 记录报告日、计划时点 Asia/Taipei 08:30、适用证据与依据、实际观察及取数时间、本轮执行记录和报告版本。启动或恢复时重读时钟、原报告日状态和账本。已有本轮取数记录时按实际进度恢复，已完成取数时直接用有效的本地证据处理文件，按「读取、修订与同步」复用或成稿。跨午夜仍用原报告日及路径。
- 定时取数按「运行锁与共享账本」先取共享锁，再取报告日锁。取锁后先重读本轮执行记录及账本，再决定是否发送。完成请求、证据落盘、对账及本轮完成记录后按相反顺序释放。无法取锁时按锁规则回报。费用、权限、证据及待对账限制只约束受影响的操作，缺项记 `UNKNOWN`。
- 在本轮按「适用数据日期」复核适用数据日及榜图版次，优先复用合格的本地证据和已核实响应。按「核对与筛选」核实官方金融资产日图的可确证席位，按「定时取数」进行已授权的必要查询。`getUpdateStatus` 仅在授权范围内用于最小更新观测。日期、身份、版本或费用无法核实时记录具体缺项。取数后直接筛选、成稿、确认落盘，按「读取、修订与同步」交付。数据缺项不触发等待、后续轮次或自动刷新。

### 定时取数

在定时取数轮次中，先核对适用数据日及榜图版次，再按已有证据、缓存、账本、字段费用和授权串行查询必要字段。超出授权或无法核实费用、请求身份、版本或响应时，保留已知事实和缺项，按账本规则停止受影响的发送。

1. 对作为交易品种的入选大类，直接核对自身身份与当期行情，不等待或为此查询成分。先从现有证据确认标的身份、实际市场及覆盖，复用适用数据日或版次的已核实快照。必要的身份、日期或当前温度缺失时，沿用既有授权的 `getTickerSnapshot` 路径及已核实的字段、费用和频率补齐。没有适用授权、已知覆盖或可靠身份时记缺项，不能从分类 ID 推定行情标的。

   核实身份和当期数据日或版次后，若仍缺判断自身特殊信号的证据，用同一快照路径请求识别阳性事件所需的最小字段集，例如经核实确实承载相关事件的 `tickerLabels`。只请求已获授权、字段含义及费率已核实的必要字段。此检查不受当前温度或开仓初筛限制。优先复用同一标的、市场和版本的缓存。门槛已满足时，将所需字段合并到同一标的、市场和版本的已计划快照，按共享账本核对覆盖范围和去重。取得响应后核对标的、市场和数据日或版次，并私下记录实际字段和来源。授权、费用、版本或字段不可核实时标 `UNKNOWN`。不为证实没有事件追加查询。

   BTC 现货属于已核实的入选大类且与该大类直接同一时，先复用该现货标的、实际市场及适用数据日的有效 `trendStrengthLocalCurr`。缓存未覆盖且已有同一 BTC 现货的已授权计划快照时，将 `trendStrengthLocalCurr` 合并到该次 `getTickerSnapshot` 的 `fields`。使用已核实的现货 `tmId`，并取足以核实身份、市场和 `asOfDate` 的返回字段。按「适用数据日期」核对响应，按共享账本检查字段覆盖、等效请求和未结算发送。没有可合并且获准的快照时，定时轮次保留缺项，不为强度另开一次查询。
2. 为新仓筛选入选大类时，使用已授权的 `getComponentTicker(tmId=类别ID, getAllBasicComponentsFlag=0)` 取直属成分。仅沿已核实的下级分类展开，叶节点返回的所属父类不展开。只核对所得直属或下级成分中适用市场的股票、1 倍 ETF，以及已有证据识别的适用市场股票和 1 倍 ETF。未核实的期权身份、行情或资格只列缺项；只有具备已提供且核实的期权自身身份、市场和字段时，才将该证据用于筛选。不同来源的相同标的按身份、市场和数据日去重。成分关系与收藏夹成员关系分别核实。
3. 对尚缺行情的股票及 1 倍 ETF 用 `getTickerSnapshot` 分两轮取最少字段。首轮取身份、`asOfDate` 和 `trendTemperatureCurr`。仅对通过身份和日期核验的标的补第二轮。对做多当前「热」或做空当前「寒」的标的，补 `trendTemperaturePrev` 和 `tickerLabels`。给进入比较范围的已核实组员补 `trendStrengthGlobalCurr`，含当前温度已排除开仓信号的可比组员；符合初筛且需评估方向席位的已知标的也补该字段。第二轮仍须核对同一标的身份与适用交易日。其余标的优先用已有证据核实信号字段；只有在判定信号一致性确有必要且费用与授权均已核实时才补取。字段未齐时可写实际温度及已排除的转换，状态仍按具体缺项判定。缺少比较或资格证据时按「核对与筛选」标缺口。
4. 期货、持仓与凯利不进入本期取数。本期沿用已有直属成分路径和已知标的，收藏夹建议只来自现有证据；新增资产发现、期权研究和收藏夹管理由本期范围之外处理。

### 运行锁与共享账本

- 以 `umask 077` 建立私有报告目录及 `.claims/`，权限 `0700`。用不带 `-p` 的原子 `mkdir` 取得报告日锁 `.claims/YYYY-MM-DD` 和跨日报日共享锁 `.claims/scheduled-check`。定时检查，以及任何手工或修订操作中可能计费的请求，均先取共享锁，再取报告日锁。只读报告、离线从已核实证据更新格式或只写日状态证据时，只需报告日锁。若在持日锁时发现需要付费，先释放日锁，再依次取共享锁及日锁，重新核对两处证据。仅创建成功者持有本次随机令牌，并以 `0600` 写入锁目录的 `owner` 文件。创建失败或所有者记录不完整时停止相应操作，回报正在运行或需要核对。不得检查后重建、借用别人的令牌，或用 `.dispatch` 锁代替。
- 任何可能计费的发送前，持共享锁查询 `_evidence/_billing/` 的跨日报日账本，并检查全部日报日下现有及旧版证据中的请求记录。可用已核对覆盖完整、源记录可访问且尚未变更的索引查旧记录。将旧版的已完成、可能已发和待对账状态及原证据纳入共享查找。若旧记录身份含糊、来源不可读、覆盖不全或存在仍按旧规则执行的会话，先停受影响的付费发送，核对后再继续。无法排除与请求重叠时标 `UNKNOWN`，不把索引缺项当成未发。
- 用供应商作用域、端点、实际目标及有效参数、字段集和可验证的数据日或版本识别逻辑请求。只归并已证实等效的参数表达，保留影响实际请求或计费范围的字段与过滤条件。启动日、报告日、仅用于编排的市场标签、入口、文件夹和本地调用时间不进入身份。复用匹配的已完成响应并保留费用出处。响应不可取时标 `UNKNOWN`，不补发已完成请求。查找时也核对可能覆盖同一计费目标的记录。真正不同的数据日或版本必须有可核验证据，且能证明旧发送不可能取到同一版本。没有版本证据时仍按同一逻辑目标核对。不得通过换日期、市场标签、字段或参数规避尚未对账的发送。
- 对 `getUpdateStatus` 等可变观测，先核实授权、费用和间隔。复用同一观测已完成的结果。仅在前一观测已落盘并核对、确实需要新的观测、且共享账本记录的间隔已到时，为同一逻辑目标登记下一次观测。若前次是否发出或扣费不明，先对账，时间戳或下一个小时不能开启新的计费尝试。只有已核实免费且不会重复待核对的可能计费请求时，才可在日报检查时作免费观测。
- 每次可能计费的请求，先在共享账本持久化逻辑请求身份、原日证据定位和「可能已发送」记录，再发送。用同目录临时文件原子更新记录，并同步文件和父目录。共享锁持续覆盖查找、持久化意图、请求及结果落盘。分别记录响应、缓存命中和实扣，日账本引用共享记录。响应或账单暂缺时，落为 `UNKNOWN` 并记录待对账依据后可释放锁。恢复时先核对原响应和账单，不以另一笔已完成记录结清待核对请求。无法证实未发且未扣费时，不得重发该请求。崩溃在意图写入与结算之间，仍视为可能已发送。
- 锁目录跨工具和 shell 调用持续存在。没有在途请求且意图及最后已知结果已落盘时，仅原持有者核对令牌，再删除 `owner` 并用 `rmdir` 释放锁。中断留下的共享锁或日锁，优先交原会话核验和恢复，所有权不明或原会话无法恢复时保留锁及账本并回报人工核对。禁止自动超时接管、替其他会话删除锁或在等待时持锁。

### 适用数据日期

- 定时、手工、历史离线及修订都按品种的实际市场独立判断，不以股票休市否决整份日报。手工读取不启动取数；明确要求的手工修订仍受适用数据日期、授权及费用门槛约束。历史离线只用固定证据，不用今天的日历状态或后来发布的数据替换历史事实。
- 定时日报以该报告日及其计划时点为证据基准。按当时适用的市场日历、日界和已核实的供应商发布时间规则，分别确定并保存该报告日应使用的榜图日期或可接受版次、各来源及品种应有的数据日和核验依据。恢复时沿用已核实的适用范围。尚不确定时记 `UNKNOWN`。实际观察或取数时间只记录何时取得证据。迟到的原日报日证据可以使用，后续报告日专属的榜图或行情不能替代。
- 历史或修订报告用该报告确认的截至时间（含时区）。按交易所当地交易时段和已核实的发布时间规则，取已应发布的最近交易日。连续市场按供应商已核实的时区、日界及发布时间取已应发布的数据日。台北报告日不等于供应商数据日，连续市场的滚动 24 小时也不是交易所日线。只有依据明确确认上一数据日仍适用，才可用其数据。若两个报告日各自核实同一闭市市场的数据日或版本适用，按共享账本复用符合条件的响应。
- `getUpdateStatus` 只用于观测实际更新。证据缺失、无法映射榜图版次或无法核实发布时间规则时记 `UNKNOWN`，不按日历日、最近响应或更新时间猜测。榜图用图面日期或可核实日期的版次匹配预期榜图；大类和每个品种的必需行情输入须匹配各自适用的预期数据日。只有已核实某日期适用时才可继承榜图日期。已知但不符的实际日在私有证据中如实记录，并给出预期日期和原因。受影响的证据不能用于观察卡、新仓判断或比较，不用旧图、替代榜或顺延大类填补缺口。

### 手工补取 BTC 现货强度

- 在明确要求的手工修订中，先复用该现货标的、实际市场和适用数据日的有效 `trendStrengthLocalCurr`。只有缓存及已完成响应均未覆盖，并且 Ray 已明确授权本次单笔补取及适用费用时，才用既有 `getTickerSnapshot` 路径请求该字段及必要的身份、市场和 `asOfDate` 返回字段。仍要按共享账本取锁、查重及落盘。已完成但暂不可取、可能已发送、扣费未明或覆盖无法核实时按账本记 `UNKNOWN` 并停止补发。普通读取、离线成稿和只改格式继续用本地证据。

## 核对与筛选

1. **选大类。** 用官方金融资产日图 `getTickerTrendPlot(tmId=368431, seq=2, orderType=3)` 的证据核对图面日期、组名、全局名次和强度。按入口使用固定证据或复用已核实响应，定时取数中只在已有授权及费用保护允许下查询。头两名做多，尾两名做空，记录并列和分数。使用能够独立核实的席位，切点或图面证据不明的席位标 `UNKNOWN`。`10002` 和结构化 18 行均不能替代图面名次。保留官方榜图头尾的原始席位。只有期货、缺少合格标的或证据有缺项时，保留该已核实的大类席位，在展开区简述适用的事实和缺项，并保留私有核对记录。有证据支持的关联标的另列，不顺延替换原席位。
2. **核对标的证据。** 使用离线输入或既有授权路径取得的分组、身份、经济敞口、覆盖和行情证据。来自 #512 的可用证据可补充，采用其已经核实的事实；日报可独立成稿，不依赖 #512 的文件格式或额外发现。按市场及经证实的标的身份和数据日去重，核对适用市场预期日期、标的自身 `trendTemperaturePrev` → `trendTemperatureCurr` 及 `tickerLabels`。在私有证据记录直接、反向或代理的敞口及其出处，保留已核实的关联和局限。股票、1 倍 ETF、期权都必须有自身信号。标的自身信号缺失时，货币、指数、ETF 或期权底层资产已有的信号只能作为明示归属的背景。期权只列可用标的代码和市场及自身信号，Ray 手选行权价、到期月和张数。
3. **记状态和资格。** 每条私有证据行用下表的具体状态，保留已核实的身份、日期、敞口或信号。缺失字段标 `UNKNOWN` 并注明缺项。「证据不足」仅统称表中后六种状态。只有「已触发」且已核实符合交易资格的标的可入新仓区。信号已核实、资格待核时写「部分待核」，保留已知信号并点明缺项。信号已核实且已明确不符合资格时，保留「已触发」、数据日、标的自身转换和标签，另写「开仓资格：不符合」及具体原因。

| 标的状态 | 判定 |
| --- | --- |
| 已触发 | 身份、敞口和数据日已核实。做多为自身严格温→热且带「温转热」，做空为自身严格凉→寒且带「凉转寒」。 |
| 核实后未触发 | 身份和日期相符，信号字段一致，未出现该方向的开仓信号。 |
| 信号冲突 | 温度转换与标签不一致。 |
| 日期不符 | 必需数据日过期、超前或缺失。写明实际日和预期日。 |
| 已核实无匹配 | 适用范围内的趋势动物查询成功完成，证据确认没有与已核实身份完全匹配的结果。只说明该查询的结果。 |
| 敞口未核实 | 标的身份或经济敞口缺少可核实的出处。 |
| 部分待核 | 保留已证实的事实并点出仍缺的字段或资格证据。 |
| 未查询 | 写明因覆盖或费用而跳过的范围。 |

4. **计算方向名次。** 每个大类对应一个收藏夹分组，例如「V3-美元」。用该组可比成员的标的自身 `trendStrengthGlobalCurr`（记为 G）。多头名次为 1 加组内 G 严格较高的标的数，空头名次为 1 加组内 G 严格较低的标的数。私有名次表中同名次按代码字母序排列。按各成员适用的数据日和同一比较口径核实 G 与组员身份。可比成员即使未触发或明确不符合开仓资格，仍计入组内名次。分开标记已收藏成员与拟加入标的。拟加入标的若有经核实的自身 G 且有可比组员，可标明相对已核实组员的参考位置，不能把它计为已有组员或把参考位置写成正式组内名次。标出分组、数据日、计入范围和漏项；已经能计算的名次须注明其仅适用于可比范围。缺少必要数据时保留已知事实，名次标 `UNKNOWN`。小程序 0–100 页面整数的分位和舍入规则未公开。
5. **核对新仓及收藏建议。** 在私有证据中记录新仓名单。A 股股票即使自身做空信号已核实，本期也不符合做空开仓资格。选前两席之前就从做空候选中剔除，私有证据行写「开仓资格：不符合（本期 A 股股票不列做空新仓）」。资格根据实际交易标的的市场与品种核对。另行核实的期权和其他市场代理按各自的身份、资格及自身信号判断。

   只对已触发、符合资格且有已核实 G 的标的按多头 G 从高到低、空头 G 从低到高，同值按代码字母序，每类最多两个。私有名单保留其原组内名次或已注明的参考位置。第 2 席遇并列按代码取满，其余在私有证据中标「并列未列入」。以有证据支持的比较范围选入可列候选，并在私有证据注明比较范围、已知排除理由及具体缺项。无可入列候选时记「当前证据无可列候选」，保留已核实的信号事实。收藏建议及分组理由保留在私有证据，必要时在会话中请 Ray 手工添加。收藏建议不改变成员身份和开仓资格。分列接口或来源事实、计算名次和按纪律得出的新仓判断。

6. **核对大类自身的观察。** 仅在全局榜图已核实的头两类和尾两类内，核实大类本身是否就是可交易品种，记录大类与标的的直接同一关系、实际市场、适用数据日、自身当前温度和当期特殊信号。固定版本纪律中的自身特殊信号已确认（如「开香槟」「上天台」或「反抽警报」）且其余必需事实齐全时，在该大类下列观察卡，无需新仓触发、开仓资格、组内名次或新仓席位。沿用特殊信号逐项核验。由底层现货、父类、成分、指数或代理传来的信号均不能证明标的自身有事件。不凭简称或名称相同确认身份，不把期货放入本期。自身事件有明确阴性且事件覆盖完整时记「核实后无观察」；身份、日期、当前温度或事件仍待核时记录缺项。有至少一项独立确证事件时，其他事件待核不妨碍展示已证实事件。同品种强度缺失不撤销已证实的观察。单独记录观察及新仓结论，止盈及警报事件只作为观察事实，不产生开仓、持仓或订单动作。

### 关联品种的查询状态

- 仅对已核实身份、市场及所属入选大类关系的已知关联交易品种列查询状态。趋势动物查询成功完成，目标、范围和版本适用于该报告日及截至时间，且完整结果（含所有相关分页）确认无精确匹配时，记「已核实无匹配」，显示「查不到」。旧证据只记「平台未覆盖」时，回查原查询是否满足相同条件。
- 查询失败、未查询、分页未完成、结果未定、版本不适用或查询证据矛盾未解决时，在私有证据按实际情况记 `UNKNOWN` 或未查询，并对具备上述已核实身份及归属的品种显示「待核」。身份或归属未核实的品种仅留私有证据。若已有无匹配证据仍适用且未被冲突证据或更正推翻，保留「查不到」。查到精确匹配、身份或组别有更正、或旧证据不再适用时，按「同日证据更正」重新判断。
- 「查不到」和「待核」仅表明查询结果状态，不推定趋势、信号、交易资格、强度或名次，也不占用新仓席位。独立满足新仓或观察条件时优先显示相应卡片。

### 标的字段来源

- 为用于前温、当前温度、标签、G、同品种强度与特殊信号的每条实际记录分配简短、易读的私有证据编号，例如 `R17`。将编号与脱敏本地文件的固定版本及文件内的精确记录位置一并保存，例如数组下标或记录键。核对记录对应的标的身份、市场、实际数据日和字段。即使同一标的同一天，来自不同记录的字段也分别引用各自的编号。仅当同一条记录确实支持多个字段时才共用编号。
- 复用已有编号，同版复验、只改状态及合并其他市场时保持编号和记录对应关系。改用新版本的记录时分配不同编号，即使字段值相同。保留旧稿及其证据索引，已用编号不改绑、不回收。编号不依赖当前报告的行序、市场检查顺序或显示名次。
- 字段或可核实的源记录缺失时，对相应字段或来源标 `UNKNOWN` 并说明缺项，保留其他能核实的字段。无法核实来源的字段不用于确认信号或计算名次。无标签也须有相应记录，不能把缺失标签写成「无」。只依据现有脱敏证据，不按代码与日期猜测来源，不为补编号调用供应商。本技能可用已有文件形式记录对应关系。
- 特殊信号逐项核实。现有记录中的标的自身当期事件标签、事件专用布尔值或其他经核实的事件字段均可作证。确认字段含义、标的身份、市场和数据日，再记录每项事件的结论、实际字段和对应证据编号。开仓事件仍须符合「核对与筛选」的转换与标签证据。单凭温度变化或任意供应商标签不能确认特殊事件。遇到缺字段、覆盖未证实或同一事件证据冲突时，将该项标为 `UNKNOWN`，保留其他独立确证的事件。空或缺失的 `tickerLabels` 只说明标签证据的状态。只有完整覆盖及逐项阴性证据支持私下判为已查无事件。缺项不触发付费补查或猜测字段。
- 观察卡的同品种强度采用该标的自身、同市场同数据日及 0–100 同资产类别比较口径的原值。BTC 现货只采用已核实匹配的 `trendStrengthLocalCurr`。核实并记录实际字段、比较口径和证据编号。数值 0 是有效原值。缺值、非有效数值、口径不明或相互冲突时在私有证据标 `UNKNOWN`，保留其他独立确证的事实。榜图组分数、名次、代理分数及 `trendStrengthGlobalCurr` 都不能代填。同品种强度不参与分组、方向名次和新仓筛选。

## 生成阅读 HTML

### 版式与展示白名单

- 使用 [V1 阅读模板](assets/report.html)和下述渲染入口。页首显示「趋势动物观察报告」及实际报告日。目录锚点依次为做空、做多、实盘、模拟盘、凯利胜率。固定保留页首、目录、做空及做多面板、逐类展开行、直属与关联列表、实盘预留区、模拟盘状态和凯利列表及其原有顺序和样式。各方向首个显示的大类默认展开，后续大类默认折叠。实盘预留区内与模拟盘各用一条 `p.positions-note` 显示「未接入」。凯利列表的实盘与模拟盘两项各显示「未接入」，共四处状态。正式报告以 `YYYY-MM-DD.html` 命名。只有单张标的卡片的视觉可独立调整，其余版式改动需 Ray 明确批准。
- 各方向按已核实的榜图组序保留头两席或尾两席。展开行的「组内排名」是该大类在做多或做空面板中的方向席位，保留 `01`、`02` 等原席位。榜图全局名次及标的组内名次各自留在私有证据。展开行的「强度」只取大类榜图原值，标的自身强度填入对应卡片。页首说明当前采用的官方榜图日期及已核实的版次。缺失的榜图日期标「待核」，缺失的大类强度标 `UNKNOWN`。保留没有合格标的的大类。无法确认席位时，在相应面板写具体缺项并保留其他席位。
- 各大类展开区按已核实的直接交易关系和关联关系列标的。候选、观察及已核实的其他直属、关联或底层品种统一用 `li.asset.reader-card`。按已核实的身份和市场去重，各列表先列入选新仓，再列观察和其他已核实品种，查询状态卡按代码排序列在后面。新仓名单先按原规则选定，同一标的涉及多个新仓组时按阅读顺序取首个席位，其他有据关联可在对应组保留。同时入选新仓和观察时只显示一张新仓卡，观察依据另存私有证据。没有可刊标的时，在对应列表位置写具体缺项。
- 每张卡显示「代码 · 名称」、标的自身「当前趋势」「特殊信号」「强度」以及一句中文理由。「当前趋势」取标的自身当前温度。「特殊信号」只列标的自身当期已确认的事件名称，按首次出现顺序去重，用中文逗号「，」分隔。没有可列事件时写「无」。查询或事件覆盖的缺项及原因按已有规则记入私有证据，适合发布的查询状态或理由仍在本卡其他字段呈现。「无」只表示没有可列的已确认事件，不能据此判定事件均未发生或作交易判断。止盈事件不能当作开仓触发。可展示的全局强度用 `trendStrengthGlobalCurr` 原值加 ` / 100`，观察卡用核实的同品种原值，例如「同品种 6 / 100」。趋势、强度缺值显示「待核」。已核实值不换算或舍入。市场、日期、原始字段、范围和取舍按原规则保留在私有证据。
- 新仓理由说明该标的为何在这个方向和大类入选，比较结论限于已核实的范围。观察理由按固定版本纪律解释品种自身信号的用途。上天台写「该品种触发空头止盈信号，列为观察。」开香槟写「该品种触发多头止盈信号，列为观察。」反抽警报写「该品种出现空头风险警报，列为观察。」其他已核实的事件按各自用途写。其他品种的理由简述已核实的关联、未入选或待核原因。理由限于可发布的事实，不引入交易指令、推定持仓、日期、证据编号、公式、名次、费用或其他标的。身份或归属未核实的品种只留私有证据。日期不适用时停用该行情值，在私有证据写明实际日和预期日。
- 身份及关联已核实，但只适用查询状态的品种使用 `lookup`。完整适用查询已确认无精确匹配时，用 `miss`，趋势和强度显示「查不到」。查询失败、未查询、未确认后续页或仍待核时，用 `pending`，趋势和强度显示「待核」。两种卡片的特殊信号均为「无」。理由可写经核实且可刊的来源或原因，例如只收到第一页。没有适用理由时显示相同的查询状态短语。每个查询状态卡放在阅读顺序的首个已核实关联组。部分响应或其他证据足以独立确证事件时，通过有据的普通卡、观察卡或新仓卡呈现该事件，保留其他缺项。
- 版式和字段以模板为准。静态目录可链接页内锚点。正式 HTML 仅包含白名单内容，禁止脚本、外链、外部资源、任意 HTML 片段、隐藏数据、纪律或费率附录、费用、证据编号、路径及账户信息。落盘、交付和已有授权的同步前核对全文件、五处锚点、展开结构、三区的四处「未接入」及白名单字段与证据的一致性。校验不通过时不得交付。

### 固定渲染入口

定时、手工、离线、修订及同日复用核对都调用同一版本的 [渲染器](render_report.py)。先将适用于请求报告日和截至时间的已核实事实筛为下列 JSON。生成可用报告不要求任何组或行情字段达到覆盖门槛。JSON 只放获准显示的值，保存在现有授权的私有目录，不同步。

```sh
python3 "$skill_dir/render_report.py" "$verified_json" "$new_html"
```

`skill_dir` 为核对过版本的技能目录，`verified_json` 为明确选定的 UTF-8 输入路径，`new_html` 为已存在的私有目录下尚未使用的候选文件路径。渲染器只读该输入与同目录下的 `assets/report.html`，生成一份 UTF-8 HTML。它转义所有动态文本，展开并移除模板节点和插槽。已有路径返回非零。需要替换现行日报时，先核对候选，再按下文的锁、归档和原子替换流程处理。

- 根对象必须有 `date`（实际报告日，`YYYY-MM-DD`）。可选 `board_date`（经核实的榜图日，同格式）、`board_version`、`short`、`long`、`short_note`、`long_note`。方向数组缺省为空，方向说明只写白名单允许的具体缺项。
- 每个大类有已核实的方向席位 `seat`（整数 `1` 或 `2`，同一方向内唯一）和 `name`，可选 `code`、`board_strength`、`direct`、`related`、`direct_note`、`related_note`。两个列表缺省为空。两种列表说明用于对应列表为空时。保持筛选后的席位和标的顺序。
- 列表中的标的有 `code` 和 `name`，可选 `trend`、`strength`、`reason` 和 `lookup`。有据的趋势及普通强度使用显示文本。趋势及普通强度的缺项可省略或用 `UNKNOWN`，读者值为「待核」。BTC 现货观察卡用 `local_strength` 投影已核实的 `trendStrengthLocalCurr`，可用数值或保留原精度的数值文本，缺值用 JSON `null`。有 `local_strength` 时，渲染器只用该字段确定卡片强度。旧投影仍可用已核实的 `strength` 显示文本。提供 `lookup` 时，按查询状态填趋势和强度，特殊信号填「无」，仍可提供经核实的 `reason`。
- 新投影用 `signal_events` 文本数组，每项只填一个通过「标的字段来源」逐项核实的标的自身事件名称。常见例子有「温转热」「热转沸」「寒转冻」「寒转凉」「开香槟」「上天台」「反抽警报」。其他同等确证的事件也使用该数组。定时成稿、手工成稿与同日更正都先逐项核实，再写数组。禁止把供应商的原始标签列表、否定结论、覆盖状态或解释文字直接写入数组。空数组表示当前无可列事件，并优先于同一投影中的旧 `signal` 文本。
- 有效旧投影若只有 `signal`，渲染器在分号、句号或换行分隔的每个分句内，从开头保留完整匹配的既有事件名称。列表可用 `、` 或中英文逗号，分句开头允许「已确认：」或「已触发：」。否定、待核或含义不明的说明若出现在分句开头或紧接逗号，结束对该分句的采纳。说明若紧接 `、`，仍可保留随后由逗号独立分隔且带旧版「（其余待核）」后缀的单个既有事件。带冒号或不明括号的说明始终结束该分句的采纳。显示时去掉覆盖后缀。仅用当前仍适用的历史私有证据迁移旧投影。其他已确证的事件用 `signal_events` 重建。最少输入只有报告日，例如 `{"date":"2040-01-01"}`，仍生成完整页面。

### 私有证据

- 用固定版本的 `纪律.md` 做核对，纪律全文、完整榜图和证据原件、收藏建议、方向名次计算、费用、讨论，以及超出展示白名单的字段和技术缺项只留私有证据或必要的会话状态。禁止读取持仓或账户仓位来源，不用持仓做候选筛选，不生成持仓动作或凯利值。
- 在原有 `_evidence/YYYY-MM-DD/vNN/` 保留脱敏输入及实际来源、版本与摘要、各标的实际日期、身份与敞口、温度与标签、资格、可比组及范围、方向公式及名次、并列、未查询及缺项。私下逐项记录事件、同品种强度、大类与自身标的同一关系的来源字段及私有编号，并记录观察与新仓结论及去重取舍。无匹配或未核实的关联品种另记已核实的身份、所属大类、查询范围和版本、完成状态、实际结果出处及缺项，引用原脱敏证据，HTML 只列白名单允许的查询结果与简短理由。引用定位到脱敏本地证据的实际版本与记录，保留完整阴性范围及未知原因。按「标的字段来源」稳定复用编号。记录估算、可核实实扣、差额、缓存、未发和待对账请求及其共享账本引用。缺失与待对账金额记 `UNKNOWN`，不得当作零或实扣。既有授权的只读费用对账仅取必要扣费证据，不读取仓位或留存账户标识。禁止把私有证据、旧稿、账本、说明或伴随文件置入阅读文件或同步目录。

### 读取、修订与同步

- 持报告日锁核对同日更正记录及最新有效的本地证据。只有能证实文件使用当前有效版本的模板与渲染器生成、属于请求报告日、符合白名单，且与同日当前证据重新渲染的结果字节一致时，才直接复用原字节。单凭文件名、格式或历史状态不得复用。旧版日报保留在私有历史。没有可复用的文件时，在授权范围内按请求报告日和截至时间用可用证据渲染完整的 V1 HTML，方向面板按现有证据列席位、标的或具体缺项。普通读取和仅改格式均零新增行情查询。文件身份、写入授权或目标有疑问时按锁和文件规则说明具体问题，不覆盖身份不明的文件。读取不触发重写其他历史日报。
- 复验旧稿时按当前投影规则从仍有效的私有证据写 `signal_events` 与 BTC 现货 `local_strength`。旧信号覆盖说明只留在理由或私有证据；现货强度只从匹配的 `trendStrengthLocalCurr` 重建。现行 HTML 的旧格式或历史展示文本不能代替字段证据。
- 写入时持有报告日锁，核对原报告日、可用证据和修订授权，按原有私有目录权限（`0700`，`umask 077`，文件 `0600`）留存不可混淆的旧稿与版本，再用同目录临时文件原子更新同日阅读路径。以经过核验的私有证据合并变化。即使只更正一项，也用当前有效模板和渲染器生成整份报告，带入其余仍有效的榜图字段、展开行、卡片、查询状态、缺项及顺序。不从旧 HTML 提取事实。现行文件版本身份可核实且与候选字节相同，保留原字节，不创建新阅读版本。落盘失败直接在会话回报。
- 每个向 Ray 正式交付日报的会话或标签都使用所选仓库版本的本技能。按既有同步授权，在现有 iCloud `trend_v3` 文件夹读回并逐字节核对现行 `YYYY-MM-DD.html` 与本地版本一致。若缺副本且已有授权涵盖补齐操作，按原生同步流程补齐该份已核实 HTML，再读回核对。只在当前会话给出这个文件的链接。单项更正也用整份 HTML。无法核实目标或有效副本时，在会话说明实际的同步或文件问题。保持现有同步配置和权限，私有证据只留本地。固定证据离线验收样例仍沿用指定的离线输出目录。

### 同日证据更正

- 暂未取得更新、仍待核或费用状态变化时，保留此前仍适用于报告日及截至时间、未被推翻的榜图事实、展开行、卡片和查询状态。已有授权且核实的同日更正若明确推翻已刊席位、展开事实、原卡的信号、资格、强度或其他已刊事实（含无匹配结果及关联组别），先在私有证据持久记录受影响的席位或标的、旧刊版本、证据版本和原因。该旧条目立即不得再作为当前内容返回、重生成或同步，即使本地文件尚未处理或其他标的仍待核。按最新有效证据重新核对席位、展开行、观察、新仓和查询状态。仍可保留的卡片按现有有效证据重写 `signal_events`，需要时用空数组。只撤回同品种强度且仍满足观察条件时，在私有证据记 `UNKNOWN`，现货卡以 `local_strength: null` 投影。复验与重试不得用旧证据恢复已撤回的事实。
- 持报告日锁先核对原阅读路径、报告日、已保存的文件身份及版本，只有可确认由本技能生成且与私有记录匹配时才处理旧文件。已有授权范围内先在私有证据存档原件，再按最新有效证据生成整份现行 HTML 并原子替换。保留 V1 版式及其余仍有效的内容，无可列席位或标的时在相应方向面板或列表说明缺项。若确有文件或授权问题无法安全替换，只按已有撤回授权处理核实过的旧稿，并说明实际问题。用户编辑过、身份不符或未获授权的文件不自动移动、覆盖或删除，即使原件留在当前路径，也不作为当前报告返回或同步。
- 若已核实原同步副本仍含失效条目，仅在核对原共享目标和版本且已有授权覆盖该更正或撤回操作时，限于该副本更正或撤回。没有适用授权时停止重新交付，在会话说明云端仍有旧副本并请 Ray 明确批准；目标或版本无法核实时停手并说明缺口。区分本地和云端处理结果，未核实云端生效时保留待核。重试前读回私有处理记录和当前版本，已完成的同版更正不重复，结果不明时不盲重发。不处理其他文件、伴随文件或历史日报。本地和同步更正均不补发付费查询。

### 状态更新

- 市场状态、缺项和费用状态记入私有日状态。当前有效模板、渲染器及可刊证据均未变，且已有合规的现行 HTML 时，状态更新保留原字节，不另存阅读版本、不访问供应商或增加费用。发现已核实更正时执行「同日证据更正」。中断恢复时从已保存私有证据继续，遵守共享账本的禁止重发规则。
- 历史状态（如 `NOT_READY`）和历史复查时点只留作记录。恢复以实际取数、对账和文件证据为准，当日有权成稿时使用现有适用证据。历史状态不得阻止成稿、触发新一轮取数或代替对现行文件身份和事实的核对。
