# Trend V3 日报

在当前交互式会话完成日报和回报。只读核对，使用已授权的官方 API 查询行情。品种身份和经济敞口可查交易所或发行人的公开一方资料，查询只带公开品种身份。保持持仓事实和报告在本地。禁止交易、发布、发消息、微信或登录自动化、委派其他 agent，以及改动调度。

## 开始与费用控制

1. 用启动消息给出的 Asia/Taipei 运行日，交互请求按指定日期或当日。先检查 `~/.local/share/trend-animals/reports/YYYY-MM-DD.html`。同日已存在时读取并回报原路径，新增行情调用为零。仅在用户明确要求时修订该日，先说明变更范围和预计新增费用，留存旧稿和证据。
2. 从本技能入口的绝对路径定位所在 OpenTrader 检出目录，或使用启动消息明确给出的检出目录。用 `git -C` 核实根目录及指定的提交，未指定时用该检出目录的 `HEAD`。从同一个完整提交 SHA 读取 `services/trend_v3/.agents/skills/trend-v3-daily-report/assets/report.html` 和仓库根目录的 `纪律.md`，也核对该 SHA 的 `SKILL.md` 与当前指令一致。不依赖启动工作目录，不混用工作树、分支或其他检出目录的文件。记录完整 SHA 和两份输入的摘要。缺文件、版本不符或无法确认时回报缺口，停止正常成稿，不以旧纪律或旧模板替代。
3. 按本机私有配置确认 API 权限、允许范围与速率。`TREND_ANIMALS_API_KEY` 从环境或明确配置的私有来源在内存读取，配置文件只解析。只向通过证书校验的 `https://www.trendtrader.cn/apiData/data/` 发送 `X-API-Key`，不随重定向转发。输出、调用参数和证据中不得留存密钥、认证请求头或账户标识。
4. 以 `getUpdateStatus` 与各市场交易日历确定预期数据日，逐源核对实际数据日。用 `getSnapshotColumnBilling` 和当前官方价目，按调用、字段集、预计行数、折扣和缓存分段估算首层、模拟持仓与候选费用。标准范围内只发已有授权的必要调用，按当前获准频率串行执行。费用上限仅在用户明确指定时适用。遇认证失败、限流、权限、费率、费用或额度不明时停止受影响的付费请求，交已核实部分并标 `UNKNOWN`。
5. 按端点、参数、字段集、数据日和可验证更新版本复用缓存。逐项记录估算、发送状态、缓存命中和账单实扣，未知实扣标 `UNKNOWN`。中断后先查同日证据、账本和账单。已完成的请求不重发，发送或扣费状态不明时先对账。

## 核对与筛选

1. **先核对模拟持仓。** 仅使用明确配置且可信的 Trend V3 `SIMULATE` 来源，或用户提供并明确标识为该模拟盘的私有快照。核实环境、账户归属、时间和快照完整性。不猜路径或账户，不读实盘或旧系统持仓。来源缺失、身份不符、过期或读取不完整时标 `UNKNOWN / 未取得可核实的模拟盘持仓`。只有完整、可信的空快照才写 `已确认无模拟盘持仓`。大类出榜后仍核查已有模拟持仓自身的 ID、市场数据日、价格口径、币种及信号。按同版纪律「清仓 → 退回观察仓 → 止盈 → 加仓」报告首条已核实的动作。高优先级条件、身份、数据或必要仓位事实不明，或标签冲突时写 `UNKNOWN / 人工核对` 及原因。只在私有报告内标识持仓。
2. **选大类。** 用官方金融资产日图 `getTickerTrendPlot(tmId=368431, seq=2, orderType=3)` 核对图面日期、组名、排名和强度。头两名做多，尾两名做空，记录并列和分数。切点或图面证据不明时标 `UNKNOWN`。`10002` 和结构化 18 行均不能替代图面名次。仅在证实某入选大类无可交易品种时按同图顺延，缺失或覆盖不足不能作为顺延理由。
3. **筛成员。** 仅查询入选大类。用 `getComponentTicker(tmId=类别ID, getAllBasicComponentsFlag=0)` 取直属成分，只沿已核实的下级分类展开，叶节点返回的所属父类不展开。按 ID 和数据日去重并报告过期、冲突和覆盖缺口。先用 `getTickerSnapshot` 取得身份、`asOfDate`、`trendTemperatureCurr`，只给做多类当前为「热」及做空类当前为「寒」的成员补取 `trendTemperaturePrev`、`tickerLabels`、`trendStrengthLocalCurr`。两轮身份和数据日必须一致。做多须温→热且带「温转热」，做空须凉→寒且带「凉转寒」。按本类的 `trendStrengthLocalCurr` 排序，做多由强到弱、做空由弱到强，每类最多两个已核实候选。只有经用户明确要求且核实目标页面口径时才换排序口径，报告覆盖范围。保留并列，名次或切点无从核实时标 `UNKNOWN`。
4. **核实品种。** 将直接交易标的与关联标的分列。对外汇先核实直接、反向或代理的经济敞口及方向。篮子货币、间接经营敞口、指数和连续行情等可列在关联栏并写明局限。具体股票、1 倍 ETF 或期货主力合约纳入可执行候选前，必须核实实际标的 ID、数据日、敞口和自身适用的转换及标签。货币信号不能代替代理的品种信号。按同版纪律标注其余开仓、加仓和人工执行条件。价格、信号、排名和敞口缺证据时据实标 `UNKNOWN`，不代填。

## 生成私有 HTML

- 保留 [报告模板](assets/report.html) 的标题、目录、样式和原生折叠。浏览器标题附运行日期，首屏写覆盖、结论、各市场数据日和主要待核事项。正文先放默认折叠的完整 `纪律.md`，再按做空、做多、当前实盘持仓、模拟盘持仓情况、当前凯利胜率排列。完整纪律按语义渲染标题、列表、引文和表格，首标题用 `h2#discipline-source-heading`。禁用 Markdown 原始 HTML，转义文本并将链接和媒体降为纯文本，禁止另写一份纪律摘要充当全文。两侧大类独立折叠，有数据时各自第一行默认展开。
- 用 ISO 日期替换模板中的 `{{report-date}}`，用年月日填充页眉日期。复用模板末尾的行结构，将品种列表包在 `<ul class="asset-list" role="list">` 内，按 `<!-- slot:… -->` 填充并移除所有模板节点和插槽。大类摘要列方向内的官方图名次及强度，展开后列直接与关联品种、成员覆盖、品种数据日、价格及币种、转换、标签、类内名次和证据缺口。模拟盘表保留日期、价格口径、币种和费用口径。仅用已核实字段或可复算的值，缺项标 `UNKNOWN`。
- 缺少已核实大类或标的时，在对应栏说明数据缺口或已经确认的空结果。仅给信号已核实的品种使用 `signal` 样式。模拟持仓的方向和盈亏样式按已核实值选择。
- `#live` 只保留标题和空白区域。实盘持仓及其推断不进入模拟盘、候选标记、摘要或其他输出。`#kelly` 只保留「实盘」「模拟盘」标签，两处值永远留空。模拟盘无已核实持仓行时仅显示对应状态，不生成占位持仓。
- 只用 UTF-8、模板内嵌 CSS 和页内导航。所有数据按文本用 `html.escape(value, quote=True)` 或等效方式转义。结构化片段只能由受控标签和转义后的文本生成。费用和证据放在页脚，简列估算、实扣、差额、缓存、未发和待对账请求及官方来源和本地证据位置，均用纯文本。禁止脚本、外部资源和远程链接。落盘前检查数据日、区块顺序、折叠、空白面板、未知状态及隐私边界。
- 以 `umask 077` 将报告和同日证据写入私有报告目录，目录 `0700`、文件 `0600`。在 `_evidence/YYYY-MM-DD/vNN/` 保留最小化输入、脱敏原始响应、只读 API 的调用账本、版本与摘要、费用对账和旧稿。用同目录临时文件原子落盘，同日写入串行化，覆盖前再核对既有报告及显式修订授权。最后在当前会话回报路径、费用和未解决缺口。落盘失败时直接报告失败。
