# Trend V3 日报

在当前交互式会话完成日报和回报。只读核对，使用已授权的官方 API 查询行情。品种身份和经济敞口可查交易所或发行人的公开一方资料，查询只带公开品种身份。保持持仓事实和报告在本地。禁止交易、发布、发消息、微信或登录自动化、委派其他 agent，以及改动调度。

## 开始与费用控制

1. 用启动消息给出的 Asia/Taipei 运行日，交互请求按指定日期或当日。定时、手工及修订都在同一主机使用同一个私有目录 `~/.local/share/trend-animals/reports/`。读取报告、缓存和账本或发任何付费请求前，先按下文取得该日运行锁。普通交互请求遇已有 `YYYY-MM-DD.html` 时读取并回报原路径，新增行情调用为零。普通手工修订仅在用户明确要求时进行，先说明变更范围和预计新增费用，留存旧稿和证据。启动消息指定的定时会话按下文接管当天检查，包含同路径数据修订的授权。
2. 从本技能入口的绝对路径定位所在 OpenTrader 检出目录，或使用启动消息明确给出的检出目录。用 `git -C` 核实根目录及指定的提交，未指定时用该检出目录的 `HEAD`。从同一个完整提交 SHA 读取 `services/trend_v3/.agents/skills/trend-v3-daily-report/assets/report.html` 和仓库根目录的 `纪律.md`，也核对该 SHA 的 `SKILL.md` 与当前指令一致。不依赖启动工作目录，不混用工作树、分支或其他检出目录的文件。记录完整 SHA 和两份输入的摘要。缺文件、版本不符或无法确认时回报缺口，停止正常成稿，不以旧纪律或旧模板替代。
3. 按本机私有配置确认 API 权限、允许范围与速率。`TREND_ANIMALS_API_KEY` 从环境或明确配置的私有来源在内存读取，配置文件只解析。只向通过证书校验的 `https://www.trendtrader.cn/apiData/data/` 发送 `X-API-Key`，不随重定向转发。输出、调用参数和证据中不得留存密钥、认证请求头或账户标识。
4. 用 `getSnapshotColumnBilling` 和当前官方价目，按调用、字段集、预计行数、折扣和缓存分段估算首层、模拟持仓与候选费用。标准范围内只发已有授权的必要调用，按当前获准频率串行执行。费用上限仅在用户明确指定时适用。遇认证失败、限流、权限、费率、费用或额度不明时停止受影响的付费请求，交已核实部分并标 `UNKNOWN`。

## 定时会话

每天 Asia/Taipei 08:00 启动一个交互式标签。该标签负责启动日的到点检查、等待和原路径更新。晚启动时按实际时间判断哪些检查已到点。先核对交易日历和本地状态，先于应查时点不调用行情或计费接口。

| 市场 | 首次检查时间 | 日历口径 |
| --- | --- | --- |
| A 股 | 启动日 Asia/Taipei 08:30 | A 股交易所 |
| 港股 | 启动日 Asia/Taipei 08:30 | 香港交易所 |
| 美股 | 启动日 America/New_York 08:30 | 美股交易所 |

- 以报告日期构造表中的当地日期及时间，再用 IANA 时区换算。美股夏令时对应台北 20:30，冬令时对应 21:30。A 股、港股和美股分别核对周末、假日及特殊交易日。休市的市场不启动新窗口，其他市场照常。按窗口原定时点和「数据日期门槛」独立确定预期交易日及榜图日期或版次，未能核实的规则或日期标 `UNKNOWN`。美股午夜后的复查继续核对该窗口，仍写原 Asia/Taipei 启动日。
- 在 `_evidence/YYYY-MM-DD/` 随同日证据保存逐市场状态，记录报告日、市场、检查窗口、日历来源、预期数据日和榜图版次依据、最近观测及已验证版本、状态、下次检查。窗口从首次检查时点到该市场下一交易日的首次检查时点，右端点不含。每次检查前核对现在和窗口结束时间。只检查已到点且未结束的市场，跳过错过的复查时点。尚未验证且可安全再查时，从本次检查时点起一小时后再查该市场。下次检查落在窗口外时，结束该市场的复查并保留缺口。已验证、休市、被下一窗口取代或因证据与计费保护无法继续的市场结束本轮检查。证据无法读取、费用未知或不明扣费保留 `UNKNOWN`，禁用需核对的重发。
- 逐市场串行执行检查。相邻日期的标签也通过 `.claims/scheduled-check` 共用一次检查的短锁，沿用同日锁的原子创建、令牌核对和释放规则。定时检查先取该短锁，再取报告日锁。另一会话持锁且可核实仍在检查时，将未能检查的市场顺延一小时并重查窗口，不能核实则按锁规则回报人工核对。每个市场只在当前窗口内启动请求。完成当次请求、落盘及对账后，按相反顺序释放两把锁。等待期间不持锁或留下在途请求。
- 用各未完成市场中最早的下次检查作为唤醒时间，报告当前状态和下一个时点，在同一前台会话定时等待。有 `clock.sleep` 时用该可中断工具，否则用当前会话支持的短段定时等待。仅有 shell 时可在前台使用分段 `sleep`，每段最多 60 秒，保持能处理 Ray 的新消息。醒来或回答 Ray 后，重新读当前时钟和状态，再判断已到点事项。未来仍有检查时保持该轮会话运行，避免空转。不另起调度器、后台服务、标签或 agent。没有待查市场时汇报报告路径（如已落盘）和各市场结果，标签保留供 Ray 追问。

### 到点检查与修订

1. 重查保存的证据及账本。先用获准的最小更新观测判断该市场的预期数据日或可验证版本是否已到。`getUpdateStatus` 只能提供实际更新线索。版本未变、仍旧或暂不可证实，跳过候选下钻，记录最近观测及下次检查。未知发出状态和账单仍按账本核对，不能把同一请求移到新市场、报告日期、版本目录或换参数来重发。无法区分新观测与旧的已完成/待对账请求时，先用可核实的旧证据，保留 `UNKNOWN`。
2. 仅对首次出现或已变化、且通过日期与身份核验的输入执行后续步骤。仍从同一官方金融资产日图确定全局头两名和尾两名，记录该图所用交易日或版次。按到点的市场限制成员和持仓下钻。不能建立该市场与全局榜图的关系时标 `UNKNOWN`，不按市场重排大类。另一个市场原有内容与证据仍保留。若使用过往榜图，标出其版次，不把旧版本候选写为新榜图下已核实的信号。
3. 只有首次取得已验证数据或已验证的数据实际变化时，才生成或更新该报告日的原 HTML 文件。先核对现有报告及可访问的既有版本证据，留存旧稿，再合并本轮市场变化，保留其他市场的内容、来源、历史和既有讨论。保留讨论正文时仍按纯文本转义规则渲染。无法核实现有报告与证据的对应关系时，停止覆盖并回报缺口。每次落盘的首屏摘要显示当时各市场状态、数据日、待核事项及下次检查。没有数据变化时保持 HTML 不动，在会话和状态证据中更新待查、`UNKNOWN`、原因及下一时点。

### 同日运行锁与账本

- 以 `umask 077` 建立私有报告目录及 `.claims/`，权限 `0700`。用不带 `-p` 的原子 `mkdir` 创建 `.claims/YYYY-MM-DD` 取得锁。仅创建成功者持有本次随机令牌，并以 `0600` 写入锁目录的 `owner` 文件。创建失败或所有者记录不完整时停止，回报正在运行或需要核对。不得检查后重建、借用别人的令牌，或用调度的 `.dispatch` 锁代替。
- 取得锁后重查当日报告、缓存和该日所有版本的账本。按端点、参数、字段集、数据日和可验证更新版本复用缓存。每次可能计费的请求先持久化请求身份和「可能已发送」记录，再发送。用同目录临时文件原子更新记录，并同步记录文件和父目录。逐项记录响应、缓存命中和实扣。已完成的请求不重发。发现任何先前已发送或状态不明的请求，先用原响应和账单对账。无法证实未发送且未扣费时，保留 `UNKNOWN`，不得重发该请求或通过改参数绕过对账。
- 锁目录跨工具和 shell 调用持续存在。持有者用本次原始令牌核对所有权，持锁完成对账、请求及报告原子落盘。没有在途请求且本次检查或交互任务已落盘后，仅持有者核对令牌，再删除 `owner` 并用 `rmdir` 释放锁。中断留下锁时，优先继续可核验的原会话。所有权不明或原会话无法恢复时，保留锁及账本并回报人工核对，禁止自动超时接管或由其他会话删除锁。

### 数据日期门槛

- 固定并记录报告截至时间（含时区）。用各市场交易日历和已核实的发布时间规则，独立确定截至此时已应发布的最近交易日及官方榜图的应有日期或版次。历史或修订报告用该报告确认的截至时间。`getUpdateStatus` 只用于观测实际更新，不能决定预期日。发布前仍可用按该规则确认为预期日的上一交易日，例如美国市场当期尚未发布时。
- 榜图用图面日期或可核实日期的版次匹配预期榜图，大类和每个品种的必需行情输入须匹配各自适用的预期交易日。只有已核实某日期确实适用于该大类时才可继承榜图日期。不同市场各自核对，无需相等。任何必要日期或发布规则不明确、实际日期过期、超前或相互冲突时，将受影响的榜图、大类或品种标 `UNKNOWN`。不作可执行开仓或加仓判断，不用旧图、替代榜或顺延大类填补日期缺口。

## 核对与筛选

1. **先核对模拟持仓。** 仅使用明确配置且可信的 Trend V3 `SIMULATE` 来源，或用户提供并明确标识为该模拟盘的私有快照。核实环境、账户归属、时间和快照完整性。不猜路径或账户，不读实盘或旧系统持仓。来源缺失、身份不符、过期或读取不完整时标 `UNKNOWN / 未取得可核实的模拟盘持仓`。只有完整、可信的空快照才写 `已确认无模拟盘持仓`。大类出榜后仍核查已有模拟持仓自身的 ID、市场数据日、价格口径、币种及信号。按同版纪律「清仓 → 退回观察仓 → 止盈 → 加仓」报告首条已核实的动作。高优先级条件、身份、数据或必要仓位事实不明，或标签冲突时写 `UNKNOWN / 人工核对` 及原因。只在私有报告内标识持仓。
2. **选大类。** 用官方金融资产日图 `getTickerTrendPlot(tmId=368431, seq=2, orderType=3)` 核对图面日期、组名、排名和强度。头两名做多，尾两名做空，记录并列和分数。切点或图面证据不明时标 `UNKNOWN`。`10002` 和结构化 18 行均不能替代图面名次。仅在证实某入选大类无可交易品种时按同图顺延，缺失或覆盖不足不能作为顺延理由。
3. **筛成员。** 仅查询通过日期门槛的入选大类。用 `getComponentTicker(tmId=类别ID, getAllBasicComponentsFlag=0)` 取直属成分，只沿已核实的下级分类展开，叶节点返回的所属父类不展开。按 ID 和数据日去重并报告过期、冲突和覆盖缺口。先用 `getTickerSnapshot` 取得身份、`asOfDate`、`trendTemperatureCurr`。首轮日期合格后，仅给做多类当前为「热」或做空类当前为「寒」的成员补取 `trendTemperaturePrev`、`tickerLabels`、`trendStrengthLocalCurr`。两轮身份必须一致，每轮均须匹配该品种适用市场的预期交易日。做多须温→热且带「温转热」，做空须凉→寒且带「凉转寒」。按本类的 `trendStrengthLocalCurr` 排序，做多由强到弱、做空由弱到强，每类最多两个已核实候选。只有经用户明确要求且核实目标页面口径时才换排序口径，报告覆盖范围。保留并列，名次或切点无从核实时标 `UNKNOWN`。
4. **核实品种。** 将直接交易标的与关联标的分列。对外汇先核实直接、反向或代理的经济敞口及方向。篮子货币、间接经营敞口、指数和连续行情等可列在关联栏并写明局限。直接或关联的股票、1 倍 ETF 或期货主力合约纳入可执行候选前，须核实实际标的 ID、按品种所在市场通过日期门槛，并核实敞口及自身适用的转换和标签。货币信号不能代替代理的品种信号。按同版纪律标注其余开仓、加仓和人工执行条件。价格、信号、排名和敞口缺证据时据实标 `UNKNOWN`，不代填。

## 生成私有 HTML

- 保留 [报告模板](assets/report.html) 的标题、目录、样式和原生折叠。浏览器标题附运行日期，首屏写覆盖、结论、各市场数据日和主要待核事项。正文先放默认折叠的完整 `纪律.md`，再按做空、做多、当前实盘持仓、模拟盘持仓情况、当前凯利胜率排列。完整纪律按语义渲染标题、列表、引文和表格，首标题用 `h2#discipline-source-heading`。禁用 Markdown 原始 HTML，转义文本并将链接和媒体降为纯文本，禁止另写一份纪律摘要充当全文。两侧大类独立折叠，有数据时各自第一行默认展开。
- 用 ISO 日期替换模板中的 `{{report-date}}`，用年月日填充页眉日期。复用模板末尾的行结构，将品种列表包在 `<ul class="asset-list" role="list">` 内，按 `<!-- slot:… -->` 填充并移除所有模板节点和插槽。大类摘要列方向内的官方图名次及强度，展开后列直接与关联品种、成员覆盖、品种数据日、价格及币种、转换、标签、类内名次和证据缺口。模拟盘表保留日期、价格口径、币种和费用口径。仅用已核实字段或可复算的值，缺项标 `UNKNOWN`。
- 缺少已核实大类或标的时，在对应栏说明数据缺口或已经确认的空结果。仅给信号已核实的品种使用 `signal` 样式。模拟持仓的方向和盈亏样式按已核实值选择。
- `#live` 只保留标题和空白区域。实盘持仓及其推断不进入模拟盘、候选标记、摘要或其他输出。`#kelly` 只保留「实盘」「模拟盘」标签，两处值永远留空。模拟盘无已核实持仓行时仅显示对应状态，不生成占位持仓。
- 只用 UTF-8、模板内嵌 CSS 和页内导航。所有数据按文本用 `html.escape(value, quote=True)` 或等效方式转义。结构化片段只能由受控标签和转义后的文本生成。费用和证据放在页脚，简列估算、实扣、差额、缓存、未发和待对账请求及官方来源和本地证据位置，均用纯文本。禁止脚本、外部资源和远程链接。落盘前检查数据日、区块顺序、折叠、空白面板、未知状态及隐私边界。
- 以 `umask 077` 将报告和同日证据写入私有报告目录，目录 `0700`、文件 `0600`。在 `_evidence/YYYY-MM-DD/vNN/` 保留最小化输入、脱敏原始响应、只读 API 的调用账本、版本与摘要、费用对账和旧稿。持有同日运行锁，用同目录临时文件原子落盘，覆盖前再核对既有报告及显式修订授权。最后在当前会话回报路径、费用和未解决缺口。落盘失败时直接报告失败。
