# Trend V3 日报

在当前交互式会话完成私有日报。当前范围是股票、1 倍 ETF 和期权的新仓观察，期货、实盘和模拟盘持仓核查、持仓动作与凯利均后置。报告保存在本地。禁止交易、发布、发消息、微信或登录自动化、委派其他 agent，以及改动调度。

先辨明入口。指定固定证据离线成稿或复验时，直接走「离线证据入口」。定时会话按「到点检查与修订」运行。普通交互请求优先复用已有日报，任何查询均受原有授权与费用保护约束。

## 开始与费用控制

1. 用启动消息给出的 Asia/Taipei 运行日，交互请求按指定日期或当日。除离线演练外，定时、手工及修订都在同一主机使用同一个私有目录 `~/.local/share/trend-animals/reports/`。读写报告及同日证据须持该日运行锁。普通交互请求遇已有 `YYYY-MM-DD.html` 时按已有版本回报原路径，新增行情调用为零；旧版仅回报其路径和版本，不读取或复述其持仓。若读取时发现与状态证据不符或下次检查时间已过且无法确认之后进展，指出报告状态待核对。普通手工修订仅在用户明确要求时进行，先说明变更范围和预计新增费用，留存旧稿和证据。启动消息指定的定时会话按下文接管当天检查，包含原路径的数据修订和状态更新。任何入口发可能计费的请求前，都须按「运行锁与共享账本」核对跨日报日证据。
2. 从本技能入口的绝对路径定位所在 OpenTrader 检出目录，或使用启动消息明确给出的检出目录。用 `git -C` 核实根目录及指定的提交，未指定时用该检出目录的 `HEAD`。从同一个完整提交 SHA 读取 `services/trend_v3/.agents/skills/trend-v3-daily-report/assets/report.html` 和仓库根目录的 `纪律.md`，也核对该 SHA 的 `SKILL.md` 与当前指令一致。不依赖启动工作目录，不混用分支或其他检出目录的文件。记录完整 SHA 和三份文件的摘要。缺文件、版本不符或无法确认时回报缺口，停止正常成稿。
3. 按本机私有配置确认 API 权限、允许范围与速率。`TREND_ANIMALS_API_KEY` 从环境或明确配置的私有来源在内存读取，配置文件只解析。只向通过证书校验的 `https://www.trendtrader.cn/apiData/data/` 发送 `X-API-Key`，不随重定向转发。输出、调用参数和证据中不得留存密钥、认证请求头或账户标识。
4. 用 `getSnapshotColumnBilling` 和当前官方价目，按调用、字段集、预计行数、折扣和缓存估算已有授权且确有必要的查询费用，按当前获准频率串行执行。费用上限仅在用户明确指定时适用。遇认证失败、限流、权限、费率、费用或额度不明时停止受影响的付费请求，交已核实部分并标 `UNKNOWN`。

### 离线证据入口

- 用户指定固定证据目录离线成稿或复验时，只使用固定输入、版本核对、日期核对、筛选与成稿步骤。跳过定时和实时取数路径，不访问供应商、行情、价目、账户或调度，不为任何缺项购买数据。只在指定离线输出目录写文件，保持输入只读，跳过正式日报目录和跨日账本。记录证据文件摘要，按证据中的报告日、截至时间、交易日及来源成稿。费用沿用同版证据，新增付费调用为零，缺失的旧费用仍标 `UNKNOWN`。
- 复验未提交的技能候选时，可显式指定同一检出的候选技能、本检出基准完整 SHA 及两个保持基准内容的版本文件。核对模板、纪律与该 SHA 的内容一致，分别记录候选技能、模板和纪律的摘要，以及固定证据版本。将结果标为未提交候选演练，纪律引用仍用其实际提交。普通定时与手工运行用前述提交规则。重复成稿比较事实、名次、状态和费用。

## 定时会话

每天 Asia/Taipei 08:00 启动一个交互式标签。该标签负责启动日的到点检查、等待和原路径更新。晚启动时按实际时间判断哪些检查已到点。先核对交易日历和本地状态，先于应查时点不调用行情或计费接口。

| 市场 | 首次检查时间 | 日历口径 |
| --- | --- | --- |
| A 股 | 启动日 Asia/Taipei 08:30 | A 股交易所 |
| 港股 | 启动日 Asia/Taipei 08:30 | 香港交易所 |
| 美股 | 启动日 America/New_York 08:30 | 美股交易所 |

- 以报告日期构造表中的当地日期及时间，再用 IANA 时区换算。美股夏令时对应台北 20:30，冬令时对应 21:30。A 股、港股和美股分别核对周末、假日及特殊交易日。休市的市场不启动新窗口，其他市场照常。按窗口原定时点和「数据日期门槛」独立确定预期交易日及榜图日期或版次，未能核实的规则或日期标 `UNKNOWN`。美股午夜后的复查继续核对该窗口，仍写原 Asia/Taipei 启动日。
- 在 `_evidence/YYYY-MM-DD/` 随同日证据保存逐市场状态，记录报告日、市场、检查窗口、日历来源、预期数据日和榜图版次依据、最近观测及已验证版本、状态、下次检查。窗口从首次检查时点到该市场下一交易日的首次检查时点，右端点不含。每次检查前核对现在和窗口结束时间。只检查已到点且未结束的市场，跳过错过的复查时点。尚未验证且可安全再查时，从本次检查时点起一小时后再查该市场。下次检查落在窗口外时，结束该市场的复查并保留缺口。已验证、休市、被下一窗口取代或因证据与计费保护无法继续的市场结束本轮检查。证据无法读取、费用未知或不明扣费保留 `UNKNOWN`，禁用需核对的重发。
- 逐市场串行执行检查。定时检查按「运行锁与共享账本」先取共享锁，再取报告日锁。另一会话持锁且可核实仍在检查时，将未能检查的市场顺延一小时并重查窗口，不能核实则按锁规则回报人工核对。每个市场只在当前窗口内启动请求。完成当次请求、落盘及对账后，按相反顺序释放两把锁。等待期间不持锁或留下在途请求。
- 用各未完成市场中最早的下次检查作为唤醒时间，报告当前状态和下一个时点，在同一前台会话定时等待。有 `clock.sleep` 时用该可中断工具，否则用当前会话支持的短段定时等待。仅有 shell 时可在前台使用分段 `sleep`，每段最多 60 秒，保持能处理 Ray 的新消息。醒来或回答 Ray 后，重新读当前时钟和状态，再判断已到点事项。未来仍有检查时保持该轮会话运行，避免空转。不另起调度器、后台服务、标签或 agent。没有待查市场时汇报报告路径（如已落盘）和各市场结果，标签保留供 Ray 追问。

### 到点检查与修订

1. 重查保存的证据及账本。先用获准的最小更新观测判断该市场的预期数据日或可验证版本是否已到。`getUpdateStatus` 只能提供实际更新线索。版本未变、仍旧或暂不可证实，跳过候选复核，记录最近观测及下次检查。按共享账本的规则区分真正新增的版本或观察与旧请求，无法区分时保留 `UNKNOWN`。
2. 仅对首次出现或已变化、且通过日期与身份核验的输入执行后续步骤。按「核对与筛选」核实同一官方金融资产日图的全局头两名和尾两名，记录该图所用交易日或版次，再按「定时到点取数」取得已授权的标的证据。只核对到点市场。不能建立该市场与全局榜图的关系时标 `UNKNOWN`，不按市场重排大类。保留其他市场已有且符合本期范围的证据和事实。若使用过往榜图，标出其版次，不把旧版本候选写为新榜图下已核实的信号。
3. 首次取得已验证数据时生成日报。已验证数据实际变化时，核对现有报告和版本证据，留存旧稿并合并本轮市场变化。无法核实现有报告与证据的对应关系时，停止覆盖行情并回报缺口。保留其他市场的内容、来源、历史和讨论。行情未变但可见状态变化时，按「状态更新」修订同一路径。没有行情或可见状态变化时保持 HTML 不动。

### 定时到点取数

只用于已到点且当期榜图通过日期门槛的市场。每批先核对已有证据、缓存、共享账本、字段费用与已有授权，再串行补齐必要字段。超出授权或无法核实费用、请求身份、版本或响应时，保留已知事实和缺项，按账本规则停止受影响的发送。

1. 对入选大类，使用已授权的 `getComponentTicker(tmId=类别ID, getAllBasicComponentsFlag=0)` 取直属成分。仅沿已核实的下级分类展开，叶节点返回的所属父类不展开。只核对所得直属或下级成分中适用市场的股票、1 倍 ETF，以及已有证据识别的适用市场股票和 1 倍 ETF。未核实的期权身份、行情或资格只列缺项；只有具备已提供且核实的期权自身身份、市场和字段时，才将该证据用于筛选。不同来源的相同标的按身份、市场和数据日去重。成分关系与收藏夹成员关系分别核实。
2. 对尚缺行情的股票及 1 倍 ETF 用 `getTickerSnapshot` 分两轮取最少字段。首轮取身份、`asOfDate` 和 `trendTemperatureCurr`。仅对通过身份和日期核验的标的补第二轮。对做多当前「热」或做空当前「寒」的标的，补 `trendTemperaturePrev` 和 `tickerLabels`。给进入比较范围的已核实组员补 `trendStrengthGlobalCurr`，含当前温度已排除开仓信号的可比组员；符合初筛且需评估方向席位的已知标的也补该字段。第二轮仍须核对同一标的身份与适用交易日。其余标的优先用已有证据核实信号字段；只有在判定信号一致性确有必要且费用与授权均已核实时才补取。字段未齐时可写实际温度及已排除的转换，状态仍按具体缺项判定。缺少比较或资格证据时按「核对与筛选」标缺口。
3. 期货、持仓与凯利不进入本期取数。本期沿用已有直属成分路径和已知标的，收藏夹建议只来自现有证据；新增资产发现、期权研究和收藏夹管理由本期范围之外处理。

### 运行锁与共享账本

- 以 `umask 077` 建立私有报告目录及 `.claims/`，权限 `0700`。用不带 `-p` 的原子 `mkdir` 取得报告日锁 `.claims/YYYY-MM-DD` 和跨日报日共享锁 `.claims/scheduled-check`。定时检查，以及任何手工或修订操作中可能计费的请求，均先取共享锁，再取报告日锁。只读报告、只改 HTML 状态或只写日状态证据时，只需报告日锁。若在持日锁时发现需要付费，先释放日锁，再依次取共享锁及日锁，重新核对两处证据。仅创建成功者持有本次随机令牌，并以 `0600` 写入锁目录的 `owner` 文件。创建失败或所有者记录不完整时停止相应操作，回报正在运行或需要核对。不得检查后重建、借用别人的令牌，或用 `.dispatch` 锁代替。
- 任何可能计费的发送前，持共享锁查询 `_evidence/_billing/` 的跨日报日账本，并检查全部日报日下现有及旧版证据中的请求记录。可用已核对覆盖完整、源记录可访问且尚未变更的索引查旧记录。将旧版的已完成、可能已发和待对账状态及原证据纳入共享查找。若旧记录身份含糊、来源不可读、覆盖不全或存在仍按旧规则执行的会话，先停受影响的付费发送，核对后再继续。无法排除与请求重叠时标 `UNKNOWN`，不把索引缺项当成未发。
- 用供应商作用域、端点、实际目标及有效参数、字段集和可验证的数据日或版本识别逻辑请求。只归并已证实等效的参数表达，保留影响实际请求或计费范围的字段与过滤条件。启动日、报告日、仅用于编排的市场标签、入口、文件夹和本地调用时间不进入身份。复用匹配的已完成响应并保留费用出处。响应不可取时标 `UNKNOWN`，不补发已完成请求。查找时也核对可能覆盖同一计费目标的记录。真正不同的数据日或版本必须有可核验证据，且能证明旧发送不可能取到同一版本。没有版本证据时仍按同一逻辑目标核对。不得通过换日期、市场标签、字段或参数规避尚未对账的发送。
- 对 `getUpdateStatus` 等可变观测，先核实授权、费用和间隔。复用同一观测已完成的结果。仅在前一观测已落盘并核对、确实需要新的观测、且共享账本记录的间隔已到时，为同一逻辑目标登记下一次观测。若前次是否发出或扣费不明，先对账，时间戳或下一个小时不能开启新的计费尝试。只有已核实免费且不会重复待核对的可能计费请求时，才可按到点规则作免费观测。
- 每次可能计费的请求，先在共享账本持久化逻辑请求身份、原日证据定位和「可能已发送」记录，再发送。用同目录临时文件原子更新记录，并同步文件和父目录。共享锁持续覆盖查找、持久化意图、请求及结果落盘。分别记录响应、缓存命中和实扣，日账本引用共享记录。响应或账单暂缺时，落为 `UNKNOWN` 并记录待对账依据后可释放锁。恢复时先核对原响应和账单，不以另一笔已完成记录结清待核对请求。无法证实未发且未扣费时，不得重发该请求。崩溃在意图写入与结算之间，仍视为可能已发送。
- 锁目录跨工具和 shell 调用持续存在。没有在途请求且意图及最后已知结果已落盘时，仅原持有者核对令牌，再删除 `owner` 并用 `rmdir` 释放锁。中断留下的共享锁或日锁，优先交原会话核验和恢复，所有权不明或原会话无法恢复时保留锁及账本并回报人工核对。禁止自动超时接管、替其他会话删除锁或在等待时持锁。

### 数据日期门槛

- 固定并记录报告截至时间（含时区）。用各市场交易日历和已核实的发布时间规则，独立确定截至此时已应发布的最近交易日及官方榜图的应有日期或版次。历史或修订报告用该报告确认的截至时间。`getUpdateStatus` 只用于观测实际更新，不能决定预期日。发布前仍可用按该规则确认为预期日的上一交易日，例如美国市场当期尚未发布时。
- 榜图用图面日期或可核实日期的版次匹配预期榜图，大类和每个品种的必需行情输入须匹配各自适用的预期交易日。只有已核实某日期确实适用于该大类时才可继承榜图日期。不同市场各自核对。必要日期缺失时用 `UNKNOWN`，已知但不符的实际日仍如实显示，并给出预期日期和原因。受影响的证据不得用于新仓判断或比较，不用旧图、替代榜或顺延大类填补日期缺口。

## 核对与筛选

1. **选大类。** 用官方金融资产日图 `getTickerTrendPlot(tmId=368431, seq=2, orderType=3)` 的证据核对图面日期、组名、全局名次和强度。按入口使用固定证据或复用已核实响应，定时到点时只在已有授权及费用保护允许下查询。头两名做多，尾两名做空，记录并列和分数。切点或图面证据不明时标 `UNKNOWN`。`10002` 和结构化 18 行均不能替代图面名次。保留官方榜图头尾的原始席位。只有期货、缺少合格标的或覆盖不足时，在该大类原位说明已证实的事实和缺口；有证据支持的关联标的另列，不顺延替换原席位。
2. **核对标的证据。** 使用离线输入或既有授权路径取得的分组、身份、经济敞口、覆盖和行情证据。来自 #512 的可用证据可补充，采用其已经核实的事实；日报可独立成稿，不依赖 #512 的文件格式或额外发现。按市场及经证实的标的身份和数据日去重，核对适用市场预期日期、标的自身 `trendTemperaturePrev` → `trendTemperatureCurr` 及 `tickerLabels`。显示直接、反向或代理的敞口及其出处，保留已核实的关联和局限。股票、1 倍 ETF、期权都必须有自身信号。标的自身信号缺失时，货币、指数、ETF 或期权底层资产已有的信号只能作为明示归属的背景。期权只列可用标的代码和市场及自身信号，Ray 手选行权价、到期月和张数。
3. **记状态和资格。** 每行用下表的具体状态，保留已核实的身份、日期、敞口或信号。缺失字段标 `UNKNOWN` 并注明缺项。「证据不足」仅统称表中后六种状态。只有「已触发」且已核实符合交易资格的标的可入新仓区。信号已核实、资格待核时写「部分待核」，保留已知信号并点明缺项。信号已核实且已明确不符合资格时，保留「已触发」、数据日、标的自身转换和标签，另写「开仓资格：不符合」及具体原因。

| 标的状态 | 判定 |
| --- | --- |
| 已触发 | 身份、敞口和数据日已核实。做多为自身严格温→热且带「温转热」，做空为自身严格凉→寒且带「凉转寒」。 |
| 核实后未触发 | 身份和日期相符，信号字段一致，未出现该方向的开仓信号。 |
| 信号冲突 | 温度转换与标签不一致。 |
| 日期不符 | 必需数据日过期、超前或缺失。写明实际日和预期日。 |
| 平台未覆盖 | 有证据证实平台无此标的。 |
| 敞口未核实 | 标的身份或经济敞口缺少可核实的出处。 |
| 部分待核 | 保留已证实的事实并点出仍缺的字段或资格证据。 |
| 未查询 | 写明因覆盖或费用而跳过的范围。 |

4. **计算方向名次。** 每个大类对应一个收藏夹分组，例如「V3-美元」。用该组可比成员的标的自身 `trendStrengthGlobalCurr`（记为 G）。多头名次为 1 加组内 G 严格较高的标的数，空头名次为 1 加组内 G 严格较低的标的数。同名次按代码字母序展示。按各成员适用的数据日和同一比较口径核实 G 与组员身份。可比成员即使未触发或明确不符合开仓资格，仍计入组内名次。分开标记已收藏成员与拟加入标的。拟加入标的若有经核实的自身 G 且有可比组员，可标明相对已核实组员的参考位置，不能把它计为已有组员或把参考位置写成正式组内名次。标出分组、数据日、计入范围和漏项；已经能计算的名次须注明其仅适用于可比范围。缺少必要数据时保留已知事实，名次标 `UNKNOWN`。小程序 0–100 页面整数的分位和舍入规则未公开。
5. **列新仓和收藏建议。** 在大类内设「新仓观察」。A 股股票即使自身做空信号已核实，本期也不符合做空开仓资格。选前两席之前就从做空候选中剔除，证据行写「开仓资格：不符合（本期 A 股股票不列做空新仓）」。资格根据实际交易标的的市场与品种核对。另行核实的期权和其他市场代理按各自的身份、资格及自身信号判断。

   只对已触发、符合资格且有已核实 G 的标的按多头 G 从高到低、空头 G 从低到高，同值按代码字母序，每类最多两个。名单保留其原组内名次或已注明的参考位置。第 2 席遇并列按代码取满，其余在观察证据中标「并列未列入」。比较范围不完整时注明查了什么、漏了什么，已核实的候选仍可在证据支持的范围内列出。覆盖完整且核实零触发时写「已核实空结果（确认触发 0）」。覆盖完整且确认有触发、但均明确不符合资格时，写「确认触发 N，符合资格 0」并列排除理由。已知信号或资格、日期、强度等判定有待核实而无可入列标的时，写「当前证据无可列候选」，保留已知信号事实及具体缺项。另列「建议加入收藏夹」，写明建议分组及理由，交 Ray 手工添加。收藏建议不改变已核实的成员身份和开仓资格。分列接口或来源事实、计算名次和按纪律得出的新仓判断。

### 标的字段来源

- 为用于前温、当前温度、标签、G 与特殊信号的每条实际记录分配简短、易读的私有证据编号，例如 `R17`。将编号与脱敏本地文件的固定版本及文件内的精确记录位置一并保存，例如数组下标或记录键。核对记录对应的标的身份、市场、实际数据日和字段。即使同一标的同一天，来自不同记录的字段也分别引用各自的编号。仅当同一条记录确实支持多个字段时才共用编号。
- 复用已有编号，同版复验、只改状态及合并其他市场时保持编号和记录对应关系。改用新版本的记录时分配不同编号，即使字段值相同。保留旧稿及其证据索引，已用编号不改绑、不回收。编号不依赖当前报告的行序、市场检查顺序或显示名次。
- 字段或可核实的源记录缺失时，对相应字段或来源标 `UNKNOWN` 并说明缺项，保留其他能核实的字段。无法核实来源的字段不用于确认信号或计算名次。无标签也须有相应记录，不能把缺失标签写成「无」。只依据现有脱敏证据，不按代码与日期猜测来源，不为补编号调用供应商。本技能可用已有文件形式记录对应关系。
- 特殊信号逐项核实。现有记录中的标的自身当期事件标签、事件专用布尔值或其他经核实的事件字段均可作证。确认字段的含义、标的身份、市场和数据日，再记录每项事件的结论、实际字段和对应证据编号。遇到缺字段、覆盖未证实或同一事件证据冲突时，将该项标为 `UNKNOWN`，保留其他独立确证的事件。只有已核实证据覆盖该标的所有相关事件字段且逐项都有明确阴性时，才显示「无」。空或缺失的 `tickerLabels` 只说明标签证据的状态，不能证明没有事件。使用现有证据，缺项时不追加查询。

## 生成私有 HTML

- 保留 [报告模板](assets/report.html) 的标题、目录、样式和原生折叠。用 ISO 日期替换 `{{report-date}}`，在默认折叠的「市场数据与日期」填入报告日、各市场数据日、范围、结论和待核事项。页首仅保留简短的市场状态提示，具体时间和原因放到展开区。正文先放默认折叠的完整 `纪律.md`，再按做空、做多、当前实盘持仓、模拟盘持仓情况、当前凯利胜率排列。完整纪律按语义渲染标题、列表、引文和表格，首标题用 `h2#discipline-source-heading`。禁用 Markdown 原始 HTML，转义文本并将链接和媒体降为纯文本。
- 在各大类默认可见区用 `candidate-pattern` 只展示已入选新仓的标的。标题写代码和名称，例如「MOL-OPT · 能源期权」。标题下恰好三个值和一句中文入选理由。「当前趋势」取标的自身当前温度。「特殊信号」列已确认的当期事件，例如「温转热」「凉转寒」「开香槟」「上天台」，多个事件用「、」分隔。有已确认事件且其他项待核时，在同一个值内加「（其余待核）」。尚无已确认事件且覆盖不足时写 `UNKNOWN`。特殊信号的展示与开仓资格分别判定，「开香槟」「上天台」等止盈事件不能当作开仓触发。「强度」按原值写「G / 100」，例如「9 / 100」，保留原精度。理由写清入选依据并避免复述数值或标签；有覆盖缺口时限定为已核实的比较范围，只有覆盖与排序证据支持时才写「最强」。
- 保留 `class-pattern` 中默认折叠的「分组与标的证据」。展开后显示大类图名次、强度、点名对应榜图日期或版次，并保留选中席位、其余直属及关联标的证据、空结果或覆盖缺口与收藏建议。同一标的默认只显示一张卡，按已核实的标的身份及市场去重；如属多个组，保留各组证据与实际席位。选中标的的详细行留在对应组展开区，默认视图内不重复代码或标签。将品种列表包在 `<ul class="asset-list" role="list">` 中，填充并移除所有模板节点和插槽。
- 在大类展开区写明收藏夹分组、适用数据日、实际可比范围、缺项和名次口径。G 是标的自身的 `trendStrengthGlobalCurr`，多头名次 = 1 + 组内 G 严格高于该标的的个数，空头名次 = 1 + 组内 G 严格低于该标的的个数。注明小程序 0–100 页面整数的分位和舍入规则未公开。展开后的标的证据行显示代码、市场、数据日、身份与关联依据、自身转换、标签、全局强度、组内方向名次、开仓资格及具体原因。价格与币种据可用证据显示。仅给已触发且已核实符合资格的证据行用 `signal` 样式。
- 在每条展开的标的证据行就地列前温、当前温度、标签和 G 的来源编号，并逐项列出已确认特殊事件的字段与对应编号。标「无」时在展开区列出已核实的事件范围和逐项阴性依据。有未知项时说明哪些事件缺证据。默认卡片中的值可通过展开同组证据追溯，默认不显示日期、名次、编号、费用或技术说明。页脚在默认折叠的费用下列私有证据索引，将每个引用编号映射到实际存在的脱敏本地文件版本与精确记录位置，附标的、市场、实际数据日和该记录支持的字段。索引使用纯文本，排除密钥、账户标识、远程链接与资源。背景信号的出处不能充作标的自身字段的来源。
- 完整引用的纪律是版本文档。在「市场数据与日期」注明本期只覆盖股票、1 倍 ETF 和期权。保留 `#live`、`#simulation`、`#kelly` 标题，各标题下恰好一行「本期不含持仓」，用单个段落代替模板保留区、模拟盘插槽和凯利列表。禁止读取持仓或账户仓位来源，不用持仓做候选筛选，不输出持仓动作或凯利值。既有授权的只读费用对账只取必要扣费证据，不读取仓位或留存账户标识。
- 只用 UTF-8、模板内嵌 CSS 和页内导航。所有数据按文本用 `html.escape(value, quote=True)` 或等效方式转义。结构化片段只能由受控标签和转义后的文本生成。费用和证据放在页脚，保留估算、已核实实扣、可复算差额、缓存、未发、待对账请求、来源及证据位置，均用纯文本。费用缺项标 `UNKNOWN`，待对账金额不记为零，也不当作实扣。禁止脚本、外部资源和远程链接。落盘前检查日期、区块顺序、折叠、三处持仓状态、未知状态及隐私边界。
- 以 `umask 077` 将报告和同日证据写入私有报告目录，目录 `0700`、文件 `0600`。在 `_evidence/YYYY-MM-DD/vNN/` 保留最小化输入、脱敏原始响应、同日报告引用的共享账本记录、版本与摘要、费用对账和旧稿。持有同日运行锁，用同目录临时文件原子落盘，覆盖前再核对既有报告、适用证据和修订授权。最后在当前会话回报路径、费用和未解决缺口。落盘失败时直接报告失败。

### 状态更新

- 定时会话发现可见状态、原因或下次检查变化时，持日锁先保存状态证据。已有 HTML 时更新同一文件的市场状态及证据摘要。已核实、休市、窗口到期或因证据、费用无法确认而终止的市场写实际结果及原因，清除该市场下次检查时间。其他仍可检查的市场保留各自时间。页首可简示状态；完整覆盖、日期、原因及下次检查时间放入市场和页脚的展开区。
- 只更新状态时，核对日期、模板结构和可安全更新的状态位置，留存旧稿，原子更新原路径。保留行情、信号、名次、覆盖口径、费用、原来源及版次、字段来源编号与证据索引、历史和讨论。保留讨论正文时仍按纯文本转义规则渲染。已有行情证据缺口应标 `UNKNOWN`，不能据此替换或补造行情。状态更新不访问供应商，不产生额外费用。比较 HTML 当前可见状态与证据中的应显示状态，两者一致时不重写、不开新版本。若状态已落盘但 HTML 更新中断，下一次可恢复操作据已保存状态补写，不重复数据请求。无法安全核验或合并原文件时，保留文件并明确回报状态未同步及原因。旧版含持仓的 HTML 不作为本期成稿；保留旧稿，状态单独落盘并注明未同步。
- 始终没有可用数据且未生成 HTML 时，在状态证据和会话中明确回报「未生成日报」和各市场的终止原因。已有文件但没有可用行情时，注明无可用数据和原因。本轮没有可用数据时不报成功或显示已核实行情结论。
