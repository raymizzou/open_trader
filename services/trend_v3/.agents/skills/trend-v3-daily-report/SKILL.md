# Trend V3 日报

在当前交互式会话完成私有日报。当前范围包括股票、1 倍 ETF 和期权的新仓观察，以及入选大类本身作为交易品种时的当期特殊信号观察。持仓对账与凯利数据后置。模拟盘首开仅由正式定时 tab 交接同版模拟开仓技能，其他日报入口只读。实盘与凯利各保留原占位；没有已核实的模拟状态时保留模拟盘占位。正式阅读文件先在本地核对，再按「读取、修订与同步」交付。禁止本技能直接交易、未经授权发布或发消息、未经授权的微信自动采集或登录自动化、委派其他 agent，以及改动调度。

先辨明入口。指定固定证据离线成稿或复验时，直接走「离线证据入口」。定时会话按「定时会话」运行。普通交互请求按「读取、修订与同步」处理；普通首稿、复用、修订和历史离线的截至基准统一按「适用数据日期」核对。每次日报交付以适用于请求报告日及其截至时间的可用证据成稿，交付一份保留 V1 阅读版式的现行 HTML。定时首版立即用可用证据成稿，不因缺项等待。定时会话在交付后按下文逐小时核实完整性；普通读取和离线成稿不启动轮询。任何查询均受原有授权与费用保护约束。

## 视觉取证与行情费用

每次需要采集或重做日报时，按下文版本规则核对并读取同版[趋势动物视觉下钻技能](../trend-animals-visual/SKILL.md)，作为正式日报的视觉取证入口；缺失或不符时按视觉证据缺口处理。日报复用与离线演练仍按各自入口执行，离线不启动现场或 API 取证。以原报告截至时间核对同日或适用市场数据日；保留画面观察时刻，收盘后看到的页面不能回填早于该时刻的早报。后台自动操作微信须符合本机采集 SOP 的 E17 条目 已核实的服务方范围；未核实前，定时会话复用已获准且符合截至时间的视觉证据，有缺口即在当期报告注明。独立重跑按本次明确的截至时间或可复用数据日期核对，保留正式日报原件。交互式现场核对按 Ray 当次要求执行。登录提示交给 Ray。

新版正式日报使用 `selection_mode: "threshold-v1"`：先独立冻结截至时间内完整金融资产母榜，≥80 做多、≤20 做空，含边界和零分，保留全部入选大类。按同版视觉技能的「方向信号榜交叉验证」搜索温转热／凉转寒，仅查有入选大类的方向。完整搜索结果决定适用市场组合，不默认每个市场都有两种榜；同版同范围信号榜只读一次。用独立直属证据与在榜且有自身方向标签的成员取交集。部分覆盖保留已证命中与待核，双方完整且无交集才报无命中。关联榜排名路线仅供明确点名或研究，不阻塞本路径。旧报告未声明选择版本或显式 `legacy-two-seat` 时继续按原双席契约读回，不静默迁移原件。

只给交集中的原已核实直属卡补信号榜名、标签和数据日；原有其他直属卡继续按自身证据展示。搜索命中不证明归属，标签不证明严格转换或交易资格，模拟盘选中更须保留原始证据。结果复用现有方向面板、三块结构与模板，不截短入选大类、不另加导航或 section。信号字段和双强度逐项核实，缺项按既有规则遮蔽。11/25 20:00 的节气榜观察不回填早报，也不能证明新方向榜成员；新增榜和直达路径未现场核实时明确待核。

官方行情使用本节费用规则：已核实整笔免费的请求可以直接执行，按字段计费且本次全免也可直接执行。费率或字段不明先通过已知免费价目核价；任何可能收费的调用（含榜图和成分），先在日报 tab 说明目标、字段、次数、估价及用途，等 Ray 对这次查询明确批准。尚未批准仍交付可用内容；排程、以往付费同意和缓存命中预估不构成本次授权。明确纯视觉及离线入口继续使用其限定来源。此规则覆盖本技能中对“已授权采集／费用”的旧默认解释。

## 开始与费用控制

1. 用启动消息给出的 Asia/Taipei 运行日，交互请求按指定日期或当日。除离线演练外，定时、手工及修订都在同一主机使用同一个私有目录 `~/.local/share/trend-animals/reports/`。读写报告及同日证据须持该日运行锁。普通手工修订仅在用户明确要求时进行，先说明变更范围和预计新增费用。启动消息指定的定时会话按下文接管当天检查、同日修订和私有状态更新。任何入口发可能计费的请求前，都须按「运行锁与共享账本」核对跨日报日证据。
2. 从本技能入口的绝对路径定位所在 OpenTrader 检出目录，或使用启动消息明确给出的检出目录。用 `git -C` 核实根目录及指定的提交，未指定时用该检出目录的 `HEAD`。从同一个完整提交 SHA 核对本技能的 `SKILL.md`、`render_report.py`、`assets/report.html`、同目录 `collection.py`、仓库根目录的 `纪律.md` 及相对路径 `../trend-animals-visual/SKILL.md`。使用与该 SHA 字节一致的文件，记录完整 SHA 和六份文件各自的摘要及核对结果；视觉技能缺失时记录缺失，不伪造摘要。独立发布包须包含上述六份文件，保留日报技能与视觉技能的同级目录、模板子目录及纪律相对仓库根的位置，使相对链接仍可解析。不依赖启动工作目录，不混用分支或其他检出目录的文件。原有五份基础文件任一缺失、版本不符或无法确认时，仍回报缺口并停止正常成稿。仅视觉技能缺失、字节不符或版本无法确认时，不加载该文件、不从其他版本补入，不启动新的视觉取证；记录视觉证据缺口，在基础文件核验通过后继续从可用合格证据成稿，按实际缺项交付不完整报告，不以此延迟可用首版或声称视觉覆盖完整。
3. 按本机私有配置确认 API 权限、允许范围与速率。`TREND_ANIMALS_API_KEY` 从环境或明确配置的私有来源在内存读取，配置文件只解析。只向通过证书校验的 `https://www.trendtrader.cn/apiData/data/` 发送 `X-API-Key`，不随重定向转发。输出、调用参数和证据中不得留存密钥、认证请求头或账户标识。
4. 用 `getSnapshotColumnBilling` 和当前官方价目，按调用、字段集、预计行数、折扣和缓存估算已有授权且确有必要的查询费用，按当前获准频率串行执行。费用上限仅在用户明确指定时适用。遇认证失败、限流、权限、费率、费用或额度不明时停止受影响的付费请求，保留已核实证据，缺项标 `UNKNOWN`，继续用可用证据成稿。

### 离线证据入口

- 用户指定固定证据目录离线成稿或复验时，只使用固定输入、版本核对、日期核对、筛选与成稿步骤。跳过定时和实时取数路径，不访问供应商、行情、价目、账户或调度，不为任何缺项购买数据。只在指定离线输出目录写文件，保持输入只读，跳过正式日报目录、跨日账本和报告日运行锁。正式日报的本地重排不属于固定证据离线入口：仍在原私有目录持报告日锁处理，零新增请求。按原报告日和截至时间核对事实，私下保存证据摘要、来源和费用；新增付费调用为零，缺失的旧费用仍标 `UNKNOWN`。重复成稿核对阅读文件的候选与事实，并在私有证据核对来源、名次和费用。
- 复验未提交候选时，可显式指定同一检出的候选日报技能、渲染器、模板、collection.py 及相对路径 `../trend-animals-visual/SKILL.md`，并记录基准完整 SHA、这五份候选文件各自的摘要及相对布局、纪律的实际提交及摘要、固定证据版本。逐份核对基准提交字节与候选字节，列明有意修订的文件及差异；未改文件须与基准一致。候选视觉技能缺失或身份不符时，同样只记视觉证据缺口，不借用其他版本，不阻止基础文件合格的离线不完整成稿；原有基础文件前提不变。候选和证据身份只记在私有验证记录。定时与手工运行仍用前述固定版本规则。

## 定时会话

启动交接保留原正式交互 tab 和本日会话身份。当正式发布包含纸盘计划入口时，在适用正式报告版本交付读回后，从同一提交调用 [Trend V3 模拟盘首次开仓](../trend-v3-paper-entry/SKILL.md)。盘前计划与结果都留在此 tab。在原 tab 展示可核验的盘前计划，收到明确用户回复后才记录批准，并由该 tab 的受监督命令等待相应市场开盘。收到撤回立即记录。日报版次变更后重新展示计划并取得新回复。该入口只读取原日报和模拟盘执行条件，不增加趋势数据请求、费用、调度或新 tab。未启用、证据不足或错过开盘时在原 tab 标明。历史读取及离线入口继续复用已经核实的同版报告，不启动纸盘入口。

每个日历日（含周末及股市假日）Asia/Taipei 08:30 首版立即交付；晚启动只补当前轮，不补历史轮次。缺项时页头显示「数据收集中」，列具体工作项、目标日、实际日及下一次核实时间。08:30、09:30、10:30 等为锚定时点，跨午夜继续原报告日。全部证据核实并交付当前完整 HTML 后显示「数据已完备」与核实时间，停止监测，保留交互标签。

- 使用同版 `collection.py` 的正式命令，不以文字约定代替执行控制。报告日开始时，按「适用数据日期」将已核实日历保存为 `calendars.json`：连续市场 `kind: continuous`；股市 `kind: equity`、`sessions`（已确认交易日）、`covered_through`（完整日历覆盖末日）；均含 `source`。`targets` 命令按 D−1 计算连续市场，按各市场日历取不晚于 D−1 的最近收盘日；覆盖不足或来源不明返回 null。榜图目标独立核实，版次不等于图面数据日。把结果保存到投影 `collection.targets`，未知为 null，不得猜测；已确认日期冻结。
- 在 `_evidence/YYYY-MM-DD/` 持日锁运行 `init`，保存本日控制文件。恢复先读此文件及共享账本，复用已核实缓存、响应与原日目标，不滚动到新日。已有旧版报告也须先交付可用首版，再建工作清单；旧报告不能凭缺项列表为空成为完整。
- 各轮先运行 `claim --now <带时区实际时间>`。返回 null 不取数。持久化成功才处理返回的当前 slot；已过小时不追赶、同 slot 不重发。`markets` 是仍待核实市场集合，每轮至多一次已有授权的 `getUpdateStatus` 覆盖这些适用市场（BOARD 先映射已核实供应商榜图范围，不作为臆造的 API 参数）。集合为空只处理尚未完成的交付。返回 `changed` / `affected_groups` 指明变动字段与相关结论，重核变化及其直接依赖，不为已核实且来源未变的项重复请求。控制文件的本地重算不产生请求。
- 共享锁→日锁→重读共享账本和本轮状态后才发送获准请求。`claim` 自身不是费用授权或账本锁；“已认领”后的崩溃仍须核对原发送，不能用下一 slot 绕过 UNKNOWN。每次更新观测和响应保存原始私有记录与账本定位。先复用缓存，更新发布时间不证明标的字段已齐。迟到发布仅补原目标日；请求范围、费率、强度/BTC 限制和未知不重放规则不变。
- 将响应中的变化逐项核实后更新投影及其证据，再 `assess`、渲染并交付整份 HTML。报告数据、字段日期和完整性不能仅凭新发布标记、布尔值或空 missing 数组断定。每轮保存投影及账本关联，部分成功仍保存已证事实。任何保存/渲染/同步/读回失败都不能标监测完成；只重试文件处理，不重取已发送行情。
- 本轮无在途请求、证据和未知状态已落盘时释放各锁。使用当前会话的既有可恢复等待机制等下一锚定点，不另建调度/agent，不在等待时持锁。普通读取、离线入口、已最终交付的报告均不启动轮询。
- 完整报告交付后调用 `confirm`，逐字节读回本地及获准目标文件；任一不存在、落后或不同均失败。完成记录绑定当前投影摘要，证据修正/撤回使旧完成失效，重新按当前 slot 核实。只读入口仍不轮询。

```sh
python /绝对同版路径/collection.py targets calendars.json
python /绝对同版路径/collection.py init reader-projection.json --state control.json
python /绝对同版路径/collection.py claim reader-projection.json --state control.json --now 2026-11-23T09:30:00+08:00
python /绝对同版路径/collection.py assess reader-projection.json
python /绝对同版路径/collection.py confirm reader-projection.json --state control.json --local /本地/2026-11-23.html --delivered /已授权目录/2026-11-23.html
```

### 离线交叉验证入口与版本契约

`python /同版路径/collection.py search-plan search-input.json` 只读本地 JSON、向 stdout 输出规划和逐类交集，零网络、不轮询、不操作交易。输入字段：

- 可选 `targets: {市场: 适用日}` 由已核实日历独立提供；节假日市场数据日可异于母榜日，成员和归属均按其市场目标核对，缺市场目标沿用输入已确认的母榜适用日，显式 null 保持待核。正式报告边界始终使用 collection.targets 冻结目标重算搜索；signal_search 显式目标与冻结目标不一致时保留已核实事实并记待核，不终止小时复查。每份直属清单用 `markets: [{market, instrument_type}]` 声明自身覆盖范围，空清单也一样；其单一 data_date 仅证明其中目标日相同的组合，先分清单验日，再合并完整覆盖。美股休市目标日和港股目标日不同时，分别保存对应范围／日期的两份清单，不要求一份日期同时等于两个市场目标。仅当该大类只有一个已核实市场×品种组合时，兼容旧省略 markets 的清单；多市场／多品种省略声明即待核，不能把歧义空清单广播给全部市场。`cutoff` 为带时区截至时间；`board` 为独立完整金融资产母榜，含 `state: verified`、`complete: true`、`source`、`observed_at`、`data_date`、`version`、`groups: [{name, strength}]`。数字可以为零，不能从信号成员生成母榜。
- `group_markets` 为独立映射数组：`group`、`state: verified`、`source`、`complete`、`markets: [{market, instrument_type}]`。多对多允许，缺映射保留缺口。
- `boards` 每张含 `board_id`、`title`、`direction`、`label`、`version`、`data_date`、`observed_at`、`source`、`state`、`complete`、适用 `markets` 和 `members`。成员行显式给出的 `data_date/version/state` 必须与适用范围一致，不得由外层榜覆盖陈旧行；`labels` 必须为完整字符串数组，禁止子串匹配。信号榜同样只把其声明范围内、data_date 与该市场冻结目标相符的组合计入覆盖；同榜其他组合未适用或目录承诺与读回矛盾时记待核，其他榜不能代替该榜的范围证明。成员逐行含 `instrument_id`、`code`、`market`、`instrument_type`、`labels`、显式 `removed: false/true`，可选 currency。同身份同类多源合并；其他榜退出状态不取消本榜阳性。
- `memberships` 含 `group`、独立 `source`、同版同适用日的 `version/data_date/observed_at/state`、明确覆盖的 `markets`、`complete` 及独立身份 `members`；不得与信号榜使用同一名单来源。`search_coverage` 按方向记录完整搜索结果，含相同范围元数据和 `boards: [{board_id, version, markets: [{market, instrument_type}]}]`；每张目录项分别保留其与该类相交的市场×品种组合；同 ID／版次读回必须覆盖这一张榜承诺的组合，其他榜的覆盖不能代替。只有已核实适用组合与该类相交的目录项才安排读取；未知映射只记缺口，不猜市场。缺失、改版、晚于截至时间及分页未完分别保留待核。
- 输出 `searches` 为要执行的唯一关键字设计，`boards_to_read` 为尚需读取的唯一榜／版次，`groups` 含 `hits`、`gaps` 和 `status`。`metrics` 是离线设计／留存证据计数；`elapsed_seconds: null` 表示没有现场耗时，不能称实际节省。实际搜索／读取／额外归属查询和耗时由现场执行者另记。

独立直属清单的 `state: "withdrawn", members: []` 是来源范围撤回，不需要重复列出旧成员。按相同 group、source、version、data_date 及所声明 markets 取消该来源的成员阳性和完整覆盖（含旧完整空清单），与先后顺序无关；不得借旧空清单结案。只撤回该市场×品种，其他市场、日期、版次、大类与其他来源独立。多市场撤回缺少或矛盾的范围时，不猜成全量有效覆盖，而保守停用该来源同适用日可能受影响的范围；不能由此确认成员或无命中。仍有独立、完整且适用的其他来源时，按其确证成员与覆盖保留命中和完备；只有部分证明时保留已知命中及具体缺口。带非空成员的撤回继续逐成员处理，不扩大为其他成员的撤回。撤回不授权追加查询。

将上述原始输入保存在报告私有 `signal_search`，公共渲染器会重新算交集，只给身份完全匹配且 `direct_verified: true` 的原卡添加来源；不复制行情、事件或观察资格。旧卡的实际日期、市场目标或最终 lookup 调解冲突时不添加当前信号阳性。新增卡仍须正常独立核实、填入原投影与逐字段证明；不能把 planner 输出当作全部字段证明。

新版投影还须有 `cutoff`、`board_date`、`board_version`，以及 `collection.parent_board`（母榜字段另含 `row_count`）。母榜独立完整且日期／版次适用，`assess` 才按完整母榜检查应出现类、强度、顺序和方向序号。`init` 冻结选择版本、截至时间和已核实母榜事实。首版母榜未知或部分覆盖时保留缺口；之后可首次补入截至时间内已有的完整独立母榜，不改既有行、来源、日期与版次；同 slot 保存补证但不重放请求。完整母榜确认后 `claim/confirm` 不得改写。新版所有相关方向／大类必须有 signal_search 覆盖，已证明交集必须在实际独立核实直属卡中出现。缺类、漏命中、缺搜索或母榜缺证不能完备，就地显示缺口及截至时间；空方向可以成立，前提是独立母榜确无阈值入选类。历史控制文件与旧双席输入继续按原规则读回。

模拟盘仍只识别母榜可独立重建的原头尾各两席。新增类和仅标签行不扩充候选，原严格转换、身份、日期、覆盖和原始字段保护不变；原双席无法证明就报缺口。此兼容不授权新策略、委托、调度或上线。

### 完备工作清单与字段证据

初次 `init` 允许未知目标，不因日历缺项延迟首版。后来首次确定 null／新增市场时，在 `collection.target_evidence[市场]` 提供 `{state: "verified", report_date: 原报告日, basis_date: 原报告日D−1, source: 可回溯日历来源, kind: "equity"或"continuous"}`；股市另含 `sessions` 和 `covered_through`。交易日列表不得超出原 D−1；覆盖须到该日，按同一 D−1／最近收盘规则重算后严格等于拟定目标。既有初始非空目标仍兼容，但不能晚于 D−1；显式提供的初始日历证明也须匹配。`init`／`claim`／`confirm` 在 state_lock 下校验并原子保存首次确定及证明，不替换或删除已确认日期。无证明、不适用原报告日或未来目标一律拒绝，保留原控制状态；同 slot 的日历补证可以保存，但不授权重放请求；首次确定目标会把相关缓存字段及分组列为待重核，保留至下一有效 slot，不要求响应字节先发生变化。

`collection` 是私有投影元数据，只公开适用日期、总体状态、就地缺项和适用时间，不公开路径/请求/账本。包含 `targets`、`worklist`、`evidence`、`next_check`、`verified_at`。所有必需项逐项入 `worklist`，每项为 `{path, label, market, target_date}`；path 是当前投影的位置，如 `/long/0/searchable/0/strength`。已确认目标不变；null 或新增市场可在原报告日下首次核实，规则如下。清单不能缺失、重复、少项或留下未决额外项；名单/排序调整后同步迁移 path 和证据，不按旧位置继承。

必需项由程序从实际报告枚举：`/board_date`、`/board_version`，两方向所有入选大类的 `board_strength` 和 `coverage`（旧版仍为各 1/2 席），以及每卡的 `trend`、`strength`、`local_strength`、`signal_events`；查询卡改为其 `lookup`。每类 `coverage` 为 `{state: "complete", instrument_ids: [...]}`，按 direct/searchable/related 原序列出核实名单身份，空名单也须有完整查询证据，不能用无卡片证明完整。尚未完成的目录/候选查询列为额外工作项；查完后更新 coverage 和正式清单，保留原记录历史。

`evidence[path]` 每项含 `{state: "verified", data_date, version, source, identity, value}`（标的字段另含匹配的 `market`、`instrument_type`），来自可回溯且已核实的响应；value 与当前投影字段严格相等，source 不为空，版次/日期适用，身份匹配。榜图 identity 为 `board`；大类用其核实名称；标的用显式 instrument_id，market/type 同时核实。在含 `collection` 的投影中，查询 `miss` 必须有该 path 的证明、非空有效目标与身份、完整 market/type、匹配日期和值，另须 `full_lookup: true` 且来源确实覆盖完整适用查询范围；无证明、null 对 null 或范围缺失显示「待核」，不显示「查不到」。不含 `collection` 的旧格式仍按已核实显示投影兼容，不能借删除 collection 绕过新证据规则。pending/未知、分页不全、仅发布时间都不终结。不得为让校验通过伪填来源或值。`verified_at` 是最后逐项核实完成的带时区时间，不是启动或发布观测时间。

显式查询范围的阴性回执还须独立绑定 `lookup_scope`，此为私有证明契约，不进入阅读文件。报告行声明范围时，回执若带 `lookup_scope`，必须与行的完整范围严格相等，不能只匹配版次或子串。仅完整的 `YYYY-MM-DD/版次` 形式可由回执实际 `data_date` 与 `version` 联合证明；即使显式范围相等，回执字段与该标准形式矛盾也拒绝。其他 opaque 范围（如含截至时间或目录标识）不解析或猜测，必须由原回执独立记录完全相等的 `lookup_scope`，不能从报告行反填。范围矛盾、部分缺失或无法绑定时显示「待核」，也不能豁免最终卡片字段或完成采集。无显式范围的旧单卡完整证明及无 `collection` 的旧展示投影仍兼容，其他身份、日期、完整范围和冻结目标检查不变。

每类及卡片独立填明确 `data_date`（不得从任意榜图/市场/报告日继承）；显式 collection 中，卡片 data_date 自身未知、无效、早于或晚于目标日时，所有行情／事件均不能作为当前值或比较；即使逐字段证明声称当前日期也不能补救。保留已知实际历史日与原始私有证明，卡上遮蔽数值／事件／观察资格，去重或 split donor 不能恢复。不同字段日期在 `evidence` 逐项列出。旧投影缺日期显示「待核」。含 collection 的投影在去重和排序前逐字段检查目标日、身份、market/type、来源、版次、状态和值；缺失、UNKNOWN、撤回、错日/错值/错范围字段显示待核，事件不列出，不参与当前排序或资格。已核实历史字段可标历史及其日期，但不作为当前值或当前比较。每个字段独立遮蔽，保留另一项有效强度；重复行与 split-field 不能恢复无效字段。明确省略且无撤回的字段仍可按原 split-field 契约从独立核实的适用来源补齐；旧格式兼容仍保留，不能产生新增取数或费用权。持仓与 Kelly 的「未接入」不进入清单。该控制器不访问供应商、不购数据、不改外部调度。

完备核验与正常渲染共用同一最终卡片流程：先逐项证据遮蔽，再按 identity／market／品种／currency 去重，并进行原 lookup 与双强度调解。逐行证明齐全仍不能终结同一适用身份的 miss／match 或 scope 冲突；调解后待核的卡片使整份报告待核，claim 列出其实际市场及查询 path，confirm 拒绝停止。其他身份／市场不被连带判冲突。此核验仅用内存中的投影与证明，不通过重新渲染或读取文件判断。逐行必需字段齐全仍须检查最终卡片；同一适用身份／版次的强度值冲突而变为待核时，报告保持收集中，claim 列出该标的市场和对应 metric 来源 path，confirm 不得停止。另一项有效强度独立保留；相同已核实值可正常合并。只有具备适用完整证明的真实 miss 可豁免该卡行情字段。原排序、权重及资格规则不变。

强度缺失（显式 null 或省略，全局／同品种均同）与已独立核实的观察资格分离。无矛盾证明的缺值，或有匹配适用范围的 verified-null 证明，仅使该项不可显示为当前数值、不可参与排序及报告完备，不能撤销已核实的趋势／信号／身份／日期资格。另一项有效强度仍显示。同范围、有效身份与当前日期的 strength/local_strength 撤回，若值明确为 null，仅撤销该项显示和排序、阻止同身份同字段同日同版重复行恢复，并使报告继续待核；不撤销已独立核实的趋势／事件／身份／日期观察资格。撤回否决逐个核对实际候选值自己的已核实字段 scope；首选行省略该字段不能绕过否决，补值来自任意数量／顺序的别行也同样处理。不同日／版次／市场／身份的撤回不得否决当前候选值。撤回证明本身的值矛盾、范围或日期失效仍按原保护处理；趋势／信号未核、未来观察或未决 lookup 不能恢复观察标记。缺值不授权补取或增加费用。


### 双强度字段选择（各入口共用）

所有入报告且平台身份精确匹配的可查标的，均分别选择 `trendStrengthGlobalCurr`（全局强度）及 `trendStrengthLocalCurr`（同品种强度）。股票、1 倍 ETF、已核实品种和 BTC 使用同一规则；不受当前或前期温度、开仓初筛、已知比对组、特殊信号、直属与否或是否为 BTC 限制。温度已排除开仓的标的也不能漏选任一强度。身份或日期未核实不授权发送，也不能借旧行情补齐。

- 每一项独立核对实际目标、市场、品种、适用数据日及版次、原字段口径、来源记录与字段覆盖。逐项复用可核实的同版缓存；一项缓存有效不代表另一项已取得。缺项记录 `UNKNOWN` 及原因，不以一项代填另一项，不使用日期失效或已撤回的数据。
- 在发送前完成上述字段选择；将确有必要且已有授权的缺失字段优先合并到同目标、市场、版本的已计划 `getTickerSnapshot.fields`，保留核对身份、市场及 `asOfDate` 的字段，并重新核实合并字段的计费。已经完成的身份／温度请求不代表已请求两项强度；不能据此把未请求记为供应商无值。
- 仍须先持共享锁和日报日锁、重读共享账本、核对等效及覆盖请求、落盘意图再发送。任一可能已发、未决或待对账请求可覆盖此目标时，停止受影响的发送，不通过更换字段集或版次重发。已完成且响应不可取的请求也不补发。已结算的身份／温度字段请求不覆盖未请求的强度；对已核实日期、无未决重叠且已另行确认原有取数及费用授权的 ETF，先复用缓存或合并计划请求，仍有强度缺项时可按该既有授权走必要补取，不重发已完成的温度请求。不得将 BTC 定时无计划快照不单独请求的限制扩大到这些 ETF；不明授权不视为已有授权。新增字段选择不扩大费用或数据权限；缺授权、费率、身份或版本证据时保留缺项及具体原因，照常成稿。尤其 BTC 手工补取仍需原有费用授权；BTC 定时轮次无可合并且获准快照时不为强度另开请求。
- 定时按本轮已授权计划执行；手工读取不取数，明确授权的手工修订才按同一选择规则及费用边界处理；离线只读固定输入、分别引用有效字段或记录缺项，新增调用和费用均为零。三种入口共享选择与投影规则，不把离线请求计划当已发送或线上强度。

### 定时取数

在定时取数轮次中，先核对适用数据日及榜图版次，再按已有证据、缓存、账本、字段费用和授权串行查询必要字段。超出授权或无法核实费用、请求身份、版本或响应时，保留已知事实和缺项，按账本规则停止受影响的发送。

1. 对作为交易品种的入选大类，直接核对自身身份与当期行情，不等待或为此查询成分。先从现有证据确认标的身份、实际市场及覆盖，复用适用数据日或版次的已核实快照。必要的身份、日期、当前温度或两项强度缺失时，沿用既有授权的 `getTickerSnapshot` 路径及已核实的字段、费用和频率补齐。没有适用授权、已知覆盖或可靠身份时记缺项，不能从分类 ID 推定行情标的。

   核实身份和当期数据日或版次后，若仍缺判断自身特殊信号的证据，用同一快照路径请求识别阳性事件所需的最小字段集，例如经核实确实承载相关事件的 `tickerLabels`。只请求已获授权、字段含义及费率已核实的必要字段。此检查不受当前温度或开仓初筛限制。优先复用同一标的、市场和版本的缓存。门槛已满足时，将所需字段合并到同一标的、市场和版本的已计划快照，按共享账本核对覆盖范围和去重。取得响应后核对标的、市场和数据日或版次，并私下记录实际字段和来源。授权、费用、版本或字段不可核实时标 `UNKNOWN`。不为证实没有事件追加查询。

   BTC 现货及其他可查标的均按「双强度字段选择」逐项检查缓存和字段覆盖。确认该标的身份、市场和适用版本后，在已有授权的同目标计划快照中合并缺失的两项强度；不得仅选 BTC 同品种强度或用其代替全局强度。没有可合并且获准的 BTC 快照时保留缺项，不另开查询。

2. 先复用交叉验证的独立直属清单；只对发现交集仍缺的归属按同类合并核对，不为交集发现重复全量查询。其余在报标的既有完整性要求不变。定时、手工修订和离线入口均用「核对与筛选」的同一名单规则；手工读取不触发取数，离线只读固定输入。为新仓筛选入选大类时，使用已授权的 `getComponentTicker(tmId=类别ID, getAllBasicComponentsFlag=0)` 取直属成分。先在私有证据固定榜图版次、入选大类及方向，保存原始成员和分页边界。仅沿有同版小程序路径或人工下钻记录证据的下级分类展开，核对中间分类与叶节点；叶节点返回的所属父类不展开，不循环回父类。无路径、分页不全或版次无法对应时，保留已证实成员，未核范围标待核，不宣称完整下钻。交互式现场取证按「视觉取证与行情费用」执行。只核对所得直属或下级成分中适用市场的股票、1 倍 ETF，以及已有证据识别的适用市场股票和 1 倍 ETF。未核实的期权身份、行情或资格只列缺项；只有具备已提供且核实的期权自身身份、市场和字段时，才将该证据用于筛选。不同来源的相同标的在同一大类内按平台身份、代码、市场、品种和适用数据日去重；同码异市场或异品种不合并。跨大类复用同一标的行情及共享账本，但逐类核实归属并独立保留名单。成分关系、收藏夹成员和代理关系分别核实，关联或收藏不能冒充直属。
3. 对尚缺行情的股票及 1 倍 ETF 用 `getTickerSnapshot` 分两轮取最少字段。首轮选择身份、`asOfDate`、`trendTemperatureCurr` 以及 `trendStrengthGlobalCurr`、`trendStrengthLocalCurr`；逐项已有合格缓存则复用，缺失字段在身份和费用已核实的计划快照中合并。仅对通过身份和日期核验的标的补第二轮。对做多当前「热」或做空当前「寒」的标的，补 `trendTemperaturePrev` 和 `tickerLabels`。两项强度的选择独立于本轮温度和信号筛选，不能只给已知比较组或初筛通过者选择。强度仅排序，不能作为已合格直属标的入列的前提。第二轮仍须核对同一标的身份与适用交易日。其余标的优先用已有证据核实信号字段；只有在判定信号一致性确有必要且费用与授权均已核实时才补取。字段未齐时可写实际温度及已排除的转换，状态仍按具体缺项判定。缺少比较或资格证据时按「核对与筛选」标缺口。
4. 期货、持仓与凯利不进入本期取数。本期沿用已有直属成分路径和已知标的，收藏夹建议只来自现有证据；新增资产发现、期权研究和收藏夹管理由本期范围之外处理。

### 运行锁与共享账本

- 以 `umask 077` 建立私有报告目录及 `.claims/`，权限 `0700`。用不带 `-p` 的原子 `mkdir` 取得报告日锁 `.claims/YYYY-MM-DD` 和跨日报日共享锁 `.claims/scheduled-check`。定时检查，以及任何手工或修订操作中可能计费的请求，均先取共享锁，再取报告日锁。只读正式报告、从已核实本地证据重排正式日报或只写日状态证据时，只需报告日锁。固定证据离线验收使用指定输出目录，不访问正式目录、共享账本或日锁。若在持日锁时发现需要付费，先释放日锁，再依次取共享锁及日锁，重新核对两处证据。仅创建成功者持有本次随机令牌，并以 `0600` 写入锁目录的 `owner` 文件。创建失败或所有者记录不完整时停止相应操作，回报正在运行或需要核对。不得检查后重建、借用别人的令牌，或用 `.dispatch` 锁代替。
- 任何可能计费的发送前，持共享锁查询 `_evidence/_billing/` 的跨日报日账本，并检查全部日报日下现有及旧版证据中的请求记录。可用已核对覆盖完整、源记录可访问且尚未变更的索引查旧记录。将旧版的已完成、可能已发和待对账状态及原证据纳入共享查找。若旧记录身份含糊、来源不可读、覆盖不全或存在仍按旧规则执行的会话，先停受影响的付费发送，核对后再继续。无法排除与请求重叠时标 `UNKNOWN`，不把索引缺项当成未发。
- 用供应商作用域、端点、实际目标及有效参数、字段集和可验证的数据日或版本识别逻辑请求。只归并已证实等效的参数表达，保留影响实际请求或计费范围的字段与过滤条件。启动日、报告日、仅用于编排的市场标签、入口、文件夹和本地调用时间不进入身份。复用匹配的已完成响应并保留费用出处。响应不可取时标 `UNKNOWN`，不补发已完成请求。查找时也核对可能覆盖同一计费目标的记录。真正不同的数据日或版本必须有可核验证据，且能证明旧发送不可能取到同一版本。没有版本证据时仍按同一逻辑目标核对。不得通过换日期、市场标签、字段或参数规避尚未对账的发送。
- 对 `getUpdateStatus` 等可变观测，先核实授权、费用和间隔。复用同一观测已完成的结果。仅在前一观测已落盘并核对、确实需要新的观测、且共享账本记录的间隔已到时，为同一逻辑目标登记下一次观测。若前次是否发出或扣费不明，先对账，时间戳或下一个小时不能开启新的计费尝试。只有已核实免费且不会重复待核对的可能计费请求时，才可在日报检查时作免费观测。
- 每次可能计费的请求，先在共享账本持久化逻辑请求身份、原日证据定位和「可能已发送」记录，再发送。用同目录临时文件原子更新记录，并同步文件和父目录。共享锁持续覆盖查找、持久化意图、请求及结果落盘。分别记录响应、缓存命中和实扣，日账本引用共享记录。响应或账单暂缺时，落为 `UNKNOWN` 并记录待对账依据后可释放锁。恢复时先核对原响应和账单，不以另一笔已完成记录结清待核对请求。无法证实未发且未扣费时，不得重发该请求。崩溃在意图写入与结算之间，仍视为可能已发送。
- 锁目录跨工具和 shell 调用持续存在。没有在途请求且意图及最后已知结果已落盘时，仅原持有者核对令牌，再删除 `owner` 并用 `rmdir` 释放锁。中断留下的共享锁或日锁，优先交原会话核验和恢复，所有权不明或原会话无法恢复时保留锁及账本并回报人工核对。禁止自动超时接管、替其他会话删除锁或在等待时持锁。

### 适用数据日期

- 普通手工当日首稿默认以报告日 Asia/Taipei 08:30 为截至基准，早间和晚间请求使用同一基准，不以请求时间当作 as-of。在本地证据记录报告日、完整截至时间及时区（例如 `2026-11-24T08:30:00+08:00`、`Asia/Taipei`），并分开记录实际观察时间。08:30 前读取只能使用当时已经可用、且适用该报告范围的证据；未来观察或预计发布不能当作事实，未取得项为 `UNKNOWN`／待核，照常成稿。
- 普通读取沿用该报告已确认并记录为现行的截至基准；不因晚到请求、跨日恢复或仅改格式改变它。明确指定其他截至时间的修订才记录新基准及其时区、授权与旧基准，并保留原版本。自定义修订后须核对其是否被明确确认为现行基准；普通读取不能静默复用不同截至时间的版本，也不能静默重置为 08:30。记录不清时说明待确认的基准，不能以文件名或最新文件推定。
- 历史离线和未指定新截至时间的修订保留原已确认基准；固定证据不足不补取。数小时后取得的证据只可核实原冻结 D−1 目标及原报告适用事实，不把 as-of 或目标日向前滚动，不混入后来报告日专属事实。同日明确的阴性更正（包括推翻旧无匹配、信号或资格）按「同日证据更正」撤回失效事实，不能因沿用基准而继续返回已被推翻的内容。普通读取和本地重排仍零新增行情／付费请求，不启动轮询。
- 定时、手工、历史离线及修订都按品种的实际市场独立判断，不以股票休市否决整份日报。手工读取不启动取数；明确要求的手工修订仍受适用数据日期、授权及费用门槛约束。历史离线只用固定证据，不用今天的日历状态或后来发布的数据替换历史事实。
- 定时日报以该报告日及其计划时点为证据基准。按当时适用的市场日历、日界和已核实的供应商发布时间规则，分别确定并保存该报告日应使用的榜图日期或可接受版次、各来源及品种应有的数据日和核验依据。恢复时沿用已核实的适用范围。尚不确定时记 `UNKNOWN`。实际观察或取数时间只记录何时取得证据。迟到的原日报日证据可以使用，后续报告日专属的榜图或行情不能替代。
- 历史或修订报告用该报告确认的截至时间（含时区）。按交易所当地交易时段和已核实的发布时间规则，取不晚于报告日 D−1 的最近收盘交易日。连续市场目标为 D−1；核实供应商日界用于解释来源，不以发布延迟把目标回退。台北报告日不等于供应商数据日，连续市场的滚动 24 小时也不是交易所日线。只有依据明确确认上一数据日仍适用，才可用其数据。若两个报告日各自核实同一闭市市场的数据日或版本适用，按共享账本复用符合条件的响应。
- `getUpdateStatus` 只用于观测实际更新。证据缺失、无法映射榜图版次或无法核实发布时间规则时记 `UNKNOWN`，不按日历日、最近响应或更新时间猜测。榜图用图面日期或可核实日期的版次匹配预期榜图；大类和每个品种的必需行情输入须匹配各自适用的预期数据日。只有已核实某日期适用时才可继承榜图日期。已知但不符的实际日在私有证据中如实记录，并给出预期日期和原因。受影响的旧日事实可明确标历史及实际日期，但不能用于当期新仓资格；不明身份、无效/未来日期仍遮蔽，不用旧图、替代榜或顺延大类填补目标缺口。

## 核对与筛选

新版日报展示完整独立母榜中 ≥80 的全部做多类与 ≤20 的全部做空类，含边界及零分；旧版按原头尾各两席读回。保留入选大类及缺项，不以交易资格顺延替换。根 `纪律.md` 的「没有可交易标的则顺延」适用于 Ray 手工选择交易池，不是日报榜图席位规则；手工交易池选择不改写官方报告。本文「观察仓名单」指逐只满足新仓条件的观察候选；「大类自身特殊信号观察」仅记录该交易品种自身事件，不表示已取得观察仓资格，也不自动产生「应建观察仓」标记。两者都不代表实际持仓或执行交易。止盈后加仓规则由根 `纪律.md` 维护，日报不另定策略。

1. **选大类。** 核实官方金融资产组的完整母榜、组尾、每行数据日和版次，区分其他分组；视觉入口不发 API。其他入口仅在既有取数／费用权限内复用或取得母榜。新版按 ≥80／≤20 筛选，组内排名按各方向强到弱／弱到强顺排，原页次序处理并列。独立母榜未知时不能从已报类或信号名单重建完整预期，更不能补造来源。先保留可用报告并标待核。以方向信号榜交叉验证发现交集，归属缺口按同类合并核实；没有交易标的、无信号或缺证均不换类。旧双席仅兼容历史报告。
2. **核对标的证据。** 使用离线输入或既有授权路径取得的分组、身份、经济敞口、覆盖和行情证据。来自 #512 的可用证据可补充，采用其已经核实的事实；日报可独立成稿，不依赖 #512 的文件格式或额外发现。在每个大类内按市场、品种及经证实的标的身份和适用数据日去重；跨类只复用行情，不删除各类有据归属的条目。核对适用市场预期日期、标的自身 `trendTemperaturePrev` → `trendTemperatureCurr` 及 `tickerLabels`。在私有证据记录直接、反向或代理的敞口及其出处，保留已核实的关联和局限。股票、1 倍 ETF、期权都必须有自身信号。标的自身信号缺失时，货币、指数、ETF 或期权底层资产已有的信号只能作为明示归属的背景。期权只列可用标的代码和市场及自身信号，Ray 手选行权价、到期月和张数。
3. **记状态和资格。** 每条私有证据行用下表的具体状态，保留已核实的身份、日期、敞口或信号。缺失字段标 `UNKNOWN` 并注明缺项。「证据不足」仅统称表中后六种状态。只有「已触发」且已核实符合交易资格的标的可列入观察仓名单并显示「应建观察仓」标记。信号已核实、资格待核时写「部分待核」，保留已知信号并点明缺项。信号已核实且已明确不符合资格时，保留「已触发」、数据日、标的自身转换和标签，另写「开仓资格：不符合」及具体原因。

| --- | --- |
| 已触发 | 身份、敞口和数据日已核实。做多为自身严格温→热且带「温转热」，做空为自身严格凉→寒且带「凉转寒」。 |

4. **计算方向名次。** 每个大类对应一个收藏夹分组，例如「V3-美元」。用该组可比成员的标的自身 `trendStrengthGlobalCurr`（记为 G）。多头名次为 1 加组内 G 严格较高的标的数，空头名次为 1 加组内 G 严格较低的标的数。私有名次表中同名次按代码字母序排列。按各成员适用的数据日和同一比较口径核实 G 与组员身份。可比成员即使未触发或明确不符合开仓资格，仍计入组内名次。分开标记已收藏成员与拟加入标的。拟加入标的若有经核实的自身 G 且有可比组员，可标明相对已核实组员的参考位置，不能把它计为已有组员或把参考位置写成正式组内名次。标出分组、数据日、计入范围和漏项；已经能计算的名次须注明其仅适用于可比范围。缺少必要数据时保留已知事实，名次标 `UNKNOWN`。小程序 0–100 页面整数的分位和舍入规则未公开。
5. **核对观察仓名单及收藏建议。** 在私有证据中记录观察仓名单。A 股股票即使自身做空信号已核实，本期也不符合做空开仓资格。生成观察仓名单之前就从做空候选中剔除，私有证据行写「开仓资格：不符合（本期 A 股股票不列做空新仓）」。资格根据实际交易标的的市场与品种核对。另行核实的期权和其他市场代理按各自的身份、资格及自身信号判断。

   每类经证实的合格直属标的全部列入观察仓名单，不限数量，不因强度并列剔除。逐只核实同版直属路径、平台身份、代码、市场、品种、实际交易资格、适用数据日、自身前后温度及标签。多头严格温→热且有「温转热」，空头严格凉→寒且有「凉转寒」；资格或信号缺证者单列待核，不能用大类、底层或代理信号代替。每类名单按自身 G 多头从高到低、空头从低到高，同值按代码字母序。仅缺 G 而其余条件均已核实者仍标「应建观察仓」，排在有值者之后，同样按代码排列，强度显示「待核」。私有方向名次或参考位置继续保留，名次和比较范围缺项不构成数量限制。

   原始成员、独立筛选预期和实际日报名单分别保存。每类独立对照集合、归属、信号、顺序与标记，逐项记录遗漏、多列、错标或错序。同一标的在多个入选大类均有经证实的归属时各类独立展示，同类同身份只列一次；重复展示不代表重复建仓，也不改变仓位和账户规则。已证实的关联新仓沿用自身资格及信号核对，不能冒充直属或挤掉直属名单。成员结果完整且无合格者时写「已核实无合格直属标的」；覆盖、分页、身份或资格未全时写具体待核范围，不能写成完整空结果，也不阻止已知合格者展示或当日成稿。无可入列候选但未完成核实时记「当前证据无可列候选」，保留已核实信号。实样未取得、分页未全或版次无法对应时，真实下钻验收保留待核；合成用例不能代替实样。收藏建议及分组理由留私有证据，必要时在会话请 Ray 手工添加，不改变成员身份和资格。分列来源事实、计算名次和按纪律得出的判断。

6. **核对大类自身的观察。** 在本报告版本全部已核实入选大类内，核实大类本身是否就是可交易品种，记录大类与标的的直接同一关系、实际市场、适用数据日、自身当前温度和当期特殊信号。固定版本纪律中的自身特殊信号已确认（如「开香槟」「上天台」或「反抽警报」）且其余必需事实齐全时，在该大类下列观察卡，无需满足新仓触发、开仓资格或组内名次条件；这类观察本身不产生「应建观察仓」标记。沿用特殊信号逐项核验。由底层现货、父类、成分、指数或代理传来的信号均不能证明标的自身有事件。不凭简称或名称相同确认身份，不把期货放入本期。自身事件有明确阴性且事件覆盖完整时记「核实后无观察」；身份、日期、当前温度或事件仍待核时记录缺项。有至少一项独立确证事件时，其他事件待核不妨碍展示已证实事件。同品种强度缺失不撤销已证实的观察。单独记录大类自身特殊信号观察及观察仓资格结论，止盈及警报事件只作为观察事实，不产生开仓、持仓或订单动作。

### 关联品种的查询状态

- 仅对已核实身份、市场及所属入选大类关系的已知关联交易品种列查询状态。趋势动物查询成功完成，目标、范围和版本适用于该报告日及截至时间，且完整结果（含所有相关分页）确认无精确匹配时，记「已核实无匹配」，显示「查不到」。旧证据只记「平台未覆盖」时，回查原查询是否满足相同条件。
- 查询失败、未查询、分页未完成、结果未定、版本不适用或查询证据矛盾未解决时，在私有证据按实际情况记 `UNKNOWN` 或未查询，并对具备上述已核实身份及归属的品种显示「待核」。身份或归属未核实的品种仅留私有证据。若已有无匹配证据仍适用且未被冲突证据或更正推翻，保留「查不到」。查到精确匹配、身份或组别有更正、或旧证据不再适用时，按「同日证据更正」重新判断。
- 「查不到」和「待核」仅表明查询结果状态，不推定趋势、信号、交易资格、强度或名次，不产生「应建观察仓」标记，也不限制观察仓名单数量。独立满足观察仓资格或大类自身特殊信号观察条件时，按核实结论展示同一张卡。

### 标的字段来源

- 为用于前温、当前温度、标签、G、同品种强度与特殊信号的每条实际记录分配简短、易读的私有证据编号，例如 `R17`。将编号与脱敏本地文件的固定版本及文件内的精确记录位置一并保存，例如数组下标或记录键。核对记录对应的标的身份、市场、实际数据日和字段。即使同一标的同一天，来自不同记录的字段也分别引用各自的编号。仅当同一条记录确实支持多个字段时才共用编号。
- 复用已有编号，同版复验、只改状态及合并其他市场时保持编号和记录对应关系。改用新版本的记录时分配不同编号，即使字段值相同。保留旧稿及其证据索引，已用编号不改绑、不回收。编号不依赖当前报告的行序、市场检查顺序或显示名次。
- 字段或可核实的源记录缺失时，对相应字段或来源标 `UNKNOWN` 并说明缺项，保留其他能核实的字段。无法核实来源的字段不用于确认信号或计算名次。无标签也须有相应记录，不能把缺失标签写成「无」。只依据现有脱敏证据，不按代码与日期猜测来源，不为补编号调用供应商。本技能可用已有文件形式记录对应关系。
- 特殊信号逐项核实。现有记录中的标的自身当期事件标签、事件专用布尔值或其他经核实的事件字段均可作证。确认字段含义、标的身份、市场和数据日，再记录每项事件的结论、实际字段和对应证据编号。开仓事件仍须符合「核对与筛选」的转换与标签证据。单凭温度变化或任意供应商标签不能确认特殊事件。遇到缺字段、覆盖未证实或同一事件证据冲突时，将该项标为 `UNKNOWN`，保留其他独立确证的事件。空或缺失的 `tickerLabels` 只说明标签证据的状态。只有完整覆盖及逐项阴性证据支持私下判为已查无事件。缺项不触发付费补查或猜测字段。
- 所有可查标的的同品种强度采用该标的自身、同市场同数据日及 0–100 同资产类别比较口径的原值。BTC 现货只采用已核实匹配的 `trendStrengthLocalCurr`。核实并记录实际字段、比较口径和证据编号。数值 0 是有效原值。缺值、非有效数值、口径不明或相互冲突时在私有证据标 `UNKNOWN`，保留其他独立确证的事实。榜图组分数、名次、代理分数及 `trendStrengthGlobalCurr` 都不能代填。同品种强度不参与分组、方向名次和新仓筛选。

## 生成阅读 HTML

### 版式与展示白名单

- 使用已批准的整卡黄绿样式及三列行情／双强度、独立信号行。每卡只显示一个「行情截至」实际日；仅实际早于已核实目标时显示「待更新 · 等目标日」，否则日期不明或异常显示「日期待核」。绿卡「本期最新」只证明行情日期匹配，不代表信号、观察资格或报告完备。日期依据显式 data_date 与原报告日适用日历证明 collection.target_evidence；沿用已核实目标并独立校验，不从抓取时刻或今天推断。缺日历证明的旧输入可读但用黄卡待核；逐字段日期与技术诊断留私有。保留历史遮蔽规则，不用黄色卡旧值排序或恢复资格。正式入口无样稿切换控件。

- 使用 [V1 阅读模板](assets/report.html)和下述渲染入口。页首标题显示「趋势动物观察报告」及唯一一处实际报告日；其下仅显示总体状态及下次核实或确认时间，不公开集中待查清单。目录锚点依次为做空、做多、实盘、模拟盘、凯利胜率。固定保留页首、目录、做空及做多面板、逐类展开行、大类直属／趋势动物里面能够查到／相关的标的三个区块、实盘预留区、模拟盘状态和凯利列表及其原有顺序和样式。各方向首个显示的大类默认展开，后续大类默认折叠。实盘预留区内与模拟盘各用一条 `p.positions-note` 显示「未接入」。凯利列表的实盘与模拟盘两项各显示「未接入」，共四处状态。正式报告以 `YYYY-MM-DD.html` 命名。只有单张标的卡片的视觉可独立调整，其余版式改动需 Ray 明确批准。
- 新版各方向保留全部阈值入选大类；旧版保留头两席或尾两席。展开行的「组内排名」是该大类在做多或做空面板中的方向席位，新版使用 `01`、`02`、`03` 等方向序号，旧版保留原席位。榜图全局名次及标的组内名次各自留在私有证据。展开行的「强度」只取大类榜图原值，标的自身强度填入对应卡片。榜图来源及版次保留在私有证据；大类实际日期和覆盖缺项放本类展开区。缺失的大类日期标「待核」，缺失的大类强度标 `UNKNOWN`。保留没有合格标的的大类。无法确认席位时，在相应面板写具体缺项并保留其他席位。
- 每个大类固定显示三个独立区块，顺序和标题为「大类直属」「趋势动物里面能够查到」「相关的标的」，空区块也显示标题和简短缺项。仅列身份和本类关联有据的标的。按本类同版小程序下钻路径核实的直属成员放第一块；其余已精确匹配同一市场、同一品种的平台标的放第二块；其余有据关联标的放第三块，并分清已完成查询无匹配与尚待核实。直属优先于平台可查，平台可查优先于其他关联；同类同身份只出现一次，直属不在后两块重复。大类本体、名称相同或旧列表位置都不能证明成员关系。缺强度或日期不适用不等于平台查无匹配。
- 筛选阶段逐类核实成员、平台精确匹配和自身观察仓资格，分别留证。跨类已有成员关系各类保留；观察仓资格独立于区块分类，不因平台可查而自动获得。候选、观察及其他有据标的统一用 `li.asset.reader-card`。各区块用标的自身全局 G 数值按多头从高到低、空头从低到高排序；缺值置后，同值或同为缺值按代码排列。任何标的的同品种强度均不参与全局 G 排序。同时满足观察仓资格和大类自身特殊信号观察条件时只显示一张卡，两项依据分别留在私有证据。
- 查询范围、分页和整类覆盖的可公开说明统一放在三块之后，不插入已知卡片之间。用 `coverage_note` 写一句简明说明，即使直属为空或全类暂无卡片也能保留已核实的范围缺口。旧 `direct_partial_note` 兼容保留，只在有直属卡片时生效。不能因已列一只便隐藏其余范围待核，也不因缺页撤掉已核实卡片。私有分页明细、路径和证据编号不进入说明。
- 每张卡有显式证据时显示「直属」「趋势动物可查」「应建观察仓」文字标记，再显示「代码 · 名称」、标的自身「当前趋势」「特殊信号」「全局强度」「同品种强度」以及一句中文理由。「当前趋势」取标的自身当前温度。「特殊信号」只列标的自身当期已确认的事件名称，按首次出现顺序去重，用中文逗号「，」分隔。完整适用证据确认无事件时写「无」；缺失、尚未核实或被遮蔽的事件显示「待查」，已有独立确证事件仍保留。旧版已核实展示投影兼容读取。查询或事件覆盖的缺项及原因按已有规则记入私有证据，适合发布的查询状态或理由仍在本卡其他字段呈现。「无」表示本次证据确认无事件，不替代交易判断。止盈事件不能当作开仓触发。每张卡并排显示两项强度：全局强度用 `trendStrengthGlobalCurr` 原值，同品种强度用 `trendStrengthLocalCurr` 原值，各加 ` / 100`，保留零及原精度。两项独立，任一缺值显示「待核」并在该项下说明可公开原因，另一项仍照常显示。趋势缺值也显示「待核」。已核实值不换算或舍入。市场、日期、原始字段、范围和取舍按原规则保留在私有证据。
- 新仓理由说明该标的为何在这个方向和大类入选，比较结论限于已核实的范围。观察理由按固定版本纪律解释品种自身信号的用途。上天台写「该品种触发空头止盈信号，列为观察。」开香槟写「该品种触发多头止盈信号，列为观察。」反抽警报写「该品种出现空头风险警报，列为观察。」其他已核实的事件按各自用途写。其他品种的理由简述已核实的关联、未入选或待核原因。理由限于可发布的事实；程序生成的交集来源可列信号榜名、标签和数据日，其余不引入交易指令、推定持仓、日期、证据编号、公式、名次、费用或其他标的。身份或归属未核实的品种只留私有证据。日期不适用时停用该行情值，在私有证据写明实际日和预期日。
- 身份及关联已核实，但只适用查询状态的品种使用 `lookup`。完整适用查询已确认无精确匹配时，用 `miss`，趋势和强度显示「查不到」。查询失败、未查询、未确认后续页或仍待核时，用 `pending`，趋势和强度显示「待核」。查询结论不证明信号不存在，含 collection 的查询卡信号显示「待查」；旧版已核实展示投影保留兼容。理由可写经核实且可刊的来源或原因，例如只收到第一页。没有适用理由时显示相同的查询状态短语。每个查询状态卡按本类已核实归属进入第一块或第三块；没有精确匹配证据不能进入第二块。部分响应或其他证据足以独立确证事件时，通过有据的普通卡、观察卡或新仓卡呈现该事件，保留其他缺项。
- 版式和字段以模板为准。静态目录可链接页内锚点。正式 HTML 仅包含白名单内容，禁止脚本、外链、外部资源、任意 HTML 片段、隐藏数据、纪律或费率附录、费用、证据编号、路径及账户信息。落盘、交付和已有授权的同步前核对全文件、五处锚点、展开结构、三区的四处「未接入」及白名单字段与证据的一致性。校验不通过时不得交付。

### 固定渲染入口

定时、手工、离线、修订及同日复用核对都调用同一版本的 [渲染器](render_report.py)。先将适用于请求报告日和截至时间的已核实事实筛为下列 JSON。生成可用报告不要求任何组或行情字段达到覆盖门槛。JSON 只放获准显示的值和下述私有分类字段，保存在现有授权的私有目录，不同步。

```sh
python3 "$skill_dir/render_report.py" "$verified_json" "$new_html"
```

`skill_dir` 为核对过版本的技能目录，`verified_json` 为明确选定的 UTF-8 输入路径，`new_html` 为已存在的私有目录下尚未使用的候选文件路径。渲染器只读该输入与同目录下的 `assets/report.html`，生成一份 UTF-8 HTML。它转义所有动态文本，展开并移除模板节点和插槽。已有路径返回非零。需要替换现行日报时，先核对候选，再按下文的锁、归档和原子替换流程处理。

- 可选 `paper_entry` 只接受模拟开仓技能 `status` 输出的已核实脱敏结果。定时、手工、复渲染和离线入口须从所选日报的独立核实记录（`report-verification.json`）取得已核实的版次，并在渲染时用 `--report-revision "$verified_revision"` 传入。若用 `collection.py confirm` 核对本轮正式报告，传入相同参数。缺少已核实版次、版次不符或报告日不符时显示「未接入」。只显示标的、已知处理状态、简短原因和已确认数量。账本、账户身份和订单号保留在私有目录。旧输入照常显示「未接入」。
- 根对象必须有 `date`（实际报告日，`YYYY-MM-DD`）。可选 `board_date`（经核实的榜图日，同格式）、`board_version`、`short`、`long`、`short_note`、`long_note`。方向数组缺省为空，方向说明只写白名单允许的具体缺项。
- 每个大类有已核实的方向席位 `seat`（整数 `1` 或 `2`，同一方向内唯一）和 `name`，可选 `code`、`board_strength`、`direct`、`searchable`、`related`、`direct_note`、`searchable_note`、`related_note`、`coverage_note`、`direct_partial_note`。三个输入列表缺省为空，旧 `direct` / `related` 仍可读取，但数组位置不是成员或平台匹配证据。渲染器汇总输入后按显式核实字段执行三块分类、优先级去重和方向排序，不代替业务核验。`direct_note`、`searchable_note`、`related_note` 只在对应输出区块为空时显示；旧 direct/related 空列表说明还要求原输入列表为空，避免重新分组后公开原本隐藏的旧说明；非空时忽略，不能将旧空列表默认语或技术说明自动公开。
- 新 `coverage_note` 为可公开的整类范围说明文本，始终放在三块之后，与卡片和直属区块是否为空无关。缺省不显示；空文本或纯空白不显示。提供该字段时优先于旧 `direct_partial_note`，两者不重复显示。分页与查询范围写在此处，区块空说明只说明当前没有已核实卡片，不能以空说明推断完整查无成员。当天没有直属但有平台可查卡片的输入，也用此字段保留成员第二页待核等事实。
- `direct_partial_note` 只用于非空直属区块的已确认部分覆盖情形。只填一句经核实且可公开的范围缺口，渲染器转义后放在全部三个区块之后。省略、空文本或纯空白时不生成说明；直属为空时仍用 `direct_note`。迁移旧稿时回查有效证据，将公开短句提炼到该字段，不复制私有日志。例：`direct_partial_note: "部分直属成员已核实，后续页待核。"`。此说明不撤销已核实资格，不承载交易指令、费用或账户信息。
- 列表标的有 `code` 和 `name`，可选 `trend`、`strength`、`local_strength`、`strength_reason`、`local_strength_reason`、`reason` 和 `lookup`。`strength` 只投影已核实的全局原值，`local_strength` 只投影已核实的同品种原值；二者均接受 0–100 数值或保留精度的数值文本，也兼容 `"90 / 100"`。缺项用省略、`null` 或 `UNKNOWN`，各显示「待核」；分别用对应的 `*_reason` 说明已核实且可公开的缺项原因，省略时显示该项字段缺失或无效。不得放日期、证据编号、费用或私有日志。旧 `strength: "同品种 6 / 100"` 仅归同品种列，不是全局值或全局撤回；归并前也按此语义判定字段是否提供，不能因原键名为 `strength` 而阻止另有有效证据的全局值。来源行的旧前缀同样只支持同品种字段，仍须该字段独立核实；显式全局 `null`／无效值或全局字段证据撤回仍阻止恢复全局值。显式 `local_strength: null` 优先，不能从旧文本恢复被撤回的值。`lookup: "miss"` 与 `"pending"` 仍分别遮蔽趋势及两项强度为「查不到」或「待核」，事件待查（旧版无 collection 的已核实展示投影兼容），不公开旧字段说明。已确认匹配但日期不适用时，不填 `lookup`；停用相应旧行情及强度，保留匹配标记，各项填缺值和原因。
- 新标记只接受显式布尔值：`direct_verified: true` 表示已按同版小程序路径核实属于当前大类的直属成员；`platform_match_verified: true` 表示已精确核对同一市场、同一品种的平台结果，与强度和观察资格无关；`watch_eligible: true` 表示逐只核实身份、市场、品种、适用日期、交易资格和严格方向转换及标签后满足观察仓条件。缺项、不符或未触发时省略或 `false`，文本 `"true"` 不成立。查询状态卡不能带观察仓资格。独缺排序强度不撤销资格。旧列表位置、事件、大类自身观察或 HTML 标记不能推断这些字段。直属及可查标记也显示在已核实但不满足观察仓条件的卡片上。
- 为同类重叠去重，投影私下提供非空 `market`、`instrument_type` 和代码，以及已建立的 `instrument_id`。ID 可为非空文本或非负整数（含零）；整数 `1` 与文本 `"1"` 归一，布尔、浮点和复合对象不能作 ID。同市场、品种和代码只有一个已证实 ID 时，缺 ID 的同代码记录可归到该 ID；有多个矛盾 ID 时，不猜测缺 ID 的记录属于哪一个。不同市场、品种、明确币种或矛盾 ID 不合并；缺市场或品种时不按名称或裸代码合并。提供币种用私有 `currency`，缺币种不推定为某币种。ID 和代码仍是不同命名空间，只有上述唯一 ID 证据能连接。跨类独立处理。优先保留高优先区块的证据行，不从低优先重复行复制观察仓资格。身份、私有核验材料和证据编号不写入 HTML。
- 成稿者在设置 `platform_match_verified: true` 前，必须私下逐项核对精确标的身份、实际市场、品种、报告截至时点、适用数据日和版本，并保留来源。同组待归并的记录必须属于同一适用报告范围；日期或版次不适用的阳性不能作为匹配证明。私有 `lookup_scope` 可填经核实的适用范围文本（例如报告截至时点＋数据日＋版次的稳定表示），仅用于比较，不进入 HTML；若使用，所有参与身份查询核对的重叠记录均须填写一致的值；只有 `lookup: "miss"`、`lookup: "pending"` 或 `platform_match_verified: true` 代表此类查询证据，单独的行情／事件记录不因带有或缺少范围字段而成为身份查询结论。全部省略时，仍由成稿者保证同组投影已按同一适用范围筛选，不能把省略字段当作免核验。旧字段和新范围文本都不能代替原始来源。
- 同类精确同身份的去重只固定区块优先级，不丢弃兼容的已核实平台匹配事实：保留的一张直属卡可同时显示「直属」和「趋势动物可查」。只有身份和适用范围一致时才归并该阳性事实，不盲目复制低优先记录的行情；趋势、事件、理由及观察仓资格始终不迁移，只有下述逐字段核实的两项强度可在显式选择下归并。首选记录的 `lookup: "pending"` 不是查无匹配证明；存在兼容的已核实匹配时解除查询待核状态，但清除原先被此状态遮蔽的行情、事件和观察仓标记，只显示行情字段待核。不得因解除遮蔽而激活旧 `watch_eligible`。
- 强度证据可能分散在直属成员记录及已核实快照。优先在私有证据筛选阶段按各字段实际来源、同一精确平台身份、市场、品种、币种及适用数据日／版次整合到首选投影，再交渲染器；不能因去重只保留成员记录而丢失已核实强度。没有独立核实的行情不能靠平台阳性身份自动补齐。
- 若必须传分散投影，可显式启用仅两项强度的可选归并：首选行 `strength_scope: {"data_date": "2026-11-20", "version": "v1"}` 声明已核实适用于该报告截至时间的实际数据日及非空版次（不是报告日或猜测的最新版本）。每个来源行私下用 `strength_evidence: {"strength": {"state": "verified", "data_date": "2026-11-20", "version": "v1"}, "local_strength": {"state": "verified", "data_date": "2026-11-20", "version": "v1"}}` 逐项声明对应行原字段的已核实证据；只核实一项就只填该项。声明须指向已保存的真实来源，不能从卡片或匹配标记推定。来源还须有 `platform_match_verified: true`、与首选行相同的显式平台 ID、市场、品种及币种，且没有查询待核／无匹配；仅代码别名不授权迁移强度。缺少该可选契约的旧输入沿用原显示，绝不自动复制重复行行情。这些私有字段不进入 HTML。
- 每项独立归并：缺字段可以补；显式 `null`、无效原值、撤回或来源失效不得当作单纯缺字段。首选行仍有效的独立原值不因另一行缺项而丢失。来源字段只有证据日／版次严格等于首选 `strength_scope` 且 `state: "verified"` 才能参与；异日、异版、缺核实或未决来源不采用。当前同范围撤回用该字段证据 `state: "withdrawn"`，将该项置待核；首选字段自身证据不适用或已撤回同样不恢复旧值。两条可用证据数值不一致时该项待核，另一项独立保留；绝不平均或按输入次序选值。同数值保留首选精度，否则按最长原数字文本、再文本顺序稳定选同值表示。只迁移两项数值，不迁移行情趋势、事件、理由、观察资格或其他隐藏数据；首选原有 `pending` 即使身份解除，或身份查询冲突，均不得用此契约恢复行情。
- 同身份的实际身份查询证据同时存在显式 `miss` 与已核实匹配，或这些查询证据的 `lookup_scope` 不一致（包括部分填写、部分缺失）时，不静默选择一个结论。仍只保留一张卡：已核实直属留在第一块，其余取消可查标记后放在第三块，查询及行情显示「待核」，事件待查（旧版无 collection 的已核实展示投影兼容），不显示观察仓资格，并说明匹配证据冲突或范围待核。同一记录同时填 `miss` 和阳性标记也按此处理；同一记录的 `pending` 和适用阳性标记可解除查询待核，但同样不能公开原被遮蔽字段。即使没有阳性匹配，旧版 `miss` 与另一范围的 `pending` 也不能维持「查不到」，须显示「待核」；同身份且所有查询证据具有同一非空显式 `lookup_scope`、无阳性冲突时，完整 `miss` 可保留到首选 `pending` 卡：直属仍在第一块，其余仍按原区块归类，两项强度和趋势均显示「查不到」。仅归并查询结论，清除旧待核理由，不迁移别行理由、行情、事件或观察资格；事件仍按原证据规则遮蔽。没有显式范围时不把另一行阴性提升到待核卡；普通行情／观察卡也不因此新增 lookup。含 `collection` 时阴性来源仍须通过完整证明、目标日和身份检查；一张卡可用的证明不能替其他未完成工作项结案。没有身份查询结论的独立行情／事件行不参与范围冲突判定，不能因其范围不同或缺失而隐藏仍有效的首选行情、事件及自身观察仓资格。范围冲突不能用删除范围字段来绕过；须回原证据重新核实。
- 新投影用 `signal_events` 文本数组，每项只填一个通过「标的字段来源」逐项核实的标的自身事件名称。常见例子有「温转热」「热转沸」「寒转冻」「寒转凉」「开香槟」「上天台」「反抽警报」。其他同等确证的事件也使用该数组。定时成稿、手工成稿与同日更正都先逐项核实，再写数组。禁止把供应商的原始标签列表、否定结论、覆盖状态或解释文字直接写入数组。空数组优先于同一投影中的旧 `signal` 文本；含 collection 时只有匹配适用日期、身份和值的完整已核实证明才表示「无」，缺证显示「待查」。
- 有效旧投影若只有 `signal`，渲染器按分号、句号或换行划分独立分句。每句开头允许「已确认：」或「已触发：」。按 `、` 或中英文逗号逐项读取，去掉旧版「（其余待核）」后缀后比对既有事件名称。遇到首个否定、待核、含义不明或其他不能完整匹配的项，停止读取该分句。随后独立分句重新核对。仅用当前仍适用的历史私有证据迁移旧投影。其他已确证的事件用 `signal_events` 重建。最少输入只有报告日，例如 `{"date":"2040-01-01"}`，仍生成完整页面。

### 私有证据

- 用固定版本的 `纪律.md` 做核对，纪律全文、完整榜图和证据原件、收藏建议、方向名次计算、费用、讨论，以及超出展示白名单的字段和技术缺项只留私有证据或必要的会话状态。禁止读取持仓或账户仓位来源，不用持仓做候选筛选，不生成持仓动作或凯利值。
- 在原有 `_evidence/YYYY-MM-DD/vNN/` 保留脱敏输入及实际来源、版本与摘要、各标的实际日期、身份与敞口、温度与标签、资格、可比组及范围、方向公式及名次、并列、未查询及缺项。私下逐项记录事件、全局强度、同品种强度、大类与自身标的同一关系的来源字段及私有编号，并记录观察与新仓结论及去重取舍。无匹配或未核实的关联品种另记已核实的身份、所属大类、查询范围和版本、完成状态、实际结果出处及缺项，引用原脱敏证据，HTML 只列白名单允许的查询结果与简短理由。引用定位到脱敏本地证据的实际版本与记录，保留完整阴性范围及未知原因。按「标的字段来源」稳定复用编号。记录估算、可核实实扣、差额、缓存、未发和待对账请求及其共享账本引用。缺失与待对账金额记 `UNKNOWN`，不得当作零或实扣。既有授权的只读费用对账仅取必要扣费证据，不读取仓位或留存账户标识。禁止把私有证据、旧稿、账本、说明或伴随文件置入阅读文件或同步目录。

### 正式日报的模拟盘证据交接

在包含模拟盘入口的发布版本中，正式定时成稿器每个新 `vNN` 都在报告日锁内先保存 `reader-projection.json`、`selection-draft.json` 和 `fees.json`。把既有选股生成步骤的输出写到 `selection-draft.json`。随后从同一发布的服务源码执行以下命令，由程序在该版私有目录生成 `selection-evidence.json`。

```sh
PYTHONPATH="$service_dir/src" "$trend_python" -m trend_v3.paper_cli \
  prepare-report-evidence "$daily_root" "$date" "$revision" --release "$report_sha"
```

`daily_root` 为包含 `reports/_evidence` 的原日报工作区。草稿有原报告日和带时区的 `cutoff`，同名日期或版本声明须一致。命令写入 `trend-v3-paper-evidence/v1`、报告日、版次、发布提交和投影摘要。按原 HTML 核验步骤继续成稿和逐字节读回，独立核实记录采用实际 `projection_sha256`、`selection_sha256`、`fees_sha256` 和 `report_sha256`。已有核实记录或选股证据时禁止覆写。历史原件仍按原版本读取。

新版展示阈值不改变原模拟候选范围。先用独立完整母榜固定原头尾各两席，再分别组装公开阅读投影与私有模拟证据；第二席只有 79（或空头第二席 21）时，阅读投影省略该类，私有模拟证据仍保留其实际已核实成员。不得从母榜名称／分数生成隐藏候选。

在现有同版 `selection-draft.json` 中保存 `paper_projection`，仍由上述 canonicalizer 写入同一个不可覆写的 `selection-evidence.json`，由现有 selection/projection 哈希、发布提交和报告版本绑定；不创建额外信任文件。`paper_projection` 使用原投影结构：`date`、`board_date`、`board_version`、`cutoff`、`revision`（例如 v02）、原头尾两席 `long/short` 组和 `collection`。collection 的 targets、target_evidence、parent_board 与公开投影完全相同；evidence 用该私有投影自己的组索引保存原组强度、完整直属覆盖、每卡身份、日期、趋势、信号及已有字段证明。私有 group/card 保留原 seat、coverage、direct_verified/platform_match_verified/watch_eligible 等已核实字段，旧原始来源、instruments、field_records/field_sources 均仍保留在相同 selection 中。新增第三席和仅标签行不能加入原模拟范围。

在 prepare-report-evidence 及读回核实前完成两份投影，不在已核实版本上补写隐藏材料。正常 daily producer 只在同版哈希身份、日期、截至时间和母榜匹配时，从私有投影补回公开阅读投影缺少的原席；按新内部位置重定位已有证明后继续原 coverage、身份、严格前后温与原始信号、市场、费用／委托保护。candidates 使用同一私有读取逻辑，公开 HTML 不读取 paper_projection。没有匹配私有证据、原席归属／覆盖或原始字段待核时只记缺口，不推断成员，不为这些缺证行读取券商；已核实其他原席继续独立处理。旧报告及无隐藏原席的输入沿用现有流程。

有模拟候选时，投影须保存原日报日适用的 `collection.targets` 与 `target_evidence`，包含 `BOARD`。在 `collection.evidence` 留存同版榜图日期、版次、席位强度、完整直属覆盖及标的自身信号的核实记录。每条 `instruments` 行保存 `id`、`code`、`market`、`group`、`relationship: "直属"`、`data_day`、`expected_day`、`previous`、`current`、`labels`、`state` 和 `selected_new_position`。已核实候选用 `state: "已触发"` 与 `selected_new_position: true`，已核实无触发用 `state: "核实后未触发"` 与 `false`。`field_refs` 按供应商字段名引用原件，至少覆盖 `trendTemperaturePrev`、`trendTemperatureCurr`、`tickerLabels`。

每条 `field_records` 引用保留证据根下的 `source` 路径、`sha256`、JSON `location`、`identity`（`tmId`／`asset`／`tickerSymbol`／`asOfDate`）、`fields` 和适用 `version`。已有 `field_sources` 草稿可提供相同原件的 `path`、`sha256`、`location`、`record` 和 `version`，由程序转换引用。原报告日证据目录是普通相对路径的起点。字段版次须与投影的趋势和事件证明一致。草稿、原始响应和交易证据留在私有目录。

没有可核实的交易事实时保留缺项，日报照常用已核实的展示材料发布。交付读回后，原定时 tab 的盘前入口按实际证据说明 `verified_no_candidates` 或 `evidence_incomplete`，并报告 `skipped` 中的具体原因。榜图、覆盖、适用日期、身份或逐字段证据待核时保留待核结论，缺项不触发行情采购或券商读取。

### 读取、修订与同步

- 持报告日锁核对同日更正记录及最新有效的本地证据。只有能证实文件使用当前有效版本的模板与渲染器生成、属于请求报告日、符合白名单，且与同日当前证据重新渲染的结果字节一致时，才直接复用原字节。单凭文件名、格式或历史状态不得复用。旧版日报保留在私有历史。没有可复用的文件时，在授权范围内按请求报告日和截至时间用可用证据渲染完整的 V1 HTML，方向面板按现有证据列席位、标的或具体缺项。普通读取和仅改格式均零新增行情查询。文件身份、写入授权或目标有疑问时按锁和文件规则说明具体问题，不覆盖身份不明的文件。读取不触发重写其他历史日报。
- 复验旧稿时按当前投影规则重新核对完整观察仓名单及跨类归属，从仍有效的私有证据写 `direct_verified`、`platform_match_verified`、`watch_eligible`、身份键、`signal_events` 与所有可查标的的 `strength`、`local_strength` 及各自缺项说明。旧 direct/related 必须从原始成员与平台精确匹配证据重建三块，而非按旧数组搬移；仅旧投影或旧 HTML 无法证明新增标记；不能恢复被旧两只上限或跨组首席规则删去的成员，须回到原始成员证据，缺证范围保留待核。旧信号覆盖说明只留在理由或私有证据；两项强度分别只从匹配的 `trendStrengthGlobalCurr` 与 `trendStrengthLocalCurr` 重建。现行 HTML 的旧格式或历史展示文本不能代替字段证据。
- 写入时持有报告日锁，核对原报告日、可用证据和修订授权，按原有私有目录权限（`0700`，`umask 077`，文件 `0600`）留存不可混淆的旧稿与版本，再用同目录临时文件原子更新同日阅读路径。以经过核验的私有证据合并变化。即使只更正一项，也用当前有效模板和渲染器生成整份报告，带入其余仍有效的榜图字段、展开行、卡片、查询状态、缺项及顺序。不从旧 HTML 提取事实。现行文件版本身份可核实且与候选字节相同，保留原字节，不创建新阅读版本。落盘失败直接在会话回报。
- 每个向 Ray 正式交付日报的会话或标签都使用所选仓库版本的本技能。按既有同步授权，在现有 iCloud `trend_v3` 文件夹读回并逐字节核对现行 `YYYY-MM-DD.html` 与本地版本一致。若缺副本且已有授权涵盖补齐操作，按原生同步流程补齐该份已核实 HTML，再读回核对。只在当前会话给出这个文件的链接。单项更正也用整份 HTML。无法核实目标或有效副本时，在会话说明实际的同步或文件问题。保持现有同步配置和权限，私有证据只留本地。固定证据离线验收样例仍沿用指定的离线输出目录。

### 同日证据更正

- 暂未取得更新、仍待核或费用状态变化时，保留此前仍适用于报告日及截至时间、未被推翻的榜图事实、展开行、卡片和查询状态。已有授权且核实的同日更正若明确推翻已刊席位、展开事实、原卡的信号、资格、强度或其他已刊事实（含无匹配结果及关联组别），先在私有证据持久记录受影响的席位或标的、旧刊版本、证据版本和原因。该旧条目立即不得再作为当前内容返回、重生成或同步，即使本地文件尚未处理或其他标的仍待核。按最新有效证据重新核对席位、展开行、观察、新仓和查询状态。仍可保留的卡片按现有有效证据重写 `signal_events`，需要时用空数组。只撤回同品种强度且仍满足观察条件时，在私有证据记 `UNKNOWN`，该卡以 `local_strength: null` 及可公开缺项原因投影；只撤回全局强度时独立用 `strength: null`，不能影响另一项仍有效的值。复验与重试不得用旧证据恢复已撤回的事实。
- 持报告日锁先核对原阅读路径、报告日、已保存的文件身份及版本，只有可确认由本技能生成且与私有记录匹配时才处理旧文件。已有授权范围内先在私有证据存档原件，再按最新有效证据生成整份现行 HTML 并原子替换。保留 V1 版式及其余仍有效的内容，无可列席位或标的时在相应方向面板或列表说明缺项。若确有文件或授权问题无法安全替换，只按已有撤回授权处理核实过的旧稿，并说明实际问题。用户编辑过、身份不符或未获授权的文件不自动移动、覆盖或删除，即使原件留在当前路径，也不作为当前报告返回或同步。
- 若已核实原同步副本仍含失效条目，仅在核对原共享目标和版本且已有授权覆盖该更正或撤回操作时，限于该副本更正或撤回。没有适用授权时停止重新交付，在会话说明云端仍有旧副本并请 Ray 明确批准；目标或版本无法核实时停手并说明缺口。区分本地和云端处理结果，未核实云端生效时保留待核。重试前读回私有处理记录和当前版本，已完成的同版更正不重复，结果不明时不盲重发。不处理其他文件、伴随文件或历史日报。本地和同步更正均不补发付费查询。

### 状态更新

- 市场状态、缺项和费用状态记入私有日状态。当前有效模板、渲染器及可刊证据均未变，且已有合规的现行 HTML 时，状态更新保留原字节，不另存阅读版本、不访问供应商或增加费用。发现已核实更正时执行「同日证据更正」。中断恢复时从已保存私有证据继续，遵守共享账本的禁止重发规则。
- 历史状态（如 `NOT_READY`）和历史复查时点只留作记录。恢复以实际取数、对账和文件证据为准，当日有权成稿时使用现有适用证据。历史状态不得阻止成稿、触发新一轮取数或代替对现行文件身份和事实的核对。
