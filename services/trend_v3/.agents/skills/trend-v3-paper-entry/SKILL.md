# Trend V3 模拟盘首次开仓

当天正式日报的原定时交互 tab 在日报交付核验后使用此入口。用与日报相同的不可变发布版本和原 Codex 会话 UUID。程序自行读取本机启动回执、原启动消息与 native 终端身份。只在该 tab 回报。手工读取和历史报告不走正式入口。

本期模拟盘以原定时 tab 中实际收到的明确用户回复为授权。会话记录证明回复来自该 tab；本期采用 tab 级信任。交付计划后等用户本人回复。禁止代发授权、用引述代替授权或从其他 tab 接收授权。

加密模拟盘走下文「加密模拟盘手工开仓」，由 Ray 在 Futu App 操作并回原 tab 说明结果。以下自动计划、编号、批准、开盘提交与回执命令继续用于其他受支持市场，不用于加密手工项目。

做空首次观察信号为前温度「凉」、当前「寒」或「冻」，并带当期精确「凉转寒」标签；两种初始仓位均为 2%。新版开仓资格由已认证的正式日报裁定。规划和报单前均核验实际借券、合约、模拟账户及资金条件。

## 盘前计划

1. 照日报流程验证当前 HTML 和主机上传回执。程序从原路径读当天最新报告及关联的 reader、selection、费用与报告核实文件，核对日期、版本、发布身份与摘要。给定原会话 UUID 即可，无需创建证据包或填写仓位、价格或订单内容。
2. 新版读取日报冻结的全部「可开仓」，核对同版精确身份、适用日、截至时间及原件。旧版沿用原榜图、席位、直属及逐字段证据核验。没有可进入自动检查的候选时不连接 OpenD。`verified_no_candidates` 表示冻结的母榜、适用范围及入选大类的成员覆盖均已核实，且无候选，`evidence_incomplete` 表示证据待核，`no_actionable_candidates` 表示本次无可操作项目；按 `skipped` 说明具体原因。只有 `lines` 有内容时才展示批准命令。有合格候选时读取交易日、产品、合约、参考价、整手和模拟账户的风险数据。每笔首次开仓按该账户的当前净资产 2% 计算，并受本币可用资金和账户敞口上限约束，向下取整手或整张。不设标的数量上限。持仓、挂单及待核委托用于同标的去重和风险核对，各账户的资金及敞口均按本币预留。
3. 在原 tab 的可见最终回复中用代码块逐字展示 `plan` 输出的 `delivery`，包括末行的报单时机说明。同版计划保留编号和数量。使用 `确认全部`、`只确认第1项` 或 `确认第1、3项` 明确范围。只有唯一计划只有一项、上一条可见回复单独展示交付卡、期间没有其他对话时，直接回复 `同意` 才算批准。混合话题或先看过状态时，请明确回复项目编号。也可回复 `模拟批准 <计划编号> <项目编号1>,<项目编号2>`。按 `skipped` 或手工清单回报产品、路由、资金、持仓及委托方面的缺项。旧卡需重新逐字展示含报单时机的交付卡，才能取得开盘后提交的批准。日报修订后生成和展示新计划并取得新批准。
4. 收到原 tab 的明确回复后，以受监督命令运行带原日报日的 `cycle "$plan"`。盘前批准等各项目开盘。开盘后仍在该项已核实市场交易日的最新批准触发即时复核和提交，跨台北午夜仍用原日报日。同一句回复按项目分流。在已有等待句柄期间，可以用 `approve` 处理对其他项目的明确回复或撤回。保留受监督句柄并在原 tab 读回；无有效回复时继续等待用户。用户可回复 `withdraw_all` 所示命令或 `模拟撤回 <计划编号> <项目编号1>,<项目编号2>` 撤回仍可撤回的未报项目。读回 `items` 与 `ignored_opened_items` 并报告哪些决定生效。
5. 报单前核对同版报告、上传回执、标的与合约、累计占用、该账户净资产 2% 及可用资金、市场状态、价格、整手和券商容量。按原批准数量提交，预计可用数量减少或规格变化时回报原因，请用户决定如何调整。盘前批准仍须在开盘后 2 秒内唤醒、30 秒内发起；错过后须在同一市场交易日取得新的明确回复。开盘后批准时以该回复起算 30 秒，重启或过期后不重播。支持的盘后请求仍用 DAY/RTH，按实际回执报告受理、拒绝、挂单或成交。交易日结束后旧回复失效，已报委托只按原委托对账或走独立重试批准。

## 加密模拟盘手工开仓

- 以同一正式日报 `plan` 输出的 `manual` 项为候选；同一 `task_id` 只跟进一项。旧版沿用同日正式报告已核实的精确标的、行情日和现货信号。核实资金、敞口、限价和数量规格后才给出手工操作指引。核对用户已报告的持仓、活动或状态不明的手工委托；已有任务则跟进原任务，重读、刷新或重新计划均不重复布置开仓。
- 交给 Ray 下单前，复用已核实的报告、状态与 Ray 当前持仓和委托的文字回报。不设标的数量、名额或跨日加密名额限制，也不维护隐含标的计数。合并已知跨会话的持仓、活动或状态不明的委托、未结手工项目及本次拟开的项目，核对精确标的身份、重复任务和各账户本币的资金及名义敞口；身份、资金或敞口不明不能当作零。对同一账户的多个同时手工项目，逐项预留预算现金和名义敞口，计入原有未结项目后再计算下一项，不能让多项重复使用同一笔资金。自动与手工项目如使用同一账户，也须合并该账户的资金及敞口预留；不同账户分别计算，不跨账户挪用预算。资金不足或不能证明符合下单条件时，只列「候选，暂不下单」及具体缺项，不给下单指示；需要时只澄清缺失文字信息，不要求新 API、截图或回执。单说「完成了」或重复完成回复不释放待核委托的资金及敞口预留，也不创建新单。
- 在原 tab 的最终回复中，用「加密手工」在自动 `delivery` 代码块之外列出这些项目。自动正文逐字保留，原编号不变，手工项目不进入自动批准编号。即使自动 `lines` 为空、自动计划无可批准项，仍展示已核实的加密手工项目；只有自动项目时沿用原流程。无已核实加密信号时不创建手工任务。
- 每项写明已核实的交易对、买入限价、数量、计价币种及预算；仅对资金、敞口及下单条件均已核实的项目，指导 Ray 在 Futu App 的加密模拟账户以现金现货限价买入。预算按该账户当前本币净资产的 2% 计算，再受已核实可用现金及剩余名义敞口约束，扣除同一账户其他未结及本次拟开项目的预留；按 App 已知的数量精度向下取整，不超预算。限价必须有可核实依据，数量只能从已知限价、预算及交易规格计算。净资产、现金、敞口、价格或规格不可用时分别列明缺项，相关预算或数量标待补，不编造数字，也不把缺项项目表述为可直接下单。所需数值可由 Ray 在 App 查看并自然补充；不要求凭据、账户秘密、截图或回执。
- 对可下单手工项目，请 Ray 自行下单后在这份日报的原 tab 自然回复，例如「已下单」或「完成了」，无需口令或自动批准命令。只在项目或含义确实不明时追问必要信息。单说「完成了」只表示人工步骤完成，成交状态仍待用户说明；「已下单」表示用户报告已提交。只有用户明确报告成交、部分成交、撤销或失败时才分别记录对应状态，均注明为用户回报，不能将已提交或人工完成写成已成交。
- 此手工流程不连接 OpenD，不调用行情、账户或订单 API，不自动提交、重试或补单。失败、撤销或含糊回复只跟进原任务并说明已知状态，不自行发起第二次手工任务。其他市场的自动流程保持原有批准、执行与核对规则。

## 命令

使用同一发布目录的 `services/trend_v3/src` 和已配 Futu SDK 的 Mini Python。在原 tab 按现有工具读回真实 Codex UUID，传给 `--session`。入口根据现在的台北日期定位报告。错误或证据缺口留在原 tab，私有文件、账户和券商订单编号不随结果发送。

在原 tab 的受监督命令工具中直接运行下列 CLI，不另用 Python `subprocess` 包装器启动它。直接父进程关系由内核核对；更深的祖先进程关系仍须通过进程遍历证明。若遍历不可用或原会话、启动消息不匹配，入口会在读取券商前拒绝；保留错误交由 Main 核查，不更改权限或改到其他 tab 执行。

```sh
PYTHONPATH="$service_dir/src" "$trend_python" -m trend_v3.paper_cli --session "$session_id" --report-date "$report_day" plan
PYTHONPATH="$service_dir/src" "$trend_python" -m trend_v3.paper_cli --session "$session_id" --report-date "$report_day" approve "$plan"
PYTHONPATH="$service_dir/src" "$trend_python" -m trend_v3.paper_cli --session "$session_id" --report-date "$report_day" cycle "$plan"
PYTHONPATH="$service_dir/src" "$trend_python" -m trend_v3.paper_cli --session "$session_id" --report-date "$report_day" status
PYTHONPATH="$service_dir/src" "$trend_python" -m trend_v3.paper_cli --session "$session_id" --report-date "$report_day" reconcile "$plan"
```

`plan`、批准、执行与对账后自动刷新同一完整日报 HTML 的模拟盘部分。`cycle` 在每组开盘后读匹配回执并刷新，之后每 30 秒只对账已有委托，直至没有活动或待核委托或原交易时段结束；绝不因刷新重试。内部结果继续保留方向、申请/批准数量、实成、剩余、部分成交及原委托身份，供审批和核查；正常阅读件按 holdings.md 的四列真实持仓契约展示，不输出这些委托字段。

`status` 和 `rehearse` 保持只读，不刷新、不启动等待器或券商读取。原报告、投影、selection、费用及 verification 原件保持不可变，原 HTML 保存在同版 `reader-original.html`；`paper-display.json` 单独记录来源摘要和展示摘要。正式主机同步器由同一不可变发布的 `host/` 候选更新后，从原证据及私有状态重新计算展示，沿用原共享身份、文件保护与上传读回，不信任展示文件自称的摘要。`host/prepare.py` 只准备安装候选，校验发布目录名、Git HEAD 和干净状态；安装、更改主机 pin/SOP、重新加载服务仍需单独批准。部署前同步器和启动器必须同 pin；旧 SOP pin 不匹配时启动器拒绝。没有有效原交付回执不得执行。普通刷新不读取券商、重新计划或生成授权。

`reconcile` 只读取已保存委托的匹配回执。逐项回报成交、失败、活动、部分成交及待核。确认原委托已拒绝或已撤销且有剩余数量时，将返回的 `retry_reply` 逐字发给用户。仅在交易时段内收到新的同 tab 明确重试回复后，立即运行 `submit "$plan" --retry-item "$item"`。重复命令、活动委托、未知回执和已全成委托均不会补单。美国交易时段跨过台北午夜后，在 `--session` 后加 `--report-date YYYY-MM-DD`，填写原日报日期。

固定历史演练核对同一原始发布的报告版次、截至时间、日期及原件摘要。新版使用封存裁定，旧版核对原来的选择日期和逐字段引用。此入口不会访问 OpenD 或启动真实会话。仿真的账户和实际提交流程通过服务的离线集成测试验证。

```sh
PYTHONPATH="$service_dir/src" "$trend_python" -m trend_v3.paper_cli rehearse "$daily_root" "$date" "$revision" --release "$report_sha"
```

## 证据与缺项

- 盘前入口使用 `~/.config/trend-animals/daily-state/YYYY-MM-DD.launch.json` 与同日上传回执、Codex 原会话消息、最新日报目录内的原始文件。核对当前 native 前台和进程归属。出错时保留当前证据，待原 tab 或上传回执恢复。计划数据库在原日报工作区内的 `reports/_evidence/.paper-entry/state.sqlite3`。
- 精确确认标的类型、市场、代码和日期。日历没有交易日则标明休市。保留当前报告的 `field_records` 原始路径、版本、摘要和记录位置。缺少对应原件或证据更正后不发券商读取。路由或份额规格缺失时保持待核；不能从简称、相似代码或截图推断。
- 普通股的参考价与整手从精确 OpenD 代码取得。ETF 另须有引用原件中的 1 倍证明。期间无法核实的 A 股 ETF 保持待核；加密不走自动模拟市价线路，按上文手工现货限价流程处理。期货需有标的对应的可交易合约映射，再以 OpenD 合约规格核对有效期限、交易时间和乘数。两种互相冲突的时段不择一猜测。
- OpenD 默认本机回环。已有私有模拟配置时沿用。无既有配置时只发现能唯一确认的活跃 SIMULATE 市场账户。账户识别、风险及委托只允许在明确的模拟路线内，行情和账户清单端点本身没有交易环境参数。重复账号、缺账户和借券能力不足均有独立待核状态。

- 证券使用 OpenD 快照确认正常且未停牌。单市场模拟证券账户若省略资金币种，由已核实的账户市场确定，预算受扣除冻结额的现金与购买力两者限制。A 股接口使用券商的 `CNH` 参数，A 股账本仍按原计划人民币口径列示。账户资金或敞口的币种与该账户已核实本币冲突时，暂停该账户的新单。
- 已核实的港股恒指期货使用香港日间开盘，按所选交易日上午或下午时段处理。券商展示的每手 50 与合约乘数指向同一个单位换算，计划数量以整数张列出，每张名义金额仅乘一次。其他形态缺少可信时段、到期日、币种或交易单位时继续待核。

### 在仓头寸展示

正常日报模拟盘使用版本化持仓对象，按市场分区，每表仅「标的、持仓数量、开仓均价、持仓盈亏」四列；不展示委托串、申请/批准数量、跳过原因或汇总栏。只显示已归属 V3 的实际在仓头寸，跨日持续跟踪，实证归零才移除。未知估值显示 —，不填假零。手工加密只接受原 tab 明确回报，渲染与 status 保持只读。字段、权重/估值保护、手工来源及完整离线演示见 [holdings.md](holdings.md)。
